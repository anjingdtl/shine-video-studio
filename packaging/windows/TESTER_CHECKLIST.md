# 实机联调勾选清单

构建：`{{PACKAGE_VERSION}}` / `{{BUILD_ID}}` / 提交 `{{SOURCE_SHORT}}`

每完成一项打勾；失败项在后面写错误码和截图文件名。不要用「大概成功了」代替证据。

## A. 安装前

- [ ] 系统是 Windows 10/11 x64
- [ ] GPU 为 NVIDIA，显存 ≥ 15.3 GiB，驱动可用 `nvidia-smi` 看到显卡
- [ ] 系统内存 ≥ 30 GiB
- [ ] 除 C 盘外至少一个盘空闲 ≥ 180 GiB
- [ ] 能打开 github.com、huggingface.co、pypi.org
- [ ] 安全软件未拦截 PowerShell（必要时临时退出）
- [ ] 压缩包已完整解压，路径不含特殊符号，例如 `D:\ShineVideoStudio`
- [ ] 运行过 `CHECK_ENVIRONMENT.cmd`，磁盘与工具链输出已保存

## B. 一键安装

- [ ] 双击 `一键安装或启动` 入口（`一键安装并启动.cmd`，乱码时用 `SETUP.cmd`）
- [ ] 安装器自动选中了非系统盘，并打印了安装目录
- [ ] 工具链按固定版本下载并通过 SHA-256 校验（uv / node / npm / pwsh / ffmpeg / ffprobe）
- [ ] `uv sync --locked` 成功
- [ ] `npm ci` 成功
- [ ] API、Worker、Web 三个进程启动成功，窗口里打印了端口
- [ ] 浏览器自动打开了 `http://127.0.0.1:<端口>/#d/setup`（空库）或 `http://127.0.0.1:<端口>/`（已有作品）
- [ ] 安装流程没有要求输入或抄录操作员密码
- [ ] 安装目录下生成了 `install-log-*.txt`
- [ ] 再次双击同一个入口，只打开向导、不重新安装依赖
- [ ] 服务运行时再双击一次，仍只打开向导（不会起第二套服务）

失败时记录：退出码、窗口文字、`install-log-*.txt`。

## C. 向导：环境与计划

- [ ] 「检查上游可达性」四项全部 `OK`（HF / GitHub 归档 / PyPI / PyTorch）
- [ ] 「环境检查」全绿，或明确列出可解释的 blocker
- [ ] 「部署清单」显示 14 个组件 / 154 个固定包 / 约 60.8 GB
- [ ] 目标盘与运行目录确认在非系统盘
- [ ] 生成安装计划成功
- [ ] 在网页中能看清本次操作对象与影响，并完成明确确认
- [ ] 重复批准同一计划被拒绝（一次性授权）

## D. 向导：下载与安装

- [ ] 14 个组件全部下载完成，总字节数与清单一致
- [ ] 每个包的 SHA-256 校验通过
- [ ] 安装后磁盘实际占用与预算（约 174 GB）相符
- [ ] 中断后重新进入向导，能识别已完成组件并续装，不重复下载

失败时记录：组件名、包名、错误码、已完成百分比。

## E. 向导：实例与工作流

- [ ] 实例步骤执行成功（受管 ComfyUI 目录就位）
- [ ] 登记工作流成功，两个 Ref2VA 配置文件哈希与清单一致
- [ ] 生成受管配置成功，`installation` 摘要写入
- [ ] 确认运行配置成功（API 与 Worker 使用同一安装身份）

## F. 向导：服务与工作流验证（新增）

- [ ] 点击「验证服务与工作流」后，受管 ComfyUI 被短暂启动
- [ ] 读取到真实 `/object_info`，节点数 > 0
- [ ] 工作流输入契约校验通过（缺节点时应返回 409 而不是“通过”）
- [ ] 视觉审片服务读取到 `/v1/models`，模型为实际安装的 8B 级别
- [ ] 语音审片服务读取到 `/v1/models`，模型为实际安装的 0.6B 级别
- [ ] 审片路由 `vlm_reviewer` / `asr_reviewer` 已绑定到上述两个 provider
- [ ] 验证结束后所有临时服务已停止，不再占用显存
- [ ] 就绪检查里 L4「真实服务与节点契约」变为 `READY`

失败时记录：返回的 JSON、blockers 列表、端口占用情况。

## F2. Web 新用户与并发复验（本版新增）

- [ ] 设置、生产、交付、系统四区导航可用；新项目能进入素材与风格页面
- [ ] 填写七项风格并批准冻结，冻结版本与本次确认内容一致
- [ ] 两页面修改同一草稿时，过期批准返回冲突，输入与旧冻结版本保留
- [ ] 同名全局工作流并发登记时只有一个成功，其余明确报告冲突
- [ ] 升级旧库遇到 `GLOBAL_WORKFLOW_NAME_CONFLICT` 时保留原库并记录冲突，没有清空或删除历史

本段仅验证 Web 与数据库合同，不能代替下面的真实生产与人工验收。

## G. 真实生产（受管实例）

- [ ] 用 `START_APP.cmd` 或 `start_shine.ps1 -Provider comfyui` 以真实渲染器启动
- [ ] 单镜头真实生成成功，产物通过 `technical` 门
- [ ] 多镜头系列（Production Series）能独占 GPU 租约并按依赖顺序执行
- [ ] `semantic` / `audio` / `style` / `final` 四道门都有真实结论
- [ ] 任务行 `acceptance_status` 与 `final` 门一致（不是只看 `PASSED`）
- [ ] Mock 任务显示为 `mock`，没有被当成真实视频

## H. 成片验收（尚未在干净机器上跑过）

- [ ] 约 60 秒、至少两人对白、多场景的 M4 成片产出
- [ ] 768×1344 / 24fps 规格一致，全片可解码
- [ ] 成片 SHA-256 与验收报告记录一致
- [ ] 报告里的磁盘、包数、审片模型身份与实际一致

- [ ] `STOP_APP.cmd` 能停掉全部进程，端口全部释放
