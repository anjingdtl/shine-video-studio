# V1.1 Film crew and rulebook contracts

The product baseline is [PR #2](https://github.com/anjingdtl/shine-video-studio/pull/2),
commit `8bdefe8d0e394b48a3c8611ca42650e70a944040`.
The original Job/Attempt/Artifact/QualityGate tables remain the only production ledger.

## Work units and authority

`FilmAgentRegistry` enumerates seven reviewed roles. Each uses the existing `agent_routes`
and `LLMGateway`; the same provider profile can serve every role. There is no new queue,
shell tool, filesystem tool, HTTP tool or general DB tool available to a model.

| Role | Typed output | Required handoff |
| --- | --- | --- |
| scriptwriter | ScriptBreakdown, SceneBeat and existing DialogueLine | User script + locked facts |
| director | DirectorialPlan, ShotIntent | One ScriptBreakdown |
| cinematographer | CameraPlan | One DirectorialPlan |
| continuity_supervisor | ContinuityReport | DirectorialPlan + CameraPlan |
| sound_director | SoundPlan | ScriptBreakdown |
| producer | ProductionPlan | Context, advisory only |
| editor | EditDecisionList | Current eligible Job/Attempt/MediaArtifact tuples |

The four core roles also support `style_proposal`, returning `StyleProposal` before freezing.
Remote text profiles additionally require explicit per-call `allow_remote_text=true` consent
for the script/style/asset metadata. Existing VLM/ASR review consent is not reused as text
transmission authorization. No media bytes or absolute private paths enter this context.
The Web consent control resets after each operation and when switching roles.
It does not change a StyleVersion. The user's explicit style-draft action updates only the
draft, and the existing human freeze endpoint remains authoritative.

Each call commits an `AgentTaskRecord` before requesting a model. Records include input,
style, asset-manifest and rule-pack hashes, explicit profile/model routing, schema version,
status, safe error code, latency, token usage and source-cache status. Successful strict
Pydantic validation creates an append-only `AgentArtifact` with SHA-256, role, source task
and parent revision IDs. No endpoint overwrites payload JSON. Supersession preserves the
old payload and invalidates descendants and jobs materialized from affected camera plans.
An interrupted RUNNING call is visible for operator review and is not auto-replayed.

The director cannot add an unknown beat or unapproved asset. Named characters require a
bound approved image master with matching `entity_id`/`role=character`. Camera output has
no story/dialogue fields. Applying a camera plan takes dialogue and locked facts from the
script artifact, checks its corresponding continuity report, and compiles/preflights every
shot inside one transaction. Repeat application returns the existing shot IDs.

The editor selects exact current attempt/artifact IDs, bounded in/out points and CUT
transitions. Every named gate must exist. Final EDLs reject stale, mock, unverified or failed
sources, and media bytes are re-hashed. Explicit `offline_preview=true` permits only a
preview under the existing mock/unverified policy; it never changes a QC decision or
authorizes final delivery. M4 media composition, J/L cuts and delivery export are deferred.

## Rule packs and sources

`H3RulebookRegistry` contains Shine-authored machine rules with official file/section
locators. The pinned upstream is `MiniMax-AI/MiniMax-H3` at
`d21241f0a4b3acbb34c97dae47fa417b7065e438`. Official full text is not bundled or served.
Four source files (the three prompt guides and README) carry canonical URL, commit, Git blob SHA and content SHA-256. The user
may import legally acquired bytes into the data directory; both digests are verified,
fetch/import time and local-only rights are recorded, and each recheck detects corruption.
Missing originals remain `SOURCE_UNAVAILABLE`. Independently shipped original machine
rules remain explicitly available; they are not described as a cached copy of the guide.

New metadata versions produce a diff and require human approval. A project freezes an
immutable rule-pack ID/hash. Source commits or executable rules not supported by the current
compiler are rejected, even if someone tries to approve them. Upstream rule changes require
code changes, tests and review; this is intentionally not a remote arbitrary-rule executor.
Existing projects without a V1.1 rule lock keep their old compiler pin and are labelled
`LEGACY_COMPILER_PIN_ONLY`; they are never silently migrated to a stricter language policy.

RuleViolation contains rule ID, one of `OFFICIAL_H3`/`SHINE_POLICY`/`LOCAL_WORKFLOW`, severity,
source path/locator, affected field, evidence, remediation and rule-pack ID. Deterministic
checks recompute the sole H3 compiler output, inspect section order, label resolution,
keyframe modes, timing, original dialogue, style/pack hashes and CJK outside permitted
dialogue/visible-text blocks. English fluency, factual contradictions and visual quality
still require review; this syntactic detector is not a complete linguistic verifier.

Rule checks run when creating V1.1 render requests and again before the existing worker
claims/submits them, including repaired requests. A failure becomes NEEDS_REVIEW without an
external call. Actual workflow mappings/media transfers remain guarded by the existing
ComfyUI adapter; registered profiles are always shown as PENDING_LOCAL_H3 in this module.

## API and migration

- `GET /api/v1/film-agents`: roles, contracts, permissions, profile/model routes.
- `POST /api/v1/projects/{id}/film-agents/{role}/run`: validated proposal, explicit parents.
- `GET /api/v1/projects/{id}/film-runs` and `/film-artifacts`: persisted traces and JSON artifacts.
- `POST /api/v1/projects/{id}/film-artifacts/{id}/apply-camera` and `/style-draft`: user actions.
- `GET /api/v1/h3-rulebook?q=...`: packs, rules, source/cache and workflow metadata.
- `POST /api/v1/h3-rulebook/recheck`, `/cache?source_path=...`: local cache checks/import.
- `POST /api/v1/h3-rulebook/candidates`, `/packs/{id}/approve`: diff and human approval.
- `GET /api/v1/projects/{id}/rulepack`, `POST .../rulepack/freeze`: immutable project pin.
- `POST /api/v1/h3-rulebook/validate`: structured RuleValidationReport.
- Existing `/shots/{id}/compile`, job creation, worker, QC and repair remain authoritative.

Alembic `e8f1a2b3c4d5` adds `rule_packs`, `project_rule_locks`, `agent_task_records` and
`agent_artifacts` with project/source foreign keys. Existing tables/rows are not rebuilt.
RenderRequest adds optional rule-pack provenance and project_language with legacy defaults.
Run from repository root: `uv run --project backend alembic -c backend/alembic.ini upgrade head`.
