## 2. 本轮修复的具体问题

本轮从"上一轮已存在的代码"出发，先核对本地与远端 HEAD：本地 `main` 与
`origin/main` 同为 `851e300`，工作区干净，没有比它更新的提交；本地另有一个
`codex/local-final-closeout` 分支，但它相对 `main` **删除**了约 11k 行受管交接
代码，属于更早的支线，因此以 `main` 为基线。

真实运行暴露出并修复了以下问题（每一条都由真实 H3 渲染触发，不是推测）：

| # | 问题 | 根因 | 修复 |
|---|------|------|------|
| 1 | 常驻 Worker 从不进入多镜头生产 | `serve()` → `run_configured_once()` → `run_one()` 只取一个作业；`run_managed_series()` 只在测试里被调用，第一个镜头用完独占 GPU 租约后，后续镜头永远拿不到准入 | 新增**生产序列**（production series）：有序、独占、可续接的生产单元；常驻 Worker 认领序列，首镜受管启动、后续镜头租约转移、序列结束统一释放 |
| 2 | 渲染成功但租约永不释放 | 受管交接后 `IdleHandoffKeeper` 一直续租；渲染器与独占租约在镜头之间不释放也不转移 | 序列结束统一释放：先停渲染器并证明进程组为空、再实测内存基线、最后释放租约；租约释放与序列状态在**同一事务**提交 |
| 3 | 释放失败窗口 | 续租停止与租约释放分两步，进程先退出而数据库操作失败会留下不一致状态 | 释放前先落"释放意图"，租约释放与序列状态同事务提交；已提交的释放是幂等的，不是第二次释放 |
| 4 | Worker 异常退出后序列被永久锁死 | 序列没有所有者证明与心跳 | 序列有独立心跳与租约；停止续期的序列变回**可认领**，从第一个未完成镜头续跑 |
| 5 | 界面无法表达软连续性 | 分镜表单把 `continuity` 写死为 `cut` | 分镜面板新增"与上一镜的关系"（CUT / last_frame / hard_frame_anchor）与来源镜头选择 |
| 6 | 渲染器准入因内存不足被拒（本机当时只剩 6GB 可用内存） | 配方把 8192MB 写死 | 准入阈值改为可测量参数，并把**实测余量**写入证据；渲染是否真的需要那么多内存由运行本身证明 |
| 7 | 工作流声明了音频通道、镜头却没绑定音频，渲染器 40 秒后以"文件路径无效"拒绝 | 只校验"请求→工作流"方向，没有校验"工作流→请求"方向 | 建立工作流媒体族校验：工作流声明了传输的媒体族，请求必须绑定；否则在**建作业时**就以明确原因拒绝 |
| 8 | 审片结论自相矛盾时，整个交接被判为"结果未知"并扣住 GPU | 已完成的审片回答违反契约，被当成不确定的外部阶段 | 契约违例记为**审片失败**（回执证明调用已完成，画面有效，镜头需要人工）；超时/服务端错误仍然升级为不确定 |
| 9 | 一个镜头需要复核时，整条序列停摆 | 序列在第一个失败镜头处停止 | 需要复核的镜头只阻断**依赖它的**镜头；独立镜头继续生产 |
| 10 | 失败原因不可诊断 | 交接失败只记 `HANDOFF_STAGE_FAILED` | 记录并输出异常自身的代码；Provider 文本、URL、负载仍不进入日志与台账 |
| 11 | 真实 ASR 转写没有进入质检证据 | 质检报告只存结论 | 质检报告新增 `transcript`（真实转写、是否 Mock、模型） |
