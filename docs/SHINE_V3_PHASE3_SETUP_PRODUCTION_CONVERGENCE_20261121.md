# P3 建设方案：基础整备与双流水线生产零新增阻滞收束

> 状态：待实施；前置：P1、P2 已做阶段性验证和差异记录。  
> 范围：修正原链路的事实归属与阻滞、复用已有入口；禁止为解决问题再新造设置中心、工作流中心、下载器或状态机。

## 1. 为什么 P3 是必要的

过去用户机器最常遇到的并非模型本身不可用，而是已经安装 ComfyUI、权重或工作流却被反复误判为缺失、要重新下载、重复登记、用户找不到“接入受管渲染器”等问题。新统一图不能再退回“所有工作流/可选节点/增强权重均就绪才放行”的设计。唯一基础配置就要服务七阶段、四阶段、素材中心和 H3 生成底座。

目标验收不是仅显示“就绪”，而是同一台机器从零散已安装事实到**真实可投产**，仅有可定位、可恢复、按当前需求生成的缺失项；非必要项不会阻断。

## 2. 现有唯一责任入口（优先复用）

| 事实/动作 | 当前主要代码 | P3 必须遵守 |
|---|---|---|
| 已安装 ComfyUI/模型/节点识别 | comfyops/existing_installation.py、resource_discovery.py、resource_inventory.py、inventory.py | 只读扫描现有路径，无另建目录镜像 |
| 已有文件核验/自动登记 | comfyops/setup_reconcile.py、variant_readiness.py、variant_binding.py | 哈希/节点证据足够则自动采纳；不让用户手动重复登记 |
| 用户唯一制作环境状态 | comfyops/setup_summary.py、runtime_configuration.py | 前端、七/四阶段挂同一只读事实 |
| 已有下载/修复操作 | comfyops/setup_preparation.py、installation_worker.py、environment_repair.py | 复用原用户授权机制/下载任务 |
| ComfyUI 启停与归属 | comfyops/renderer_supervisor.py、runtime_orchestrator/、ownership.py | 单实例/单归属/防重复启动 |
| 资源准入/实际执行 | comfyops/mode_capabilities.py、profile_gate.py、scheduler.py、foundation/h3.py、Worker | 仅在原裁决口增量识别 effective recipe，不加第二硬门 |

以上是目标调用归属，不表示任意历史模块都应继续拥有自己的一份判定权。逐个查出多裁决分支并删除冗余调用；不以“包装一层聚合 check”完成任务。

## 3. 一个最小可生产事实与按需增强事实

令最小基础就绪 B 表示：用户当前选择、已获验收支持的 H3 变体 + Ref2VA 核心节点 + 至少一张已批准的镜头图片参考 + 正确的 ComfyUI 实例归属 + 已核验的必要权重与上传/执行入口。B 不需要 RelayVSR、二采特供权重、音频/视频 loader、VLM/ASR、任何未被该镜选择的 LoRA。

每个镜头的额外需求 E(shot,strategy,bindings) 由 P1/P2 唯一图编译器的 required_nodes、required_weights、media_transfers 和参考文件派生。准入只对 B ∪ E 做既有裁决。关闭的选项在 E 中不存在，因而既不会检查，也不会下载，更不会转化为全局 BLOCKED。用户明确开启的选项如果未满足，返回当前镜头的具名缺失与修复入口，保留未获授权的组合，不悄悄切换 native/PDD/模型/缩放方案。

重点消除“尚未登记 profile 但动态编译已可执行”产生的假阻滞。新编译图应不再需要每个镜头登记成一个数据库 profile；静态历史 profile 仍可重放。

## 4. 一次性基础配置与资源复用

1. 在现有“设置 → 制作环境”上收束一个 ComfyUI 实例：可采用已有安装或管理安装；沿用同一套 custom_nodes、models、extra_model_paths，与 user ComfyUI 现有自定义节点共存。不得因缺可选分支强迫用户重装新实例。
2. 用户授权后优先深扫现有 ComfyUI 路径、模型子目录、额外模型路径和已下载缓存；根据当前选择的 variant manifest/官方权重 SHA 校验。识别匹配的文件直接写入原有收据/台账；不要求通过另一按钮“注册工作流”。
3. 缺失资源按用户当前启用的需要列表生成一个修复计划，通过既有 setup_preparation / installation_worker 分发；未选择的选配功能不得默认加入下载队列、启动硬门或多步骤整备任务。
4. 资源下载沿用既有自动线路选择、国内/国际下载偏好、可手动下载、断点续传和哈希校验。不要扩写另一套下载管理机制，已有正确文件无下载；版本不匹配应明确说明，不准覆盖用户文件。
5. “下载 → 校验 → 登记 → 可用于当前镜头”的变化自动反映到同一个 setup_summary 读视图；当正在下载/修复时保留既有运行任务，不因为重复点击生成并行修复。
6. 已安装外部 ComfyUI 与受管渲染器是不同运行归属事实，不等于要求用户另外安装一份 ComfyUI；UI 用通俗文案解释，并在原页面提供已有接管/恢复入口。

## 5. 单执行者与阻滞恢复

- ComfyUI 启动、监听进程、PID/birth/Job Object 校验与已归属实例必须读现有监督器证据；禁止 UI 与后台各自再启动一个进程。包括 uv trampoline、子进程监听、受管恢复的真实用例。
- 已运行的队列、Job/Attempt 的外部 prompt_id、提交 UNKNOWN、恢复断点都由原 Worker 对账。恢复不是“再提交一次”。重复检查一个未改变的 blocker 不计为真实进展，不得造成恢复活锁。
- 生产批次内某一镜的某一可选参考 loader 缺失，不应把其他没有该需求的镜头全部标为不可生产。保留作品/系列已有正确的冻结与最终交付顺序语义，不能为了不阻滞而错误标识全集成功。
- X2 阶段资源紧张时仍走既有 ResourceLease 的待调度队列。已启用的 X2 如确实不可用，对相应镜头报真实状态并展示当前唯一修复入口；未启用 X2 则完全不参与生产。
- 不要用 VLM/ASR 未安装阻断 H3；保持咨询检查 NOT_RUN/UNAVAILABLE 的诚实显示。

## 6. 核心反例验收矩阵

| 场景 | 合格行为 |
|---|---|
| 已装 ComfyUI/H3，但没装 RelayVSR | 基础1图 H3 立刻能开拍，设置显示 X2 未就绪但不全局阻断 |
| 已装 H3，但没装音/视频 loader | 无音/视频参考的镜头正常生产，相关能力仅在选择时提示 |
| 用户只勾二采 | 仅新增二采的资源验证，不连带要求 X2 |
| 已存在完整模型/节点 | 一次扫描即识别，自动核验并复用，不重新下载或人工登记 |
| 用户使用已有外部 ComfyUI | 沿用外部根路径与 model paths，授权接管不复制第二份资源 |
| 重复点击“下载/修复/连接” | 原任务继续或明确返回现状，不重启/重下载/重复 Worker |
| ComfyUI 被中断、监听落在子进程 | 由已有归属机制恢复；无法确认则明确 UNKNOWN，不假装启动成功 |
| 独立镜头参考不足 | 只定位该镜具体缺失，不影响已准备好的其余镜头 |
| 候选低显存变体缺真机证据 | 明确未验收，不把5080的证据冒充4070证据 |
| 七阶段/四阶段交替工作 | 同一 ComfyUI 根、同一资源收据、同一 H3 编译/执行能力，互不抢第二实例 |

## 7. UI 要求

仍使用原“制作环境”页面作为用户一站式入口。一个基础状态 + 可选能力的就绪/未就绪说明 + 当前明确缺失清单 + 已有“自动整备/重新核验/手动下载”动作。不要要求用户理解工作流 JSON、模型内部节点注册、两个不同“绑定渲染器”入口或过多技术术语。不添加新的工作流准备页。

UI 每个“可用/缺失/修复中”都来自 setup_summary 同一读视图；不要在前端硬编码“未注册”或“必须选择 profile”。对于用户没有选择的 RelayVSR/视频参考，可以显示“可选功能尚未配置”，但不能显示“制作环境未就绪”。

## 8. 分阶段实施清单

WP0 绘制“发现→核验→登记→准入→渲染→对账”实际调用图，逐项定位重复检查、重复状态、硬编码。  
WP1 整理动态配方所需依赖，替换旧的全模板总前置判定，保持历史只读。  
WP2 整合 setup_summary / setup_reconcile / setup_preparation 的能力闭包，复用已有账本/下载器。  
WP3 修复真实用户安装场景中的重复连接、根目录检测/登记/授权恢复，不新增执行层。  
WP4 UI 从唯一事实呈现，两个流水线实测一致。  
WP5 三层测试、8分片后端、前端完整构建、5080真机正反测试，复核4070/5090vd2未测项。

## 9. 阶段交付标准

输出重构前后的唯一事实/裁决/执行者映射、删除的重复代码位置、不同依赖组合下的 blocker 列表、现有资源自动核验与收据、真实启动/连接/渲染/恢复证据。基础可用率不得因新增高级功能下降；旧历史冻结请求可回放；没有第二整备中心；不影响 Qwen 素材中心和 manual4 产出。

如新增一次整备阻滞，P3 验收即失败：回到原有唯一责任入口修复，而不是再加检查或绕过现有权限。完成 P3 acceptance MD 和本地提交，停止等待 P4。
