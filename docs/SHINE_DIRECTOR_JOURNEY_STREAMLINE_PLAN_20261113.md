## 1. 建设目标

普通用户导入小说后，可以直接修改大纲，确定导演风格、影片类型、集数和每集秒数，按集得到可编辑镜头表，再按镜头准备素材、拍摄和出片。多集项目允许就绪的一集先出片，待修的一集继续处理。用户确认过的内容应直接成为下游依据。

沿用导演模式七步，主要改造①至④。⑤导演包、⑥视频生产、⑦后期成片沿用现有执行机制，调整接收的分集、镜头和素材版本范围。文学四阶段、五维故事记忆、专业分镜五个 Agent、导演风格模板、素材中心和现有 GPU 统一调度继续复用。专业模式保留已有有效入口，导演模式把分卷、蓝图、任务细节和专业微调收进后台或现有专业界面。

正式拍摄使用本机已登记并验证的 MiniMax-H3 工作流。影片风格由用户确认后冻结。AI 素材经用户授权制作，生成结果先作为候选，用户选定后才成为项目主素材。当前使用的 Ref2VA INT8 配置、权重和参考槽位以本机验证结果为准。

## 3. 七步流程与用户操作

| 步骤 | 主操作 | 可见产物 | 推进条件 |
| --- | --- | --- | --- |
| ① 创意与剧本 | 导入后修改大纲，点「确认大纲」 | 可编辑大纲正文及定稿版本 | 当前版本已有可用正文和有效来源 |
| ② 剧本统筹 | 选四项设置，点「生成分镜书」，看完点「确认分镜书」 | 分集、场次、节拍、对白和预计时长 | 分集覆盖明确，用户选定的风格与影片类型已冻结 |
| ③ 镜头拆解 | 点「生成分镜」，按集浏览和修改，点「确认本集镜头」 | 按集可编辑镜头表 | 当前集有完整可落镜的场次和有效镜头，不依赖其他未完成的场次 |
| ④ 拍摄素材准备 | 核对现有匹配和缺项，按需点「确认并送素材中心」 | 素材需求、使用镜头和素材候选 | 已确认可用的素材可以立即回绑。可选缺项可以跳过 |
| ⑤ 导演包 | 核对本次要拍的集，生成并确认导演包 | 本次拍摄的集、镜头、冻结风格及引用快照 | 拍摄范围内的剧本、镜头和真实运行条件有效 |
| ⑥ 视频生产 | 点「开拍」，查看本次生产进度 | 实际任务、镜头片段、局部失败与续跑入口 | 已确认的导演包通过现有正式生产预检 |
| ⑦ 后期成片 | 预览和导出 | 按集成片、字幕及现有交付信息 | 当前集有效镜头已完成，可完成真实装配与导出 |

阶段条显示当前范围的真实进度，例如「1/2 集分镜已确认」「第 1 集可备料」「第 2 集有 1 场待处理」。可从已就绪的集直接进入下一步。后台执行期间可以切换页面和刷新，返回后从已持久化状态恢复。主界面呈现待办动作，任务码、Token、模型参数和执行诊断放入详情。

## 4. ① 可编辑大纲与版本确认

1. 导入小说或现成剧本后，复用导入、分段和提取逻辑，直接把大纲呈现在一个可编辑正文区。正文可用简单 Markdown，用户可直接改主线、人物、场次顺序或保留悬念。模型疑问作为提示，与正文同时可见。删除导演模式下单独补事实、逐卷确认蓝图和「接受全部疑问」的必做操作。必要的远端文本授权沿用现有入口，并以当前文档与模型授权范围为准。
2. 用户输入的定稿正文是下游内容依据。正文和已有结构投影属于同一个大纲版本，绑定母本 ID、内容哈希、场次稳定标识和来源跨度。对原有场次保留标识，对用户新增内容标记为用户创作。程序按段落和已知锚点同步投影。无法可靠定位的编辑保留正文并提示受影响的场次，由下游按需补结构。已确认文本无需再交给模型重写一遍。
3. 用一次确认完成持久化与版本切换。提交带期望版本或哈希，并使用现有审计和失效机制。重复提交返回已有结果，旧页覆盖新版本时提示刷新。后台完成的草稿不能覆盖用户正在编辑的内容。再次修改从当前定稿创建新草稿，正式确认后仅让有实际依赖变更的场次与后续工件重新计算。全局人物身份或风格变更按真实影响范围传播。
4. 对导入的成稿剧本，允许直接以原稿加用户确认大纲进入统筹。对小说，后台补齐分场剧本和全局蓝图，专业模式仍可查看和编辑。后台无法产出某场的可用正文时，保留其他场次成果，并提供局部补写或人工编辑入口。

## 5. ② 分镜书与风格确认

1. 导演模式只显示导演风格、影片类型、集数和每集目标秒数。导演风格沿用模板解析器与已有默认选择，影片类型使用服务端已支持的真人和动画枚举。现有已冻结设置应被正确带入编辑预览，用户确认新版本后再切换有效风格。
2. 「生成分镜书」读取定稿大纲和可用场次剧本，按剧情顺序生成分集预览。每集列标题、场次、剧情节拍、关键对白和预计秒数。分镜书在数据层是现有 `DirectorEpisodePlan` 的可读视图，复用已存在的剧本与节拍产物。源文覆盖、顺序和版本来源继续由后端校验。
3. 默认优先满足用户指定集数，秒数按目标处理。沿用按自然场界切分的规则，避免截断对白。材料不足、单场过长或集数和时长明显冲突时，显示预计结果、差值及可行调整。用户可改设置或在预览调整场次，确认动作以预览实际结果为准。模型不得静默删掉有来源的场次或虚构一集来凑数。
4. 「确认分镜书」提交同一份预览的计划版本和风格来源，使用已有服务完成分集计划与风格快照的成对提交。后台先校验两边的期望版本，采用单事务或具备明确恢复语义的提交方式。过期或部分失败时，界面显示实际有效版本与可恢复动作。

## 6. ③ 按集拆镜与局部恢复

### 6.1 镜头表

每行至少能看见镜号、场次、画面动作、对白、成片秒数以及与上一镜「切开 / 接拍」的关系。有镜内快切时展开列出内部切点。需要时显示该行实际 H3 生成片段数和生成秒数。一个生成片段可以承载多个镜内切点，成片时间与生成片段长度分别计算。显示计划时长和集内合计，编辑一行后即时重算。

将现有 `ShotIntent.cuts` 与 `ShotSpec.continuity` 分别映射为镜内切点和跨镜关系。普通切开无需上一镜媒体，接拍沿用前镜真实产物和版本校验。现有 `ShotSpec` 的生成片段为 4–15 秒，本机工作流有更窄范围时以实际能力为准。短成片镜头可由合法片段裁切，长段可拆为多个合法片段并保持剧情和对白边界。未经确认的超长或越界结果不得当作可拍镜头。

### 6.2 生成、确认与回退

- 普通入口一次触发后台分镜任务，按集聚合、按场或必要的场内片段执行。复用当前 Worker、逐场分镜回执和台账桥接，识别场次脚本和镜头范围。相同的输入与版本复用已成功工件，失败时从失败工种或局部单元续作。
- 「确认本集镜头」将当前集可用分镜一次落成正式镜头并更新该集在分集计划中的镜头映射，统一版本校验、写入与回执。所有必需场次均须覆盖。已落镜的场可直接复用，重复点击不会增镜。内容不足时，仅对当前集给出定位到场次的处理入口。
- `SCHEMA_VALIDATION_FAILED` 一类格式问题按「保存可用内容 → 本地规范化 → 有限的定向修复 → 用户编辑」处理。程序可补稳定 ID、排序、确定性时码和可选字段默认值。必要的画面、人物、对白归属或时间关系缺失时保留待编辑状态。自动修复复用既有重试预算，绝不覆盖用户已编辑或已确认的版本。
- 场记、摄影和剪辑对创意质量的建议作为提示。涉及真实依赖、不可用时码或锁定事实的冲突，具名暂停相应镜头及其依赖，其他场次和集可以继续。真实服务商结果 `UNKNOWN` 先恢复或对账，只有已有授权流程允许时才发起新尝试。

### 6.3 分镜五个 Agent 统一预算

- 保留编剧、导演、摄影指导、场记、剪辑的现有角色和模型路由。使用文学链路已有的 `compile_request`、`plan_call_budget` 及可用的治理接口，接通最终发送路径，复用现有流式、限流、发送意图和回执机制。
- 预算输入包括系统提示、当前场正文、必要的上游产物、相关记忆、冻结风格和实际发送的结构要求。基于已验证的模型上下文与输出能力计算，计入推理预留和请求开销。60% 沿用文学方案的输出硬上限口径，实际请求按任务需要取更小预算，同时遵循 Provider、项目配置和可用窗口中更紧的限制。未知能力使用现有保守策略。
- 超出预算时先压缩摘要、剔除与该工种无关的上下文或拆场。保留当前场的已确认事实、对白与依赖证据。记录实际发送预算、输入估算、模型报告的用量、截断和分块原因。使用可控的测试 Provider 核验五个角色实际发出的请求。 [文学低阻断方案](SHINE_ELASTIC_LITERARY_ENGINE_V2_1_LOW_BLOCKING_PLAN_20261111.md)

## 7. ④ 按镜头备料与素材中心交接

1. 汇总已确认镜头内的角色、造型、场景、核心道具和确有需求的声音引用。每项需求绑定作品、集、镜头及版本。使用已有实体 ID、别名和造型或状态区分身份。一个条目显示使用集、镜头数和可展开镜号。镜头需求与实际素材绑定各有明确来源，待制作素材可以用现有需求实体表达，素材 ID 留到批准采用时再解析。
2. 先匹配当前项目有效的主素材，再展示素材中心可复用版本。已匹配条目给出明确复用状态。缺项由用户选「复用」「上传」「AI 制作」，可选项可「跳过」。所有「AI 制作」来自用户明确选择，点击一次「确认并送素材中心」生成所选任务。页面显示确认成功、任务已排队、候选待选、已回绑的实际结果。已有素材齐全或只余可选缺口时，直接显示可继续。
3. 素材中心使用既有图片和声音能力、权属登记、版本、候选及批准机制。按确认的需求版本和选中集合防重复提交。用户选定候选后，使用现有采用机制验证身份、项目、授权、文件及镜头版本，批量回绑到对应镜头。后台渲染进度和结果从素材中心读取，导演页提供返回和候选选择入口。
4. 仅处理已落镜范围。有新增或替换镜头时增量刷新需求。已被其他镜头复用的素材保留，已确认导演包和活动 Run 的输入保持冻结。发现过时的绑定建议时，返回对应镜头和重新核对入口。
5. 缺场景、道具等可选画面参考时提示一致性差异。正式 Ref2VA 镜头缺必要人物主体、必要音频，或工作流无法承载选中的引用时，显示受影响镜号及补齐动作。正式请求按用户选定且本机已验证的模式与工作流执行。

## 8. H3 指引与运行校验

| 类型 | 处理位置 | 判定 |
| --- | --- | --- |
| 大纲、分场文本、画面描述、风格措辞 | ①至③ | 允许自然语言，持久化可编辑正文。格式细节由程序整理 |
| 镜头编号、所属集场、成片时长、切点、人物与资产绑定 | ③至⑤ | 维护最小内部结构，由代码负责读写、补默认值和验证真实关系 |
| H3 提示词写法、分段组织和参考描述 | 最终提示词编译与预览 | 规则包作为写作指引。使用现有唯一 `H3PromptCompiler` 生成可追溯的自然语言成品，并保留固定规则来源、快照和参考映射 |
| 引用文件可读性、角色主体、工作流模式与映射、时码和生成片段长度 | ⑤至⑥的实际执行准备 | 按本机已验证的配置做确定性校验，问题显示到集或镜头 |
| 技术质检及可选模型审片 | ⑥至⑦ | 复用当前确定性技术质检和最终审片口径。VLM/ASR 等建议式结果按实测状态展示 |

在导演创作入口拆除由 H3 提示词习惯引入的格式阻断。内部的 HTTP 对象、镜头版本、ComfyUI 参数和工作流仍由程序结构化处理。保留现有官方规范来源与固定的提示词编译路径，避免为导演模式另造一套 H3 文本或执行器。

## 9. ⑤至⑦衔接、数据兼容与故障隔离

- **导演包范围。** 用同一个已确认分集计划、冻结风格和完整的目标集生成包。既有按卷范围和按集 Run 能力优先复用。支持在已有包构建与 readiness 路径上确定明确的集范围、版本、镜头映射及覆盖证明。全项目进度与本包进度分别展示。包必须包含所选集的完整镜头，未完成的一集不计入就绪或已交付。
- **依赖范围。** 预检只看目标包内镜头及其实际前置依赖。存在跨集接拍、共用素材或真实前镜依赖时必须校验来源版本及产物。若依赖未就绪，仅暂停受影响镜头或集。继续使用当前包确认、Run/Series/Job、Worker 心跳、GPU 租约与启动回执。
- **后期范围。** EDL、字幕、装配和交付对当前包及 Run 的版本与范围负责。后续集开拍时复用第一集已交付证据，不重提已经通过且输入未变化的镜头。历史成片及原来的包、Run、质检结论保留。不能凭另一包的旧素材将本次交付置为完成。
- **版本兼容。** 优先扩展现有工件和计划字段，复用 SQLite、旧台账、镜头、风格与素材的版本模型。旧项目根据已有事实显示进度，保留旧哈希序列化形状及旧专业入口。仅在真实数据需要时加向后兼容迁移，用脱敏数据库副本验证升级、恢复和重复启动。
- **异常恢复。** 导入、生成、落镜、素材回绑、包构建及开拍在版本校验和防重复提交下恢复。晚到结果不能覆盖新修订。刷新浏览器或重启本工作台，已持久化的工件、镜头和交付应可继续使用。独占 GPU、互斥和 UNKNOWN 对账仍交由统一调度和现有恢复路径负责。

## 10. 开发顺序与完成物

| 工作包 | 实施内容 | 当批完成条件 |
| --- | --- | --- |
| A 大纲和统筹 | 原地编辑确认，四项设置，版本化分镜书和风格确认 | 正常浏览器入口可编辑、定稿和分集。首次使用流程找得到下一步 |
| B 镜头拆解与预算 | 按集镜头表、批量落镜、局部重做、五工种预算接入、结构容错 | 一场坏格式能保留已完成内容。两集状态隔离，已完成集可进入④ |
| C 备料及导演包交接 | 按镜头汇总，选择 AI 制作，素材中心回绑，范围化导演包 | 已有素材可直通，选中项才提交，第一集可独立形成可拍导演包 |
| D 生产回归及实机验收 | 复用真实 H3、排产和交付，验证恢复、旧项目与本地启动 | 在 Windows 从正常入口完成两集真实 MP4 并证明首集无需重跑 |

先打通 A 到 D 的最小竖向闭环，再清理重复控件与兼容分支。定向修复优先落在共用服务层，前端、专业模式、旧 API 的调用仍走各自正常入口。新增测试集中在新的跨阶段合同和旧数据回归上。测试过程中遇到可恢复故障，修复后从断点复验。

## 11. 自审与验收

### 11.1 分层验证

| 层级 | 核对范围 | 必须覆盖 |
| --- | --- | --- |
| L1 单元 | 大纲版本、分集、切点、时长、素材聚合、预算、包范围 | 旧哈希稳定，集数与时长冲突有可读结果，镜内切点与跨镜依赖分离，预算包含最终请求开销 |
| L2 工程集成 | FastAPI、SQLite、Worker、Provider 替身、前端交互、现有导出 | 失败场隔离，重复点击无重复工件与 GPU 任务，旧页提交拒绝，断流不盲重发，旧项目升级后能继续，导演模式和专业模式均可打开 |
| L3 Windows 真机 | 用户入口、真实文本模型、素材中心、真实 H3、质检、成片导出 | 两集真实交付，首集在次集待修期间产出且未重跑，至少一次用户授权的素材制作与回绑，刷新或重启后从已有状态恢复 |

定向复用 `test_storyboard.py`、`test_film_crew.py`、`test_four_stage_section_bridge.py`、`test_director_run_scope.py`、`test_material_derive.py`、`test_material_director_flow.py`、`test_asset_center.py`、`test_freeze_unlock.py`、`test_h3_compiler.py`、`test_offline_e2e.py`，以及对应前端 storyboard、material preparation、director run 用例。完成相关后端批次、Ruff、前端类型检查、全量前端测试和构建。按仓库 `AGENTS.md` 核对 Windows 启动、退出和受影响的发版入口。

### 11.2 两集实机穿测

1. 用可公开的原创短篇或用户授权测试素材，在独立数据目录新建两集项目。真实浏览器导入，修改一条可追溯剧情信息，确认大纲。填写四项设置并生成分镜书，记录每集预计时长。
2. 生成两集镜头。第一集确认完整镜头表，第二集通过正常界面保留一场待处理。格式拒绝、断流及 UNKNOWN 使用 L2 可控故障注入覆盖。真机流程以真实界面状态和真实任务记录为准。
3. 为第一集复用至少一项素材，并经明确选择送素材中心制作至少一项素材，选定后回绑。记录候选、批准版本及使用镜号。用本机实际登记并验证的 H3 工作流，确认第一集导演包并从浏览器开拍。
4. 第一集经技术质检并导出 MP4。实际播放并使用 FFprobe 核对时长、画面、音频和字幕表现。记录真实 ComfyUI 任务、镜头成片及交付证据。若故事有对白，核对对白完整、语言、音画位置和片尾截断情况。
5. 刷新浏览器或按现有入口重启验收环境，确认项目可恢复。补完第二集待处理场次后从已有状态继续，导出第二集。比对第一集的 Job ID、片段及成片哈希，证明未触发第一集重拍。
6. 另用旧项目副本验证旧大纲、分集、主素材、导演包与交付可读可继续，既有活动任务和历史成片未被覆盖。记录专业模式入口及正常回到导演模式的行为。

### 11.3 验收口径

- **工程通过**需要相关测试、构建、旧项目兼容与阻断场景用例通过，并完成自审修复。**真实出片通过**需要两集都具备真实 H3 执行、实际产物、播放核对和续跑证据。缺证据的项目标记为未验证。GitHub CI 结果单列，本地测试不能代替远端状态。
- 报告按步骤记录主动点击数、强制确认次数、每集从生成到可拍摄的时间、素材和 GPU 等待、失败重试次数。区分用户操作时间与模型执行时间。记录正常路径是否还需要手工分卷、单独填锁定事实、逐场应用、再次确认分集或重复分析剧本。可在同一机器、同一测试输入和同一工作流下对比基线，保留实测差值。
- 每项证据注明被验收提交、系统及 H3 工作流标识、测试命令、通过/失败/跳过数、脱敏截图和本地产物位置。艺术审片与自动质检分别记录。真实项目原文、素材、视频、数据库、模型权重、连接凭据和未脱敏日志留在本机。
