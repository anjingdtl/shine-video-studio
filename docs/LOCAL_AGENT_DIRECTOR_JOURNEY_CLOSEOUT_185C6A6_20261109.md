# 本地 Agent 收尾建设提示词 · 导演模式全旅程

你接手 Shine 视频工作台导演模式的收尾修复。用户要从 Windows 新机安装、下载依赖与权重、使用素材中心、导入剧本，到真实 MiniMax-H3 拍摄出片。你的任务是用最小实现消除这条路径的串版本、重复任务、误阻塞和恢复死路，交付可运行代码与分层验收记录。保留简化导演体验，默认推荐多参考 H3 Ref2VA。已经显式选定的方案由用户决定，执行须使用该方案的准确身份。

## 2. 实施顺序

先留一份当前失败复现，再按以下步骤修。优先关闭新机硬等待、数据串线和外部请求身份风险，然后修采用/开拍操作与回归脚本。每个小提交都把旧反例改成正向验收，允许独立镜头、作品及阶段继续推进。

### A · 从安装包到可执行环境（J01–J04）

- **J01** 在 `build_test_package.ps1` 统一包根和文件绝对路径的规范表示，用可靠的相对路径算法。对清单做一一对应，保证每个文件在包根内、无绝对项/越界项。以 8.3 短路径、长路径及带空格/中文的路径验证同一个 committed tree；实际解包、全文件验签、检查 ZIP 清单和文件排除。入口保持 `一键安装并启动.cmd` / `SETUP.cmd`，ASCII CMD、含中文的 PowerShell 脚本 UTF-8 BOM。
- **J02** 合并下载仅依据规范物理目标、执行器和 pinned 文件闭包。计划的授权快照与实际执行的 owner plan/hash 分开表达，复用标记准确。修复执行回执、按计划或目标找回、详情的字段契约，已有消费者可兼容迁移。导向同一个尝试 ID，且刷新、浏览器缓存清空、换作品、并发双击、execute 已提交但响应丢失时均可回到状态。等待、暂停、继续、失败、对账和完成使用该尝试的真实状态。批准动作一次覆盖页面上展示并已授权的部署序列；切作品时停止后续自动链，回来接已有记录。对相同根不同内容按既有冲突规则提供有效路径。
- **J03** 将两条安装/复用入口里的全局 LLM 就绪从 H3 环境下载、检测、复用、登记和激活中解耦。将文本就绪显示为并行分支。按当前操作实际调用的角色检查路由与连接，不用全体工种的汇总代替。新项目从零能先检测/复用/计划下载，导入剧本能先保存并看到当前依据。生成大纲时才提示需配置其角色，分镜只看实际走的角色。已经可拍的镜头继续开拍。保持连接/目录/结构化生成证据的不同含义，连接测试与角色预览的既有入口保留。
- **J04** 让权重层、生产准入和安装/原位验证用同一事实。核验回执须绑定 variant、catalog、revision、逐文件长度/SHA、核验目录或已证明的缓存与实例关系；权重按图实际加载项确定。旧 registry 状态、同名文件和同长度错误字节都不能把层级点绿。真正有效的原位核验应直接复用；变化时只复核缺失或变化部分，提供就地核对动作。W6A8 继续独立候选，保持 `auto_download_allowed=false` 和候选身份，不继承 INT8 证据，不更改原位导入规则。若仅差可选且工作流未用的 LoRA，主路径应继续。

验收反例覆盖两作品同物理目标丢回执、断网后恢复、仍在核验时重开、取消和部分缓存、无 LLM 下载、只配置所需工种、旧状态指向错误 revision、缓存文件同长错字节、有效原位复用零拷贝。用本机 test double 验证副作用计数，真机证据另记。

### B · 文本路由、当前剧本与风格（J05、J06）

- **J05** 审计父任务、子角色和模型快照的实际执行身份，至少覆盖普通大纲/分镜、创意成稿、四阶段及专业角色。统一预览和 worker 的映射。优先让已排队任务按原配置继续、新任务按新路由走。若需阻止会使在途快照失效的配置修改，使用准确的影响范围和当前已有状态，避免用所有项目的历史 `NEEDS_REVIEW` 把新作品改派锁死。覆盖旧模型可继续、旧配置失效、并发保存、子结果未知和证据证明未发出的恢复。保留已有阶段产物与调用预算，提供原页面的安全续办。
- **J06** 把当前剧本（document ID/SHA）、确认大纲（artifact ID/SHA）、分集计划来源、逐场有效 apply 回执和镜头 revision 串起来。所有建包入口，包括普通按镜头、按场次物化和四阶段按卷，读取同一当前依据及对应范围。上传 B 只是候选，明确选择或确认 B 才推进当前依据。改 B 或重确认 A 的新大纲后，不用 A 旧的计划/镜头显示 B 已完成。界面跳到第一个真正需要续办的动作，合法可复用的结果保留。手工分镜继续支持无文档入口。历史包及既有交付可查看、下载。
- 风格继续使用现有七维草稿、预览和显式冻结。给后续修改沿已有镜头修订/重编流程生成新版本。回归内置风格、旧风格、采纳草稿后冻结、分镜和 H3 编译透传。同一个风格 ID/SHA 必须出现在镜头、导演包和执行请求中。不要为内置风格或选型再添审批层。

验收按 `A→确认→落镜→建包`、上传 B 未选、选 B、B 大纲确认、重新物化、启动 B 做完整对照。至少一份普通剧本和一个四阶段小卷。比较实际包清单及应用回执；查看 A 的历史不改变 B 的范围。

### C · 素材中心到镜头（J07）

- 保留全局素材版本、QC、晋升、项目授权分配与镜头采用的现有语义。把分配成功的项目素材 ID、全局版本 ID、角色/实体与用途回执接回当前作品的素材准备区域，并从该回执提供「用于这些镜头」。从镜头需求也能定位已有候选/项目素材。清楚显示哪些镜头已绑定、将采用、可跳过、存在冲突。供用户直接从一次采用确认调用现有预览和应用服务。
- 用户显式换素材时生成新镜头 revision，并提供更新当前导演包的路径。已完成或历史包按原快照保留。历史确认包不能成为永远解不开的锁；若正运行或结果未知，按原尝试安全收束，再继续明确选中的范围。判断前先确认冲突真的是当前范围、镜头版本与活动生产所有权。
- 采用回执绑定规范请求（作品、版本、素材、镜头列表、角色和预期 revisions）；同 key 同内容返回原回执，同 key 不同内容给具名冲突。多镜采用事务一致且能抵御重复、并发与过期预览。映射基于同一 `entity_id`/明确身份，按实际需要选择，不从候选池随便填满空槽。撤权或文件变化后只影响后续使用；既有授权回执和媒体历史保留。

验收覆盖导入与人工确认后分配，关联已有分镜，旧包后新采用，多镜中一镜 revision 漂移，重复点击与换 payload，撤权及恢复，已有素材复用、空的可选需求。可选 Qwen 和音色生成用各自现有能力入口，缺能力仍可导入合规主素材。

### D · 一键开拍、预检与外部调用（J08–J10）

- **J08** 合并两处制作选型到同一份明确的作品/当前制作范围选择。用户选择优先于质量档推荐，刷新、切阶段和显式 W6A8 都不静默换方案。设置页的方案列表用于参考。工作流声明槽位代表可用容量，绑定义务来自镜头人物与有效请求。已有足够 Ref2VA 参考的镜头允许空场景图槽；命名主体缺位时继续提供具名的补素材入口。对没有任何参考的镜头，只有现有兼容并由用户明确选用的方案才可走另一模式；默认不偷偷换成 T2VA。音色按实际对白和所选图合同判断，无对白不自动加音频参考。
- 一键动作先收齐用户明确选择的范围和所需变更，再通过权威预检。利用已批准绑定和现有应用服务，无效配置/其他镜头失败时不遗留已写绑定的半成品。禁止先发一串 `PUT /bindings` 再拒绝整次开拍。保留用户可查看的计划与具名原因，能推进的镜头在其正确范围继续。
- **J09** 用单一无副作用预检表达导演包、Run、Series、Job 实际共享的条件。复用既有 `OutputSpec`、H3PromptCompiler、profile_gate、引用映射与生产准备逻辑。涵盖宽高/时长/对白与切点、profile 模式/variant/graph/map、主素材实际可用性与当前权利、style/rule/shot revision。可创建草案用来定位缺口，正式启动读同样的事实，避免先承诺「可开拍」再到 Worker 才发现静态错误。把运行时、真实前镜衍生等动态条件标明是等待或实况改变，并在恰当时重新核对。
- **J10** 将普通单镜按钮接入现有 `request_key` 语义，UI 重试和掉线重接复用同一 key；兼容客户端应能发现当前归属和进行中的任务，合法新拍有独立身份。明确同一镜头正在由哪个 Run/Series/Job 处理，避免三处重复发单。修订/失效历史的状态与外部提交回执分开管理，禁止覆盖 `UNKNOWN` 的根因。对账复用 Attempt/graph hash、外部 prompt ID 和已落盘产物；按已知状态安全恢复，未证明前拒绝同一逻辑任务被换键重投。后台 Worker 不持 SQLite writer 事务跨外部请求。GPU lease、PID/birth/Job Object 与 release/series transition 保持原有原子合同。

验收覆盖两个前端开拍入口和直调 API。至少断言空可选槽可以开始、关键主体缺失给准确入口、失败不写绑定、选型未替换、宽高未映射在派发前以同一原因返回。测试提交响应丢失、双击、旧镜头修订后仍可对账、未送达后安全继续、已有产物可复用、独立镜头继续。只有合规的当前请求可触达唯一 H3 提交漏斗。

### E · 真实进度、交付与浏览器回归（J11、J12）

- **J11** 一次解析 `project/package/episode/run` scope。显式 Run 要属于所选包；只指定 Run 时从其推导包。阶段、事件、计数、停止/继续、回放和下载全部从同一 scope 取值。未开拍包显示待开拍，异包活动 Run 只在明确归属的提示或历史入口出现。跨包、跨项目、部分分集、历史深链接及快速切换时清掉旧异步响应，后期修订只产生新交付版本。
- **J12** 更新 `verify_v13_web.py` 的模型管理控件定位，从真实可访问名或稳定的语义定位交互，续跑全脚本。保留模型配置、验证、路由的业务断言。补一条正常导演旅程的浏览器回归和关键断网恢复。完成后同时对照 Windows 与 Linux CI，按实际日志记录平台限制、fixture 问题和产品缺陷。

验收用包 A 有 Run、包 B 无 Run 的对照，验证 B 无 A 的控制和片源；指定 A 可正确回看。双集不同文件名及归属，切换不串片。最终用 FFprobe 加 FFmpeg 实际解码并对照产物 SHA，分别报告技术 QC、建议审片、最终人工验收。
