## 二、怎么把环境跑起来

```powershell
cd F:\ClaudeWorkSpace\projects\shine-video-studio
& .\scripts\start_shine.ps1 -ApiPort 8000 -WebPort 5173
```

**必须保活父进程**，否则 `Start-Process` 起的 api/worker/web 会随父 PowerShell 退出被杀（日志显示 started，端口立刻 502）：

```powershell
& .\scripts\start_shine.ps1 -ApiPort 8000 -WebPort 5173 *> .\.local-acceptance\witch-ui-20261109\_start.log
while ($true) { Start-Sleep -Seconds 30 }
```

停：`backend\.venv\Scripts\python.exe scripts/stop_shine.py --data-dir ".local-acceptance\witch-ui-20261109"`
（注意：`stop_shine` 会把托管 ComfyUI 一起停掉，下次渲染由 worker 自动拉起，冷启动约 1–2 分钟。）

ComfyUI 端口 8188，前端 5173，API 8000。本机 curl 直连常被代理挡，脚本里用 `httpx.Client(trust_env=False)` 或 `urllib`。

### P0-1 成片只含 3 镜，不是 6 镜

说明装配的 EDL 只取了**最后一条 committed series（`c15f5cd7`，3 镜）**，而不是"六镜这条完整的剪辑"。
本轮为了绕开当时序列中止的问题，是分三段拍的：
- `d51c2882` 六镜全量（NEEDS_REVIEW，只跑完第 1 镜）
- `bc840220` 第 2–6 镜（NEEDS_REVIEW，跑完第 2 镜）
- `c15f5cd7` 第 4–6 镜（COMPLETED）

**要修的是"装配以什么为一条片子"**：现在以单条 series 为单位，而用户脑子里的"这条片子"是六镜。要么让装配按镜头顺序吃已通过的成片（跨 series 也认），要么在 UI 上把"这一段"显式定义清楚。这条不修，用户看到的永远是"半支片"。

### P0-2 LLM_FORMAT 卡住出图（用户问"为什么那么多图没生成"）

证据（`agent_task_records`，`role_id='producer'`）：

```
REJECTED LLM_FORMAT  correction 1  schema_errors: [{"field": "appearance", "type": "maxLength"}]
```

三条都是同一个原因：`MaterialImageBrief.appearance` 的 `max_length=1200`（`backend/shine/materialprep/contracts.py:115`），模型写的英文外貌描述**超长**；纠错只说了"修 validator 指出的字段"，没告诉它"要短多少"，第二次仍然超长 → 整项判 FAILED，于是这几项永远没图。

受影响需求：`卡特·兰尼斯`（人物）、`行宫内早餐桌旁`、`边陲镇圆形广场及处刑高台`（场景）。典型的"名字长/场景复杂 → 描述写得多"。

建议修法（按性价比）：
1. 纠错提示带上当前实际长度与上限（如"你的回答 1,684 字符，上限 1,200，请压到 1,200 以内并保留关键形貌"）；
2. 上限适度放宽（1,600 左右），或按 family 区分（场景允许更长）；
3. 兜底：仍超长就**按完整句子截断**到上限内，并记 `appearance_truncated: true`——冗余细节不该让整项报废（用户要的是图，不是完美散文）。

### P1-1 两个罗兰，而且长得不一样

数据层三份（都在同一项目）：

| asset | 文件名 | entity_id | 创建 |
|---|---|---|---|
| `39ee9315` | 05-程岩（罗兰·温布顿）.png | 程岩（罗兰·温布顿） | 11-10 01:34 |
| `27dab390` | 05-程岩（罗兰·温布顿）.png | 程岩（罗兰·温布顿） | 11-10 04:12 |
| `d4ef4a01` | 15-罗兰.png | **罗兰** | 11-10 04:12 |

两个问题叠在一起：
1. **同一身份两份 master**：39ee 与 27dab 同 entity 同文件名、都 approved+locked。落镜绑定用 `_approved_master_for_name` 按包含关系遍历候选，**没有排序也没有唯一性保证**，不同镜头可能绑到不同那张 → 同一角色换脸。
2. **别名没归并**：「罗兰」与「程岩（罗兰·温布顿）」是同一个人（本名/身份名），需求清单把它们当两个实体各出一张图，于是"两个罗兰长得不一样"。

建议修法：绑定选主素材时同 entity 取**最新且唯一**的一份（并按 `created_at desc` 确定性排序）；生成新版本时把同 entity 旧 master 解锁归档（保留历史，不再参与绑定）；identity 层做别名归并，至少在清单里给出"这两个是同一人，要合并吗"的显式选择。

### P1-2 用自己的图替换素材会失败

接口本身是通的（已复现）：PNG 201；同一文件重传 201（幂等返回已有 asset）；HEIC 415 `File extension does not match asset kind`。

问题在前端与流程：
1. `MaterialPreparationPanel.uploadOwnMaterial` 用的是裸 `fetch`，报错只显示 `上传失败 ${status}`，**后端 detail 全丢了** → 用户只看到"失败"，不知道是格式/大小/身份不一致。
2. 只认 PNG/JPEG/WEBP（`security.py:verify_upload` 的魔数 + 扩展名双减）。手机直出 HEIC、截图 BMP/GIF、微信转存的"jpg 其实是 webp"都会被拒，且提示语不告诉用户怎么办。
3. 上传成功后资产是 `approved=false, locked=false`，需要再走审核才真正成为主素材；用户体感是"我传了，但没换成功"。
4. 上传先做 sha 去重、后做类型校验，于是"同名不同格式"会静默复用已有资产（顺序值得调整）。

建议：错误提示读 `detail` 原样展示；明确告知支持格式并给"请先转成 JPG/PNG"的可操作文案；用户自己上传的图默认就是他要用的主素材，上传即 approve+lock 并绑定到该需求（可撤销）。

## 八、这一轮踩过的坑（省下一个人时间）

- LLM 预算是 1M 上下文 / 128K 输出，不要再按 16K 配；截断时必须带 `finish_reason` / `reasoning_tokens` 才能诊断。

- 序列中止后渲染中的 job 会变成 `COMFY_ACTIVATION_RECONCILIATION_REQUIRED`，用 `POST /api/v1/operator/jobs/{id}/abandon`（注意是 `/operator` 前缀）收尾，不要直接改库。
