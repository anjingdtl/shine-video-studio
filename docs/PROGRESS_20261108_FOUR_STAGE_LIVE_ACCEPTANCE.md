## 2. 门禁复核（用户要求「不要总是硬阻滞」）

**软化（1 项）**：蓝图草稿即可驱动场次剧本（trace 记 `bible_basis=draft_unconfirmed`），
卷交付仍要求已确认蓝图——硬阻滞变记录在案的软依据。

**保留但全部配可操作出路**：同意门禁（面板「授权本机文本发送并继续」一键授权+续跑）、
UNKNOWN 不重放（恢复路由拒绝盲目重排队，指向核对路径）、生产准入（交付按钮列出全部具名缺项）、
母本隔离、sha 确认链。所有拦截都指向用户能执行的下一步，不再有死胡同。

## 3. 内置浏览器拟人实测（真实 LLM，中止前完成的部分）

环境：项目自带启动器重启的栈（8000/5173，数据目录 `.local-acceptance/live-browser`），
MiniMax-M3.1-Flash 档案路由至四阶段工种；测试作品「四阶段实测 20261108」；
测试文本为 3 章原创短篇（约 1,000 字）。母本文档经 API 入库（IAB 运行时不支持文件上传，如实记录）。

### 甲、实测通过

1. **T1 新建作品**：导演模式新建，六阶段步骤条真实点亮（步骤 1「下一步」）。
2. **T2 四阶段面板 ①**：选择母本 → 生成 1 卷分卷方案（覆盖完整）→ 人工确认 → 卷文档物化。
3. **T3 大纲提取（真实 MiniMax）**：首次点击即被同意门禁拦截
   （`REMOTE_AGENT_CONSENT_REQUIRED`）——**门禁按设计工作**；面板随即给出
   「授权本机文本发送并继续」按钮；点击后授权+自动续跑，真实 LLM 完成三段提取与归并
   （任务 `SUCCEEDED`），面板显示「5 个待确认问题」；点击「确认本卷大纲」
   （questions_sha256 一并提交）→「大纲已确认」。
4. **动态进度条**：任务进度块按设计渲染——「提取大纲 EXTRACT · 0/3」实时推进、
   「生成全局故事蓝图 · 排队等待」、阻塞态显示具名原因与恢复按钮；仅在有活跃任务时每 4 秒轮询。
5. **证据截图**：`gui-test-screenshots/t3_consent_block.png`（进度条+授权按钮）。

### 乙、实测中发现并当场修复的缺陷（三个都是真 Bug）

| 缺陷 | 根因 | 修复 |
| --- | --- | --- |
| 面板永远停在「正在读取」 | 我新增的 API 客户端函数带 `${API}` 前缀传入 `api()`（其内部再加一次）→ 实际请求 `/api/v1/api/v1/...` 全部 404 | 整块重写为与既有函数一致的裸路径（提交 `164bf85`） |
| **大纲卡在 1/3（用户报告）** | Worker 文本队列 3 拍突发计数器只在队列空时归零；渲染运行时配置变更（`ACTIVE_RUNTIME_CONFIGURATION_CHANGED`）在两拍之间抛出后计数器永久冻结，文本队列被饿死——**LLM 答案其实已返回并落库** | `run_configured_once` 在运行时拒绝该拍时归零计数器（提交 `a0da58c`），回归测试驱动「冻结计数器+拒绝运行时+排队大纲」全序列 |
| 蓝图任务 `PIPELINE_OUTLINE_CHANGED` | 队列侧 `queue_bible` 的大纲扫描在代码重建中**丢失 `project_id` 过滤**，跨项目大纲混入 refs；执行时守卫按设计拒绝 | 恢复项目过滤（提交 `6c9c098`），回归混入两项目大纲并断言只有本项目的进入 trace |
