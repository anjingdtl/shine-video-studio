# P4 建设方案：淘汰静态导演风格入口，电影 Skill 原生增强现有五角色

> 状态：待实施；前置：P1—P3 生产底座已验收。  
> 本阶段目标是提升真实成片艺术质量，不追求新增 Agent、工作流、UI、LLM 额度或安装依赖。

## 1. 用户核心判断

旧“名导风格”模板在真人/动画媒体类型以外，没有产生可感知的稳定艺术效果。真正有价值的是让现有编剧/导演/摄影/剪辑/场记 Agent 在撰写既有结构化方案时，按镜头需要检索专业电影知识 Skill：场面调度、构图、可表演动作、运动动机、节奏、视觉连续性。Skill 是现有 Agent 的专业方法文件，不是另一个能否“通过”的业务门，也不应成为全新 LLM 链路。

新的默认界面保留“真人演出 / 2D 动画演出”及用户镜头重点干预；不再强制选择王家卫/诺兰等静态导演模板。高级 Skill 选择不是基础流程必填项，自动调用为首选，缺 Skill 时现有能力可生产而不全局阻断。

## 2. 现状与必须保护的事实

- backend/shine/h3/film_type.py 的 FilmType.LIVE_ACTION / ANIMATION、H3 摄影媒介锚点是真实有效控制，必须保留。
- director_styles/catalog.py / resolver.py / service.py 与 config/director_styles/builtin/ 存在旧导演风格绑定、确定性技巧选择、冻结版本哈希；api_director_styles.py 和前端曾消费该入口。旧 StyleResolution/StyleBible 在历史镜头、旧 Run/包与 prompt 重放中有兼容价值。
- agents/crew_prompts.py 已有五角色权责、镜头静机位默认、物理连续性、对白语言与声音合同；agents/film.py / film_contracts.py 存储 DirectorPlan、CameraPlan、EditIntent 等原有结构化字段。
- director/pipeline.py 文学上下文与五维记忆、LLM Gateway/上下文预算已存在；不得再建平行故事记忆库或额外 LLM 调度器。
- h3/compiler.py 是唯一 Ref2VA 终稿编译出口，h3/rulebook.py 钉官方 h3-prompt-writing RulePack/hash；历史 1.3.0 双变体重放与 1.4.0 保持不变。
- quality/semantic.py、production/episode_delivery.py 已有 VLM 建议与后期剪辑建议；2026-11-21 验收报告的真机艺术 A/B 只有单镜，未完成声音真机听审、充分盲评，不能声称效果已证明。

## 3. Skill 文件与供应链边界

建议仓库内可审阅的 cinema skills 包：每种技法以 SKILL.md 为入口，可选 references/ 中放原创技法说明、拍法优缺点、适用条件与反例，另有 manifest 声明唯一 ID、版本、作用角色/产出字段、信息来源、license、sha256。一个技能只描述“可选择的拍法/原因/约束/示例”，不能更改代码、执行 shell、自动网络访问、下载权重或指挥 ComfyUI 运行。Skill 的版本/内容哈希进入创作产物溯源的既有 trace/快照（能复用则复用，不新增与现有 artifact 平行的身份台账）。

- 优先自写可商用、可审阅的专业电影方法内容；第三方 SKILL.md 必须核验作者、许可、版本和安全边界；不得直接搬运不适宜许可的仓库或在运行时直接从 GitHub 下载任意脚本。
- 官方 MiniMax-H3 h3-prompt-writing 是 H3 编译合规规则，和“电影艺术技法 Skill”不同：不得用社区 Skill 替换原有官方 RulePack/hash 或最终编译器。
- 技法材料仅作为 LLM 不可信参考文本输入，有明确作用范围；Skill 文本中的“覆盖系统指令、执行命令、改写素材/台词、联网”一律无权生效。
- UI 默认随内置轻量版 Skill 即用，不要求用户安装 Python 环境、浏览器插件、额外服务器或开启联网；没有参考附加文档可退回既有 Agent，不产生阻断。

## 4. 不新增检查器的动态选择方式

用户已冻结文学和镜头事实 → 现有 Agent 即将执行编剧/导演/摄影/剪辑/场记任务 → 在当前 LLM Gateway 调用构建处，根据任务角色、镜头 tags、已冻结风格/媒介、素材和用户强调的表现重点，选少量相关 SKILL.md/参考段落 → 将专业知识作为上下文的一部分 → 同一个 Agent 输出原来的 Film Contracts → 现有唯一裁决口按当前合同/人物/镜间/镜内 CUT/官方 H3 格式校验 → 原 H3 Compiler 编译 → 原统一生产。

Skill 选用必须在现有弹性上下文预算下进行；先目录摘要，按需加载少量片段，按可用 token 限额截取。不得每一镜全部加载五个全量 Skill；不得每次新增五次 LLM 推理并行服务，也不得加一个“Skill 审核 Agent”把新生产卡住。

角色建议：
- 编剧：人物意图→可观察动作，起始站位/姿势、动作完成、道具接触、情绪外化，避免以“想起、害怕”直接做不可拍动作。
- 导演：场景信息揭示节奏、人物走位/视线、镜头的叙事目标、静机位优先、相邻镜头动作连接。不得重算冻结的用户时长。
- 摄影：镜头起止构图、景别、景深、机位与轴线、运镜动机/幅度/速度、空间层次；没有动机不开启旋转/推拉/摇移。
- 剪辑：节拍、视线匹配、动作匹配、cut 与 last_frame 接续差异；渲染前仅做剪辑意图，渲染后才基于真实镜头决定入出点，不能凭空发明真实素材时间码。
- 场记：地面接触、道具交接、身体重心、屏幕方向、动作阶段、镜间复现一致；沿用既有连续性判定，不建立另一套“全片叙事一致性引擎”。

Skill 与用户明确镜头干预、冻结台词、角色身份、素材绑定冲突时，只允许作为候选技法被忽略，不得覆盖授权事实。原有 StyleBible 是否仍承载冻结的视觉合同，需要先做依赖审计；新创作可用 FilmType + 已有基本 StyleBible 默认生成并冻结，不能直接移除该必需合同造成投产阻滞。

## 5. 旧导演风格退出路径（安全渐进）

1. 先清点所有 director_styles 的消费者、表单、API、老数据库和历史 prompt / 编辑意图字段，形成影响地图。
2. 新项目或新导演包不再依赖固定“名导风格”选择；把原有 style binding 从默认必经 UI 移除或降为历史只读入口。绝不直接 DROP 旧表、删已冻结 style_version/hash、删除旧六模板造成历史失败。
3. FilmType 真人/动画通过现有 H3 规则继续作为硬媒介约束；风格/色彩/光影建议交给 Skills 与现有 LLM，仍写入合法 StyleBible/CameraPlan，并与用户偏好保持一致。
4. 既有风格模板如果含一般性电影技术可合法提取为原创通用 Skill 知识；不能把“某名导名字”作为 H3 质量提升的唯一指令或重复注入。
5. 回归新建、修订、冻结、恢复、旧镜头重拍及导出；旧系统的 StyleVersion/Prompt provenance 原样可读可复算。确认所有新调用路径退出旧风格解析后再做代码/界面瘦身。

## 6. A/B：用真实艺术效果决定是否推广

严格使用同一文学/分镜单元、相同角色和场景已批准参考、同一 FilmType、模型、ComfyUI 配方、尺寸、fps、采样策略、声音合同；比较“旧 crew prompts”与“Skill 增强 crew prompts”产生的实际镜头。因为生成有随机性，不应以单镜和一次 seed 偶然胜出就当作成功。

建议样本：至少两个媒介场景（真人与2D动画），至少各 5 镜以上、包含对话镜、无对白镜、双人同框动作、上一镜续接、独立 cut、复杂道具和镜头运动；相同生产预算，随机/seed 记录。由至少两名审看者盲评分 1—5：叙事清晰、动作可执行、构图光影、运镜动机、剪辑连续、人物稳定、总体审美；记录置信及反例。阈值作为试验性目标：总体均分提升 ≥0.5 / 5 且关键硬回归为零；不满足则关闭 Skills 默认接入并报告失败，不美化结论。

防回归尤其覆盖：“角色从地里长出来”、人物凭空出现/消失、道具穿帮、无意义推拉摇移、镜间人物方向跳变、旁白乱入、外语对白/背景人声、2D 动画变写实、真人变动漫。对白实际听审应配置既有 ASR/人工听审；VLM/ASR 未配置时记 UNAVAILABLE，不阻塞 H3 生产，也不能宣称声音已通过。

后期建议必须看真实视频：复用现有 semantic QC、cut-suggestions/EDL 和用户审片决策，不新增多轮无休止的“AI自己评价自己→重拍”生产循环。失败只对关联镜头通过原修订/重拍链触发，避免无差别重渲全集。

## 7. 测试与验收

- Skill 目录扫描：签名/哈希/许可/作用范围/可读取引用，非法入口内容不可执行，缺 Skill 可降级为既有 crew。
- 选择器：同任务标签 deterministic 选相同 Skill 列表；按角色与 context budget 有界；禁止长篇小说/全 Skills 倾倒。
- 五角色原 schema、镜头数量/时长/CUT、资产身份、对白原文、语言策略、官方 H3 编译版本/sha 均不被 Skill 改写。
- 新项目不选名导模板就可完成 StyleBible 冻结及出片；历史含导演风格的既有镜头仍能重放。
- 真机 A/B 的证据：baseline/enhanced 的 ShotSpec、技能清单、prompt SHA、graph SHA、作品/镜头/技术日志、真实输出文件哈希、听审结果、盲评分及未通过项。
- 全部非模型 hard tests / 前端构建/完整后端分片过关，任何新增“下载 Skill/安装 Skill Runtime/校验 Skill 才能拍摄”视为阻滞回归。

## 8. 阶段交付和回滚

交付 Skills 原创目录和来源清单、调用映射、旧风格退出路径、5角色典型输入输出例、A/B 真实证据与 P4 acceptance MD。主要回滚点应是“是否在现有 Agent 上下文启用 Skill”，而非切换整个生产引擎；出现不可控冲突即可在原调用处关闭 Skill 注入，H3 原生路径继续可用。

本阶段不改变 P1—P3 的动态图编译、整备与生产准入，也不修改 H3 旧编译器的冻结字节。实现、测试并在本地提交后停止，等待用户验收与后续合并决定。
