# Shine 双生产线隔离架构暨 H3 自主制片四阶段生产线 V1.0 建设方案

> 状态：可执行设计基线（待本地 Agent 根据最新 main 校准实现）  
> 制定日期：2026-11-20  
> 原始远端基线：`main@9be718b22397bea0204f293a5db7677352eb74d4`（2026-11-19 17:32:03 UTC）  
> 目标：在**不改造现有七阶段生产线**的前提下，新建并行、独立、可回退的四阶段 H3 自主制片生产线。  
> 本文是设计约束和建设任务书，不声明功能已在代码中实现。实际开发以本地拉取时的最新 `origin/main` 为准。

## 0. 最高约束 / 不可谈判边界

1. **并行双生产线**。七阶「AI 导演」保留原 UI、创作逻辑、数据库事实、阶段判断、模型调用、后台 Worker、ComfyUI 调度、成片行为；新四阶「H3 自主制片」另建界面、业务模块、事实状态、任务执行、素材与交付镜像。**四阶不通过调用七阶业务 Service 达到“复用”**。
2. **镜像复用，不是跨线共享服务**。从七阶既有实现选取稳定能力，复制/移植到 `manual4` 独立命名空间，固定来源版本和文件哈希，清除不必要的七阶依赖，建立四阶独立测试。不得引入 `manual4 -> shine.director / shine.production / shine.materialprep / shine.media.delivery_engine` 等七阶业务导入。H3 编译、素材制作、视频装配中属于七阶业务的部分同样采用隔离镜像；允许调用通用第三方框架、操作系统接口、独立的底层基础设施。
3. **三原则分别在每条生产线内成立**：一套事实、一个裁决、一个执行者。禁止同一生产线增加并行环境检查/素材检查/投产判决/执行队列。两条线之间不共享可变业务对象。
4. **仅平台壳允许最小变更**：项目管理/路由、选线登记、启动器或系统级 GPU 资源仲裁。不得为了四阶对七阶现有业务 API、数据合同、行为语义、前端七阶页面进行重构、兼容性放宽或全局挂钩。
5. **共享物理资源不等于共享业务**。同一机上模型权重可只读共用；ComfyUI 执行实例、端口、工作流注册、运行日志/队列/缓存状态应隔离；GPU 访问必须由系统级独占租约实现真实互斥、崩溃恢复和故障提示。禁止以在两条业务 Worker 间互相调用的方式协调 GPU。
6. **默认保留旧行为**。全部现有项目隐式属于七阶，旧 API 未指定模式时维持原行为；新建四阶项目明确选线并持久化。禁止自动迁移/重解释任何七阶项目、镜头、资产、提示词、已有成片和数据库。
7. **真实生产受 H3 项目既有能力边界约束**：V1 真实执行仍是 MiniMax-H3 Ref2VA，必须具有合法参考素材、模型和工作流，不把“手写提示词”错误解释为可以纯文本直拍；不得绕过 H3/硬件/授权/素材安全检查。
8. **用户人工内容为权威**。四阶的分镜结构/时长与 H3 原文必须经用户确认；LLM 只提取和归类，不改写用户镜头、对白、情节和提示词。禁止人工提示词失效后悄悄回退到自动编译文本并开始生成。
9. **本方案禁止先造新基础设施**。不新增第二个四阶检查链、第二个四阶调度器、第二套四阶状态裁决。同一能力只有一个四阶镜像实现。

## 2. 产品定位和用户边界

- **七阶 AI 导演线**（原样）：小说/创意 → 剧本与统筹 → AI 分镜 → 素材 → 导演包 → 生产 → 成片。
- **四阶 H3 自主制片线**（新增）：人工分镜书 → 素材生成 → 排片生产 → 产出成片。
- 用户可在项目新建流程选择生产线；选择是**项目身份**，不是可随时切换的普通界面选项。
- 四阶主用户已经决定镜头、镜长和 H3 文本；系统负责解析和呈现、素材制作、批量执行及交付。
- V1 支持粘贴文本、导入现有可解析格式的文档，以及在简单集镜表中手工建立/编辑。扫描图 PDF、图片 OCR 等不得假设现有可靠能力，需识别不支持并明确提示；未经确认不引入新的 OCR 风险链。
- V1 不提供剧本生成、五 Agent 创作、剧情再编写、自动运镜重写、全片创作代理，也不改写七阶 UI。
- V1 不支持同一个项目同时跑两条线，不自动迁移旧项目；跨线素材转移若后续需要，只允许按内容哈希、授权与校验进行显式复制导入，而非共享可变记录。

## 3. 用户旅程与极简 UI

```text
项目管理
  └─ 新建作品 -> 选择生产线
       ├─ AI 导演 · 七阶段 (已有, 原样)
       └─ H3 自主制片 · 四阶段 (新增)
             ① 人工分镜书
                导入/粘贴/手工建立 -> 自动提取分集、镜序、时长、素材实体
                -> 一页预览编辑 -> 确认冻结
             ② 素材生成
                查看按镜归并后的需求 -> 已有镜像库选用 / 生成 / 上传
                -> 审核晋升、绑定素材 -> 确认完成
             ③ 排片生产
                每集每镜贴入 H3 原文 -> 选择画幅/分辨率/CUT和连续性
                -> 冻结提示词 -> 投产快照 -> 四阶 Worker 批量生产
             ④ 产出成片
                按集预览 -> 单镜返工/重拍 -> 装配/字幕(已具备者)
                -> 交付与验收
```

UI 约束：
- 延续 Shine 现有圆角、毛玻璃、主题色、字体、交互规范；以**四阶自己的组件镜像**承载，CSS 命名空间 `m4-`，避免全局样式覆盖。
- 四阶段分别独立简单页面，同级步骤导航、顶部项目与就绪信息、底部唯一主要操作按钮。禁止复制七阶的多个重叠操作面板、隐性阶段跳转及内部异常栈。
- ① 分镜表格（集/镜/秒/画面摘要/素材需求）可直接编辑；② 素材卡片（缺项、复用、生成、上传、确认）；③ 每镜 H3 文本与状态、成片参数、队列；④ 成片预览/重拍/导出。
- 错误必须显示到具体**集、镜、素材或执行步骤**，给唯一修复动作；不让用户到其他隐藏设置页反复寻找登记按钮。
- 四阶页面只读四阶状态投影，不调用七阶 `director/journey`、`director/overview`。

## 5. 项目级选线、隔离身份与平台壳

- 项目管理同一入口，UI 先输入项目名，再选择「七阶 AI 导演」或「四阶 H3 自主制片」，确认后创建项目。新建流程原子性优先：不要生成尚未选线却被当成七阶的半成品。
- 平台登记 `project_id, workflow_kind, created_at, selection_revision`；`workflow_kind` 为 `director7 | manual4`，并提供版本化的项目模式读取接口。为兼容旧记录，**没有选线登记的历史项目只解释为 director7**。
- 七阶创建接口及默认行为不变；可单独建 `POST /api/v1/platform/manual4-projects` 执行“创建平台项目身份+持久化四阶选择”的原子操作，避免侵入旧 `POST /projects`。API 命名本地审查后定案，禁止依赖既有 `create_project()` 内部 commit 引入半提交。
- 平台项目表只承载共通的展示身份（ID、名称、选线）；四阶业务表/数据库独立，读取项目元信息不能顺便触发七阶服务。
- 项目列表中每行按选线调用自己的只读摘要。打开七阶仍进入原界面；打开四阶只进入 `Manual4App`。
- 禁止在已有四阶数据后切换为七阶或反之。已进入生产的项目切换需另建项目，不隐式迁移业务事实。

## 6. 数据与状态隔离

- 保留现有七阶数据库、旧文件路径原样；四阶建立**独立 `manual4.sqlite`（或本地明确确认的独立数据库）与单独数据根目录**，所有表/媒体/生成物/任务/日志独立；避免借用七阶 ORM 的关系和数据库迁移。
- 四阶表建议：`m4_projects`、`m4_source_documents`、`m4_storyboard_revisions`、`m4_episode_plans`、`m4_shots`、`m4_material_requirements`、`m4_asset_versions`、`m4_shot_asset_bindings`、`m4_manual_prompt_revisions`、`m4_execution_snapshots`、`m4_production_runs`、`m4_jobs`、`m4_job_attempts`、`m4_deliveries`、`m4_audit_events`。这是建议逻辑表，不要求机械一表一模型；最终按单事实原则合并冗余状态。
- `project_id` 可与平台项目身份对应，但不建立跨两业务 DB 的外键；四阶资产与七阶资产 ID 不可互认为同一对象。
- 文件采用四阶独立根目录，遵守路径穿越防护、原文件 SHA-256、媒体字节校验、原始导入保留；禁止在旧路径下覆写。
- 用户修改冻结事实时生成修订，保留旧版快照和已产成片。执行中的 Run 始终按自己固定的计划、提示词、素材版本与执行图走，禁止被编辑中的草稿改变。
- 事务与提交边界：原文导入可保存草稿；**正式确认集镜计划**时原子保存计划和镜头关系，失败完整回滚；素材晋升及绑定带版本校验，网络重试幂等；提交 Job/Run 使用幂等键。

## 7. 第一阶段：人工分镜书

### 7.1 输入
支持上传/粘贴分镜文档，及无文件时直接编辑结构化集镜表。四阶文档解析可移植七阶 `agents.script.parse_document`、`source_spans.segment_document` 的成熟行为，但**在四阶存自己的来源记录**，不能把文档注册成七阶 `ProjectDocument.current_document_id` 剧本来源。

### 7.2 解析器：一个输入适配器
- 优先确定性识别清晰的 `第X集/第Y镜/时长/人物/场景/道具`，只对非结构化或含歧义区域使用四阶镜像的 LLM 调用能力。无 LLM 时仍允许手工编辑并冻结。
- 使用用户项目已配置的 LLM 接入信息时，不通过七阶文学任务/七阶 Agent gateway 业务链；四阶只读平台允许的模型连接配置或使用独立镜像配置，密钥不得复制到日志。
- 分段保留 `source_document_sha256`、字符偏移、原文片段与抽取结果；跨片合并按集镜用户编号而非假定字符顺序可替代镜头编号。
- 五类输出：**集与镜头顺序、目标秒数、人物/形象、场景/道具、歧义与缺项**。不生成剧情、分镜新镜头、摄影风格、H3 提示词或 Agent 评审。
- 缺时长/镜号、模糊人物、重复镜头只提示用户处理；不得默默猜测镜头时长、增删镜头或改写用户输入。
- 同名角色多形象可标明变体，跨镜追踪人/场景/道具实体；不以 AI 归并自动替换用户命名。

### 7.3 冻结与约束
- 用户在一张简单表格复核并修订后点「确认并冻结分镜计划」。
- **唯一冻结事实**：`storyboard_revision_id`、`source_hash`、`episode_id -> ordered shot_ids`、`shot_id -> target_seconds`、`requested_assets`、用户确认人/时间、整体摘要哈希。
- 镜长遵守当前 H3 真实约束（仓库基线 `ShotSpec` 4–15s）及用户可配置最大镜长；严禁把 10 秒或 8 秒硬编码为四阶统一上限。
- 总集长为其目标镜长之和；如用户另给集长目标，显示偏差并请用户确认；不能自动通过截镜改变其镜长。
- 分镜确认之后才创建四阶正式 `ShotSpec` 镜像与分集合同；不要求冻结导演风格、生成大纲或五 Agent 落镜凭证。
- 修改已冻结镜长应产生计划新版本，并标记关联人工提示词待重新确认；未变更镜头及成功成片的历史不失效、不重拍。

## 8. 第二阶段：素材生成

- 以**第一阶段已冻结分镜中的 `requested_assets`、人物、镜头画面事实**为唯一需求来源，按（人物/场景/道具、实体身份、形象变体、涉及镜头）归并，不读取七阶剧本/大纲。
- 镜像七阶素材中心所需能力：检索候选、文生图/图生图/局部改图/多图合成（仅已验证的现有工作流）、上传、技术检测、授权校验、晋升/批准/锁定、镜头引用绑定。未在源项目证实的能力不得假称已可用。
- 每条素材需求显示 `missing | candidate | promoted | bound` 等事实；是否「可拍」由四阶**唯一镜头投产裁决**读取绑定与真实 Ref2VA 工作流要求决定，不在素材页面单独编第二套规则。
- 每镜至少一个合法 Ref2VA 参考；点名人物的镜头须具备符合实际工作流槽位与主体身份规则的参考素材；用户只上传未晋升不能视为正式绑定。
- 对原分镜没提出的场景/人物参考需求，系统可标记**实现 Ref2VA 必需的技术缺口**，仅提示补齐，不能编造用户剧情细节。
- 保持「需求 -> 生成或复用 -> 晋升 -> 绑定 -> 复核」单通路；探测到现成合法素材后不要反复要求用户“手动登记”。

## 9. 第三阶段：排片生产

- UI 按集折叠镜头卡片，一镜一个 H3 原文编辑器；支持粘贴/导入文本、保存草稿、冻结版本、预览最终提交原文、单镜/本集/全片排队。
- **H3 原文权威**：`prompt_sha256`、`prompt_revision`、`shot_revision`、`reference_manifest_sha256`、`target_seconds`、`generation_mode` 固定到执行快照；若任一影响提示词有效性的事实改变，明确提示失效并要求用户重新确认。**严禁静默使用编译器文本替代手写提示词**。
- 用户 H3 原文不再由 LLM 翻译、润色、补镜或套导演风格模板；语法/引用标签等只能按已验证的 H3 规范给出不阻断建议，真正不支持的执行模式/引用缺失按统一裁决拒绝。
- 画幅（如 16:9/9:16）、输出分辨率、模型量化版本、加速/高清 LoRA、二采/RelayVSR X2 等仅暴露当前镜像工作流**真实实现且已校验**的选项；用四阶镜像策略/参数映射实现，不直接改七阶动态工作流适配器。
- 画幅/分辨率 V1 以排片批次/整部作品为默认统一事实，允许按集覆盖需明确是否已有成片支持；避免同一集混用尺寸导致成片阻滞。分辨率须满足模型/工作流支持和参数实际落位要求。
- 每镜秒数**只来自第一阶段当前确认版本**；在此页只显示只读。更改镜长返回①并生成新的计划修订。
- **镜间 CUT**：`cut` 指无需上一 H3 段参考；`last_frame` 指以上段真实末帧作软连续参考；`hard_frame_anchor` 只在镜像工作流已通过能力测试时开放。与 H3 段**镜内 CUT**（由人工 H3 提示词自身描述）及第四阶段素材之间实际编辑转场是不同概念，UI 必须明确区分。延续上一镜不承诺绝对无缝。
- V1 真实模式 Ref2VA，不为纯文本 T2VA 偷开新路径；用户提示词中的图/音/视频引用需与有效 `reference_manifest` 对齐，实际 N 图/N 音/N 视频仍按镜像工作流实际能力组装。
- 每镜支持预览提交快照：时长、素材映射、模型/工作流及 H3 原文哈希。真实提交前必须判断机器就绪、任务幂等、人工提示词有效性、可用槽位和资源互斥；这些是同一个四阶裁决器的事实，不另做 UI 专属裁决。
- **内部执行快照**：一键「确认排片并开拍」由四阶系统创建 `M4ExecutionSnapshot`，等价于所需的冻结生产合同，但**不创建七阶 `DirectorPackageVersion`**，用户无额外「导演包」阶段。
- **唯一执行者**：四阶 `M4ProductionRun/Worker`（单份），自身队列、断点/幂等/重拍状态；通过四阶独立的 H3/Comfy 镜像适配器执行。禁止触发七阶 Run、镜头 Job 或其队列。
- GPU 系统级锁由平台提供；租约失败显示具体另一生产线任务、释放条件和唯一后续操作。四阶不得启动第二个自己的 Renderer 来绕开锁。
- 产物记录实际输出时长、原视频 SHA-256、尝试次数、工作流/模型快照、质检结果。用户目标秒数与视频实测秒数区分管理，超差以项目规则提示，禁止静默截掉关键画面。

## 10. 第四阶段：产出成片

- 镜像七阶稳定的交付实现：按集从**本次四阶 Run 的已通过真实 Job**选择产物（可选二采/超分的已通过最终版本），生成有序 EDL，FFprobe 校验真实时长，FFmpeg 装配，字幕及验收能力按现有真实可用范围移植。
- 严格按第一阶段的顺序拼接。默认段间是编辑 CUT；如需溶解等转场，须先证明四阶镜像装配支持后另行扩展，V1 不假设 H3 延续镜就自然无缝拼接。
- 逐镜重拍/替换不覆盖旧文件，重拍后只更新当前选用镜头事实；重生成交付产物新修订，可回看历史版本。
- 未通过真实质检、来源 SHA 不匹配、少镜、素材缺失的集不能冒充完成；错误提示到镜头/产物，沿用单一四阶就绪裁决。
- 支持一集一成片、批量多集、单集预览与导出；不要自动声称高画质超分已经成功，必须读取真实产物。

## 11. 四阶唯一状态裁决与阶段投影

四阶 `M4ReadinessVerdict` 为各个阶段、Run 前检查和前端 UI 的**唯一判定来源**；其输入来自四阶不可变快照、镜头、素材、H3 提示词、工作流能力和运行证据。

| 阶段 | 完成事实 | 缺口归属 |
|---|---|---|
| ① 人工分镜书 | `confirmed_storyboard_revision`，含至少1集1镜、每镜合法秒数 | 定位集/镜/原文 |
| ② 素材生成 | 已确认需求中真正必需的素材已晋升/绑定；Refs 模式满足真实工作流 | 定位素材/镜头 |
| ③ 排片生产 | 每镜有有效冻结的人工 H3 原文，执行快照可用；Run 有真实生成状态 | 定位提示词/工作流/Job |
| ④ 产出成片 | 本次 Run 全部要求镜头真实通过，已产出实际媒体，验收结果可查 | 定位集/产物 |

- 「状态投影」只汇总裁决器及执行器事实，不拥有新的合法性判定。
- 解析失败只影响①；素材任务失败不篡改①的冻结；镜头重拍不重新创建①计划；交付异常不推翻已通过的镜头。
- 所有阶段在刷新、重启后从数据库/任务凭证还原，禁止依赖前端本地布尔值显示完成。
- 事件日志有项目、生产线、阶段、集镜、任务关联 ID，支持 AI 管家读取四阶日志，但不得通过七阶业务操作接口修复四阶。

## 12. ComfyUI 与系统资源隔离

1. **四阶独立受管 ComfyUI 实例**，专用监听端口、队列、进程 PID 身份、工作流目录、节点环境和日志；七阶现有实例/端口/受管控制不变。绝不能把两套 Comfy 进程误识别为同一 PID 或互相停止。
2. 已安装 H3 权重和可复用的公共模型文件可在显式配置中按哈希**只读共享**，默认不自动复制数十 GB 大模型；模型下载与节点安装分别写入两条线自己的受管环境，绝不修改另一条线的节点版本。
3. 启动器持有**机器级 GPU 租约协调**。采用跨进程真实原子锁（OS mutex/文件锁+可靠 PID/实例 token 关联），不是“检查一个 JSON 再写入”式竞态；异常退出时确认旧进程已消失后才能解除占用。将启动权、停止权、租约释放权限定于持有者。
4. 推荐第一版对单显卡实行**生产任务互斥**，另一线仍可浏览、编辑、读素材/预览已存在文件；只有需要 GPU 的生产过程排队/提示占用。不允许在已有 GPU 作业内强制结束另一生产线任务。
5. 启动器与基础配置最小只增加四阶实例与资源锁的只读/授权管理，不建立第二套环境检查入口。四阶自己的就绪事实只由自己唯一的 Comfy 适配器提供。
6. 本地机器资源和驱动依然是公共故障域：不要宣称双线物理完全无关；通过互斥、独立日志/配置、可回退来降低交叉影响。

### P4：用户 H3 提示词与批量拍摄

### P5：成片镜像与收尾
- 四阶 EDl/FFmpeg/QC/单集成片/交付验收/返工，阶段概览/日志。
- 验收：不少镜、不串镜、不跨线使用旧产物；真视频哈希/时间准确；退出重启继续；七阶全流程无回归。

## 16. 测试方案与不可妥协的验收门槛

### 16.1 七阶零回归门槛
- 原七阶 UI、项目、创意、分镜、素材、导演包、H3 生产、后期成片链路合同/用例全通过；无有意修改七阶业务代码。
- 与基线对比七阶文件 diff、数据库 schema 和数据；旧项目打开、恢复、真实投产行为一致。
- 本地执行已存在的后端分片测试、前端 TypeScript/build/单测、Ruff，并按项目实际 runner 脚本确认（原 main 曾报告 8 分片/前端 87 文件 451 例，数字仅基线，不保证本地最新值）。
- 项目列表访问 7 类项目无需任何四阶服务就绪；关闭四阶/四阶崩溃时七阶正常使用。

### 16.2 四阶主要用户路径
- 新建四阶项目 → 选择 → 导入/粘贴用户分镜 → 精准读取集镜时长/素材 → 人工编辑冻结 → 图片生成或上传/晋升/绑定 → 逐镜手写 H3 提示词 → 选择画幅/分辨率/连续性 → 真实 MiniMax-H3/ComfyUI 批量跑镜 → 真媒体质检 → FFmpeg 成片交付。
- 覆盖 1 集 1 镜、2 集多镜、长文本切片、同人物多形象、缺时长、无 LLM、素材缺失、错误参考标签、失败重试、停止恢复、手动替换产物。
- 对每镜验证计划秒数、提交参考素材清单、模型/工作流版本、人工原文 SHA-256、实际媒体时长、成片顺序。
- 生成中修订①计划/②素材/③提示词不得静默改变既有 Run；新版本需明确重新生产。
- 同一次提交重复点击/网络重试不导致重复跑镜，任务重启回放不丢镜、不重投未知结果。
- 四阶镜像崩溃/重启不改变七阶状态；两线同时争 GPU 时只有一条实际拿到生产租约，另一条有清晰等待提示；错误停止指令不能结束另一条的 ComfyUI。
- 四阶及七阶各自进行真实单镜和多镜 smoke（条件允许）；七阶完整流程回归必须执行。

### 16.3 隔离专项检测
- 自动静态扫描 `manual4` import 依赖，拒绝七阶业务 Service 直接引用。
- 七阶业务文件差异零；平台壳改动逐行说明。四阶无法直接查询/修改七阶业务数据库对象（负向测试）。
- 两条线的文件目录、数据库连接串、Worker 身份、ComfyUI API 地址、工作流/节点配置及日志绝不误指向对方。
- 模型文件共享只读，有内容 SHA 校验；四阶安装/更新节点不覆盖七阶。
- 失败定位和修复动作唯一，不存在多个地方各自“说环境不就绪”的分叉结论。
