# Shine视频工作台 V1.1 需求修订：影视专业 Agent 团队与 MiniMax-H3 官方规范中心

- **状态**：用户提出的正式产品需求；方案已提交独立功能分支，尚未实现/合并
- **基线**：V1.0 项目书 + M1/M2/M3 离线收口代码 `e54e35eb2ed188f9c1812aa4e51da4454fa4ccf6`
- **目标平台**：Windows 本地 Web；独立 Agent Runtime；本地 MiniMax-H3 经 ComfyUI
- **优先级**：P0 = 约束、安全、官方标准与核心工种接口；P1 = 多角色协作、可视化、剪辑决策；P2 = 后期专业扩展
- **范围边界**：此修订不要求立即实测 H3 GPU、不替换唯一视频生成模型、不增加 AI 主资产生成路径
- **修订日期**：2026-10-21

## 1. 用户需求与不可破坏的基线

Shine 的可配置内嵌 LLM 必须驱动**具备影视工业职责分工的功能化 Agent**。首批至少包含：**编剧、导演、摄影指导（摄影师）、剪辑师**。协同角色应包含制片统筹/调度、场记/连续性监督、声音导演及独立质量审核；非必要角色可先作为受控工作单元实现，不能为每个角色再造一套 Runtime 或数据库。

不变约束：
1. 影视风格必须经过用户预制作审批和 Style Bible 冻结才能执行生产；允许已批准的分场景变化，不允许 Agent 擅自改动。
2. 角色、服装、场景、道具、音色主资产只来自用户、由用户批准并锁定；Agent 只能提出绑定建议。
3. 正式视频生成始终使用**本地 MiniMax-H3**，不得切换其他视频模型或云视频服务。
4. 已有 SQLite Job/Attempt/Artifact/QC/Repair 系统是唯一状态权威；调用共享 LLM Gateway，支持不同模型的按角色路由，Codex/Claude Code 不是运行时。
5. Agent 的结构化产物必须校验后方可进入下一阶段，外部规范不能替代用户授权。
6. 无真实 H3 工作流的离线开发仅能声明 TESTED_OFFLINE 或 MOCK_VERIFIED。

## 2. 四个必备专业 Agent 的权限与产物

| 工种 | 输入 | 职责和严格输出 | 权限边界 |
| --- | --- | --- | --- |
| **编剧 ScriptwriterAgent** | 用户剧本、项目圣经、锁定事实、人物关系 | `ScriptBreakdown`、`SceneBeat`、`DialoguePlan`：冲突目标、故事节拍、中文普通话对白、角色、时序与可拍摄性 | 不能改用户锁定情节、擅造角色资产、直接生成 H3 最终 Prompt |
| **导演 DirectorAgent** | 经校验的剧本、全片/场景风格、资产清单、官方 H3 能力表 | `DirectorialPlan`、`ShotIntent`：场面调度、人物关系、画面焦点、镜头覆盖、节奏与情绪转折 | 不能冻结风格、越权改剧本/素材、提交 ComfyUI |
| **摄影指导 CinematographerAgent** | `ShotIntent`、冻结风格、现有角色/场景参照、H3 真实能力清单 | `CameraPlan`：景别、机位、焦段语义、光源方向、构图、运动、动作轴线、起止帧策略，须可转为 H3 描述 | 不能凭空声称 H3 支持未验的节点参数、不得覆盖原定妆样貌 |
| **剪辑师 EditorAgent** | 合格镜头版本、场景节奏策略、连续性记录、声音/字幕状态 | `EditDecisionList`（EDL/JSON）：镜头顺序、入出点、CUT/接续、J/L cut（可选）、转场原因、节奏检查与时长预算 | 不能改已锁剧情事实；不能直接将未通过的真实镜头列入最终合格成片；音画处理采用受控 FFmpeg/后期模块而非替代视频模型 |

建议协同功能：
- **制片统筹 ProducerOrchestrator**：依赖排产、预算/时长/GPU 队列、阶段门禁、任务重试；调用现有 Job Orchestrator，不新增独立队列。
- **场记 ContinuitySupervisor**：人物身份/服装/道具/空间轴线/参考图污染、上镜与离场、同场续接检查；输出 `ContinuityReport`。
- **声音导演 SoundDirector**：对白、角色音色、声画时码、声场提示；输出 `SoundPlan`，声线资产必须用户批准。
- **独立审片 QualityReviewer**：检验脚本/风格/官方规则/技术媒体/语义证据，生成已有 `QCReport`；原则上不由产出者自行给出最终通过结论。

四位首要工种应能通过**同一个内嵌 LLM 配置**工作，也可由用户为每个角色配置不同 provider/profile/model；无需四份独立 API Key。各角色是被确定性工作流驱动的受控专业能力，不是自由聊天机器人。

## 3. 官方 MiniMax-H3 规范中心：H3 Official Knowledge & Rules

### 3.1 唯一权威源

- 官方仓库：https://github.com/MiniMax-AI/MiniMax-H3
- 便携式技能：`skills/h3-prompt-writing/SKILL.md`
- 基础/关键帧指导：`skills/h3-prompt-writing/references/base-en.txt`
- Ref2VA 全参考指导：`skills/h3-prompt-writing/references/ref-en.txt`
- 官方 README、模型/媒体约束说明与本地生成/工作流介绍。对其他非便携的 MiniMax Hub 技能，默认仅显示为背景资料，不视为 Shine 可调用工具。

已有 `H3PromptCompiler` 固定规则版本和摘要，是本模块的基础而非需要重写。官方规则更新须经测试、差异报告和**人工批准**；生产中的项目继续沿用其原先冻结的规则包版本。

### 3.2 内嵌方式、来源追溯与许可证门禁

建设 `H3RulebookRegistry`，区分以下材料：
- `source_docs`：可合法分发/本地缓存的官方原始资料，带原始路径、URL、Git commit、blob SHA、内容 SHA-256、抓取时间、许可证/来源标记。
- `machine_rules`：自行撰写的机器可执行规则（字段顺序、标签、模式约束、时码、媒体能力、参考时长等），每条关联源文件和规则来源段落。
- `agent_guidance`：以来源片段定位的能力说明/术语表/示例；只检索给相关工种，不把全文永久塞入每个 Agent 的系统提示词。
- `local_workflow_capabilities`：从用户导出的实际 ComfyUI API Workflow JSON 与 `/object_info` 得到的节点/参数真值，未验证时显示 `PENDING_LOCAL_H3`。

**许可要求：** 官方 GitHub 源码根目录未发现明确通用 LICENSE 时，不能凭“公开可读”推定可以把完整官方说明原文无条件复制进 Shine 可分发代码包。优先在用户授权的本机按官方 URL/固定 commit 获取并缓存、标记来源/权利条件；在明确取得许可或复用条件后才考虑再分发内置原文。首次离线启动应可加载先前合法获得的已验签缓存；未缓存则明确标记规范不可用，不能悄悄用过期/虚构规则兜底。版权未确认前，仓库仅保存**Shine 自编规则和官方引用链接/摘要元数据**。

UI 新增「H3 官方规范中心」：规则包版本、来源/校验值、五种模式说明、资产参考限制、示例、差异、违规清单、一键重新校验。将“官方明确要求”“Shine 产品自定义规则”“H3 Workflow 本机实测能力”标为三个不同的来源层级，禁止混写。

### 3.3 H3 官方格式不可被专业 Agent 绕过

- 识别 T2VA、I2VA、FL2VA、L2VA、Ref2VA 五种模式；不得把 H3 Prompt 生成与拍摄创意混淆。
- Base/关键帧模式要求 `integrated_multimodal_description` → `overall_soundscape` → `non_diegetic_music`；首尾帧模式遵循对应时码与图片对齐要求。
- Ref2VA 要求依次输出 `subject_definitions` → `summary` → `retention_analysis` → `detailed_description` → `overall_soundscape` → `non_diegetic_music`。
- 官方要求描述性部分按英文规范写；中文普通话对白、歌词、画面中文字保留原语言及规定的对白标签；不得把用户要求的中文对白翻译成英文。
- 每镜写清构图、人物相对位置、动作状态变化、环境光、摄影运动与声音，不能把故事梗概冒充可执行镜头描述。
- 验证 4–15 秒等模型能力范围；参考图/视频/音频的模式、数量、总量、时长及槽位约束由规则包与本地工作流双重检查。预设的通用 H3 规范不意味着特定 INT8 ComfyUI 节点已支持全部模式。
- 全局素材 ID 和 `<Picture N>`/`<Subject N>`/`<Video N>`/`<Audio N>` 分开；任务级独立 Label Manifest，全部标签可解析到已批准资产 SHA-256。
- 最终 Prompt **仅能**由单一 `H3PromptCompiler` 产生；角色 Agent 只提交符合 Typed Contract 的计划/指令。

## 4. 协作编排与人工审批门禁

```text
项目书/剧本/人工资产
  → 编剧 Agent: ScriptBreakdown / DialoguePlan
  → 导演 + 摄影 + 剪辑: 影视风格预制方案（建议，不得自行冻结）
  → [USER] Style Bible 审核/冻结
  → 编剧 Agent: 冻结事实的分场/对白表
  → 导演 Agent: DirectorialPlan / ShotIntent
  → 摄影 Agent: CameraPlan / Lighting / H3 可执行镜头规划
  → 场记: 人物、服装、轴线、续接、资产一致性
  → 声音导演: SoundPlan / 对白/音色/时码
  → 规范中心: H3 标准检索 + 确定性 Preflight Rules
  → H3PromptCompiler: 唯一最终 Prompt / 引用表 / 规则版本哈希
  → Job Orchestrator → 本地 ComfyUI + H3
  → 技术 QC + 场记/导演/摄影/声音独立审查
  → 不合格: RepairPlan（仅允许修改指定工种可修改字段）
  → 合格: 剪辑师 EditDecisionList → FFmpeg 后期/交付
```

角色出现冲突时：
1. **H3 官方硬约束、真实本机 Workflow 能力**不能被 Agent 讨论投票绕过；
2. 用户锁定剧情、风格和人工素材审批也不能被绕过；
3. 如 H3 能力与用户锁定要求冲突：停止该镜头并提交用户决策，不允许 Agent 静默降级；
4. 可以在已批准场景变化范围内协商摄影调度、剪辑节奏和非关键声画安排；
5. 上游产物变更触发依赖失效，保留历史版本，不污染独立镜头；
6. 用户拥有最终创作决策权，系统自动通过只能是有充分证据的生产状态，而非美学最终裁决。

## 5. 独立 Agent Runtime 技术契约

不新建独立多代理数据库/执行队列；在原有 `ProducerAgentRuntime`、`LLMGateway`、`JobOrchestrator` 上做增量：
- `FilmAgentRegistry`：角色、能力、版本、输入/输出 schema、工具 allowlist、required_rule_sections。
- `FilmAgentDispatcher`：按任务阶段选角色，使用现有 model routing；模型输出先 Pydantic 校验再存为 revisioned artifact。
- `AgentTaskRecord`：project_id, role_id, input_hash, style_version_id, asset_manifest_hash, rulepack_id/hash, model_profile_id, model_id, schema_version, attempt_id, status, error_code。
- `AgentArtifact`：kind, schema_version, payload_json, sha256, producer_role, source_task_id, input_revision_ids, approved_by, approved_at。
- `RulePack`：source_repo, source_commit, source_files[], source_sha256[], local_cache_status, license_review_status, derived_rules_version, approved_at, frozen_at。
- `RuleViolation`：rule_id, origin(`OFFICIAL_H3`|`SHINE_POLICY`|`LOCAL_WORKFLOW`), severity, source_path/locator, affected_field, evidence, remediation, rulepack_id。
- `AgentRunTrace`：LLM 路由、Token/延时、输入输出摘要、schema 验证、工具调用授权、关联 Job；不得在日志或报告中暴露 API 密钥/隐私媒体绝对路径。

典型 typed artifact 最低要求：`ScriptBreakdown`、`DirectorialPlan`、`CameraPlan`、`ContinuityReport`、`SoundPlan`、`ShotSpec`、`EditDecisionList`、`RuleValidationReport`。其中 `ShotSpec` 继续使用现有契约，只做兼容迁移。

所有专业 Agent 的系统模板包含：专业工种职责、审批与能力边界、项目故事事实、冻结风格、实际批准资产清单、适用的 H3 规则包片段与输出 JSON Schema。技能/规范中心以版本化检索插入最相关章节，不得依赖模型自称记得官方文档。

## 6. UI 最小落地

- 「影视制片团队」页：编剧/导演/摄影/剪辑（至少四个角色），当前模型、权限、最近任务、JSON 产物、审查状态。
- 「项目工作流」：阶段卡与依赖关系，展示角色交接、风格门禁、生产阻滞及返工来源。
- 「H3 官方规范中心」：来源版本、规则差异、引用查验、规则与本机能力分类；一键校验镜头/提示词/参考映射。
- 「风格预制中心」：编剧/导演/摄影/剪辑在冻结前协作提出建议，**只有用户**能点击冻结。
- 「剪辑决策」：EDL/时间线 JSON 预览、镜头版本和声轨/时长检查，先保证离线数据契约，再推进 M4 FFmpeg 合成。

## 7. 离线开发、测试与验收

**V1.1 第一轮不需真实 H3 GPU。** 在当前通过 174 项的 CI 基线之上新增专项测试：

1. 四个角色分别输出符合各自 schema 的结构化产物；错误角色/越权 Tool 被拒绝。
2. 四角色可复用同一 LLM profile，也可分配不同模型；断线、超时、畸形 JSON、恶意输入被安全处理。
3. 脚本锁定事实、人工资产审批、Style Bible 冻结门禁不可被任何角色覆盖。
4. 官方 RulePack 可读取、验证哈希/版本、离线缓存；变更时生成差异，并经人工批准后方可进入新任务；旧项目仍可复现原规则。
5. 基础/Ref2VA 的严格字段顺序、英文结构/中文对白、镜头时码、资源标签、槽位/类型/数量/时长检查；每条拒绝输出 `RuleViolation`，指向规则和来源。
6. 违反 H3 官方标准的专业 Agent 输出不能提交 ComfyUI；不得用“模型觉得没问题”覆盖确定性预检。
7. 编剧→导演→摄影→场记→H3 Compiler→Fake ComfyUI→QC→剪辑 EDL 的完整 E2E，包含一次镜头返工与依赖失效。
8. Agent 生成内容的 Prompt Injection、无授权的远程模型发送隐私参考、被篡改的官方缓存、未知许可状态及无缓存离线启动路径均必须有明确处理。
9. 新增 Alembic 迁移及旧项目升级回归测试；CI Ubuntu + Windows 后端与前端构建必须通过。
10. Mock 和真实 H3 的状态仍明确分开，未实测节点参数一律 PENDING_LOCAL_H3。

验收门禁：官方规范中心、四核心工种、角色权限、确定性官方规则校验、阶段交接、Style Bible 审批、相关数据版本和 Fake ComfyUI E2E 全部通过，才可声明 **V1.1 NON_GPU_ACCEPTED**。真实 H3 人物、中文发声、参考资产传输及摄影/剪辑成片质量仍留待真机验证。

## 8. 分期实施

- **V1.1-A**：规则包来源/许可核查、缓存/哈希/版本、规则检索、机器可执行 Validator；接通现有 H3PromptCompiler。
- **V1.1-B**：四个核心 FilmAgent 的 typed schema、角色路由/权限控制和交接工作流；复用现有 LLM/Worker/DB。
- **V1.1-C**：StyleLab 协作、场记/声音/QC 接口、剪辑 EDL、跨角色冲突/返工规则和 UI。
- **V1.1-D**：Fake ComfyUI E2E、Windows CI、回归测试、迁移审查、验收报告。
- **V1.1-E（之后）**：真实本地 H3 节点/API Workflow 映射和小规模镜头实测；不纳入 V1.1 离线完成定义。
