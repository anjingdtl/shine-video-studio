# V1 / V2 用户操作成本对比（2026-11-13）

> 同一部原创短剧（6 场 · 6 集 · 每集 1 场）、同一台机器、同一套 Ref2VA 方案。
> **V1 数字来自第一轮方案与代码结构推算（入口数量与确认点可对照代码核实）；V2 数字来自本轮真机穿测的实际点击记录。**
> 不把「自动批准风险动作」算作节省。

## 1. 入口数量（结构性重复）

| 阶段 | V1 可同时点到的业务入口 | V2 | 变化 |
| --- | --- | --- | --- |
| ① 创意与剧本 | 2（ScriptEntryPanel + FourStagePanel 折叠） | 1（ScriptEntry；四阶段移入专业模式） | −1 |
| ② 剧本统筹 | 2（分镜书 + 旧 `episode-plans` 生成分集草案） | 1（分镜书） | −1 |
| ③ 镜头拆解 | 2（EpisodeStoryboardPanel + StoryboardPanel 折叠） | 1（按集镜头表） | −1 |
| ④ 素材准备 | 3（ShotMaterialsPanel + MaterialPreparationPanel + AssetPanel） | 1（需求清单 + 素材中心入口） | −2 |
| ⑤ 导演包 | 2（导演包面板 + 分集方案段落） | 1（拍摄范围 + 唯一开拍按钮） | −1 |
| ⑥ 视频生产 | 3（Run 面板 + ProductionSeriesPanel + 单镜高级） | 1（真实拍摄进度） | −2 |
| ⑦ 后期成片 | 2（成片卡 + 独立交付面板并列） | 2（审片卡 + 文件/历史导出，职责分开） | 0 |
| 页面容器 | ③④同页双折叠；项目管理嵌在旅程内 | ③④各自独立页；项目管理独立模块 | — |

**重复入口合计：V1 16 个 → V2 9 个（−7）。**

## 2. 完成「两集短剧到第 1 集成片」的必需点击（实测）

| 步骤 | V2 实际动作 | 次数 |
| --- | --- | --- |
| 新建作品 | 输入名称 + 创建（建后自动进入①） | 2 |
| ① 输入故事 | 填想法 + 锁定事实 + 保存简报 | 3 |
| ① 确认与生成 | 确认简报 + 生成剧本 | 2 |
| ① 授权与大纲 | 允许远端文本发送 + 后台提取并归并大纲 | 2 |
| ① 编辑 | 改大纲正文 + 保存为新版本 + 确认大纲 | 3 |
| ② 分镜书 | 填四参数 + 生成 + 确认 | 3 |
| ③ 分镜 | 生成 + 确认第 1 集 | 2 |
| ③ 修复（真实发生） | 重试第 1 集（规则包缺陷修复后） | 1 |
| ④ 素材 | 生成清单 + 2 项决策 + 确认 | 4 |
| ⑤ 开拍 | 勾选集（默认已选）+ 选方案 + 开拍 | 2 |
| ⑦ 审片 | 打开成片 + 播放 | 2 |
| **合计** | | **26** |

V1 同等目标的必需点击（按第一轮结构推算）：因①③④⑥各多一次入口选择/二次确认、⑤需「生成导演包 → 确认 → 启动整部作品生产」三步、⑥需在排产面板再次确认范围，**约 34–38 次**。

### 2.1 第二集（在第 1 集已交付之后单独开拍，实测）

| 步骤 | V2 实际动作 | 次数 |
| --- | --- | --- |
| ③ 分镜 | 生成 + 确认第 2 集 | 2 |
| ④ 素材 | 重新派生清单 + 确认（必需项已匹配主素材） | 2 |
| ⑤ 开拍 | 直接点主按钮（默认只勾第 2 集，第 1 集不被顺带重拍） | 1 |
| ⑦ 审片 | 打开成片 + 播放第 2 集 | 2 |
| **合计** | | **7** |

关键点：**第 2 集只需要 7 次点击，且第 1 集的 Job / Artifact / 成片 SHA 全程未变**。V1 结构下续拍必须重建整包、重新走「生成包 → 确认 → 启动」，并把已出片的集一起纳入范围（或手工排除），续拍成本与首拍同高。

> 说明：①若使用「上传剧本」入口可省去「生成剧本」与大纲归并两步（V1/V2 皆然）；本轮因内置浏览器不支持文件选择器而走文本入口，故 V1/V2 在这一段可比。

## 3. 必须由人做出的业务确认

| 决策 | V1 | V2 |
| --- | --- | --- |
| 大纲确认 | 1 | 1 |
| 分集 + 风格确认 | 1 | 1（成对一次） |
| 镜头确认（按集） | 1/集 | 1/集 |
| 素材决策 | 每项一次 + 一次总确认 | 每项一次 + 一次总确认（可单项立即执行） |
| 素材采用（AI 候选） | 采用 + 回绑两次动作 | 采用 + 回绑合并为一次（本轮因显存未实测） |
| 真实开拍授权 | 生成包 → 确认 → 启动（3 次） | 1 次复合动作 |
| 成片接受 | 1 | 1 |

**风险类确认没有被自动化吞掉**：远端文本授权、素材采用、真实 GPU 开拍、最终艺术认可仍然逐项由人触发。

## 4. 跨页面回跳与工程字段处理

| 项 | V1 | V2 |
| --- | --- | --- |
| 因「缺图 H3 自行生成」误判导致的返工 | 存在（文案承诺错误） | 0（文案与门禁一致） |
| 因 `FREEZE_PROJECT_RULEPACK_FIRST` 卡死 | 存在（无 UI 入口） | 0（自动钉规则包） |
| 素材提交重复出图（断连重试） | 可能（`Date.now` 键） | 0（确定性请求身份 + 回执） |
| 需要手改数据库/手工调 API 才能继续 | 有（规则包、素材清单） | 本轮 0 次关键阻塞（素材上传用同一后端合同完成） |
| 每集独立推进 | 需整包就绪 | 单集可打包/开拍，未就绪集不阻塞 |
| 续拍时误把已交付的集一起重拍 | 结构上容易发生 | 0（默认不勾已交付集；重拍需手勾并显示「勾选即重拍这一集」） |
| 续拍后找不到上一集成片 | — | 0（逐集成片跨运行列出，与"当前这次运行"无关） |

## 5. 时长（实测，单机 16 GB）

| 阶段 | 实测耗时 |
| --- | --- |
| ① 大纲（含分块 + 合并 + 两次重试） | ≈ 12 分钟 |
| ② 分镜书（本地派生） | < 10 秒 |
| ③ 单场分镜（五工种，含 2 次 LLM 格式纠错） | ≈ 8 分钟 |
| ④ 素材清单 + 决策 | ≈ 1 分钟 |
| ⑤ 开拍（建包 + 预检 + 启动） | ≈ 20 秒 |
| ⑥ 3 镜真实 H3 + QC + 装配 | ≈ 9 分钟（每镜 2–4 分钟） |
| ⑥ 第 2 集 1 镜真实 H3 + QC + 装配 | ≈ 9.5 分钟（含冷启动；单镜 07:42:15→07:51:49） |
| ⑦ 播放 | 即时 |

**结论**：V2 在入口数量（−7）和开拍步骤（3→1）上是确定的收敛；点击总数的下降主要来自「不再重复选择入口/不再二次确认范围」。真正决定用户能否出片的是模型稳定性与显存，而不是页面按钮数量。
