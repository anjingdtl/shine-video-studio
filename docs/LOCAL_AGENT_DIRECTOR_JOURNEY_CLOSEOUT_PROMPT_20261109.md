# 本地 Agent 收尾任务 · 导演模式全旅程

你负责在 Windows 本机完成 Shine Video Studio 导演模式收尾。用户旅程从发给新用户的 Windows ZIP 开始，经安装、依赖与模型下载或复用、素材中心审核与采用、剧本导入、统筹、镜头拆解、备料、导演包、后台拍摄，最终到逐集播放、下载及人工验收。交付实现、失败回归、证据和复验报告。真实资源缺失时先完成可执行的软件验证，为仍待执行的真机步骤保留具名阻塞和可继续的状态。

## 先建立一份权威身份链

在 PR 中用一张表写清每项身份的写入者、读取者、版本和重试约束。以当前领域服务和 SQLite 为核心，收束分叉判断。

| 领域 | 需要携带的身份 |
| --- | --- |
| 安装 | 安装实例和规范化根目录、catalog/variant revision、组件及长度/SHA-256、实际目标占用、计划快照、尝试、运行探测证据 |
| 剧本分镜 | 选定文档 ID/hash、已确认大纲和有序场次、普通分集或四阶段卷/场次/分集版本、逐单元 apply 回执、镜头 revision |
| 素材与风格 | 全局版本 ID/hash、项目分配回执、使用范围及现行权利、项目主素材、逐镜绑定 revision、StyleVersion 与 RulePack lock |
| 拍摄 | 导演包 ID/revision/digest、范围 ID、H3 profile revision/fingerprint、模型/映射、Run → Series → Job → Attempt、提交意图、GPU 租约、external prompt ID |
| 交付 | 同一范围内的合格 Artifact hash、技术 QC、选片、EDL 和 DeliveryOrder 版本、人工审核状态 |

同一 API 可返回不同维度的状态，例如「创作快照已确认」「环境可运行」「本包可开拍」「镜头技术完成」「集已装配」「人工已认可」。每个状态都由拥有该事实的服务计算，UI 按指定范围投影。失败时返回稳定错误码、受影响对象和可继续的动作。

## 实施顺序与验收

### A · 安装、下载与真实能力（U01、U02）

- 用服务端规范化的安装内容和物理目标建持久占用。将并发准入和排他写入放在同一原子边界。两个窗口、两个项目、丢回执及浏览器重启时，对相同计划应重接同一活跃尝试或返回唯一既有回执。不同内容触及同一根目录或运行实例时给出冲突身份。对于旧重复记录，按实物与台账对账后再恢复。
- 用同一部署组合驱动推荐、下载确认、执行和包元数据。H3 是正式视频能力，Qwen Image 是独立的可选素材生成能力，ASR/VLM、小模型与固定音色按对应能力单列。实际所选 variant、组件闭包、缓存已验证字节、待传输字节、目录与磁盘预算由服务端复核。默认采用现有合格多参考 Ref2VA。估算、资格、文件已校验、节点/运行态已验证、真实生成样本均显示各自证据。
- 保持双名同入口的 Windows 安装器、启动幂等、ASCII `.cmd` 与含中文 PowerShell 文件的 UTF-8 BOM。包摘要按 catalog 实际声明计算并定义统计口径。安装器、引导页与包清单共同验证存储根、数据根和服务身份。复用现有 ComfyUI 时先只读识别和校验，控制权以已记录 PID/birth、Job Object、端口及租约证据为准。
- 反例门禁覆盖重复/并发计划、只选 H3、开启图片能力、取消授权、断网、镜像回退、Range 被忽略、字节或磁盘变动、暂停和中途重启、配置或实例结果不确定、缓存错哈希以及外部端口占用。检查每步唯一尝试、持久进度、有效确认范围和实际执行组件。已有完整文件应复用，未知外部结果进入对账。

### B · 普通与长文本入口统一到当前生产依据（U03、U04）

- 普通路径在第 1 阶段完成导入、选版本、文本发送授权、提纲、必要澄清与确认。在第 2 阶段按确认的场次分集并冻结风格。第 3 阶段按场次生成、复核并应用分镜。分集物化消费每个预期单元的 apply 回执，逐场具名标出缺失、失败、重复、过期和越界。第 5 阶段集中处理正式包确认。
- 普通剧本、创意简报产出的剧本、四阶段分卷均进入可验证的文档 lineage。导入 B 可将 B 留在候选状态，显式选用 B 才切换当前依据。包用已确认来源及逐单元回执计算身份。确认、读取、物化、冻结、Run 启动和派发重查同一依据。旧文档、镜头、卷和包继续按原 ID 访问。手工镜头以显式手工来源进入，禁止把最新上传冒充其来源。
- 浏览器需要从空作品只走普通主按钮即可完成上述顺序。四阶段保留长文本分卷、草案、精确包深链、分集合同、局部重做与逐场 UNKNOWN 对账。覆盖 R01–R09，尤其一授权最多新建一次、已应用场次不因另一场重做丢失、分片失败不能补成整卷完成、刷新后找得到原回执。
- 增加 A 已确认后上传 B、主动切换至 B、B 的大纲未确认、旧 A 版本链接、重做一场、旧标签页按 A 操作及服务在 apply 前后重启的反例。覆盖两套入口落到同一包与版本合同。早期导入后不得误要求用户去第 4 阶段完成第 1 阶段。

### C · 素材中心分配、逐镜采用与撤权（U05、U06）

- 分镜先形成可持久恢复的每镜角色、场景、道具等需求，保留稳定实体与来源。将旧「人物对照」保留为显式人工匹配能力。缺候选时允许分镜设计继续。素材区直接按需求打开全局搜索/导入，显示版本、审核、权利、项目与用途。
- 把「批准并分配某个全局版本」与「采用到这一组镜头」衔接起来。给出带现有镜头 revision 的采用预览，用户明确同意后由现有绑定服务应用到精确镜头并返回回执。可采用自动匹配建议和批量确认；同名歧义、跨项目、旧需求、旧镜头、已冻结包和已通过 Job 进入具名冲突或新版本。项目分配本身继续具备跨项目独立身份，已有绑定继续钉住原版本。
- 把现行使用权校验从仅覆盖计划项目的路径扩展到全部真实素材消费者。对每个已绑定的来源，检查全局版本及其派生来源链、项目、用途、撤销、有效期、mock/offline 标识、批准锁定与实际字节。计划项目保留额外的冻结检查。包和 Job 准入先拒绝，Worker 在上传参考和提交前复核。撤销发生在已提交后时保留历史收据并走对账。
- 回归覆盖项目 A/B 分配 V1、晋升 V2 后 A 的 V1 不漂移、分配后采用到指定镜头、重复采用、未审核候选、文件换字节、授权撤销与过期、降级用途、派生源失效、声音试听冻结、并发撤权和已排队窗口。每个负例查外部传输计数，拒绝路径应为零。用独立的图片、声音与 H3 能力结果判定，不复用同一证据等级。

### D · 导演包、编译合同与单一拍摄调度（U07、U08、U09）

- 提取或复用无副作用的共同准入，让导演包 readiness、连续制作、单镜头、Run 启动和批次派发共用 `H3PromptCompiler` 与工作流约束。静态不可能的情况在开拍前报镜头 ID、模式、缺失槽与去向。未来才能产生的前序连续性引用标记为依赖等待，并在拥有真实来源 Job 后精确核验。可保存创作快照与可启动真实 Run 是两维状态。
- 保持缺可选图可以设计与备料、固定音色可选、已绑定参考须全部可映射的既有合同。Ref2VA 零参考、指定角色主体缺位、映射或参数不足时给出可执行修复。默认多参考 Ref2VA。明确选择其他模式时按已验证的实际 profile 执行。所有对白语言、时间、标签、无对白禁声和七维冻结风格经原编译器输出。
- 统一冻结与比较完整执行身份。至少覆盖 workflow revision/graph/checkpoint/model/parameter map/media transfers、输出、项目语言、StyleVersion、RulePack、逐镜 spec/revision、引用的角色/槽/顺序/来源版本及 hash、制片计划和生产政策。校验根清单与子清单集合和顺序。已确认包遇不等价变化时阻断新 Run 与未提交批次，既有外部任务进入对账。使用标准参数 API 的真实变更测试验证旧包失效或历史冻结执行仍严格读原修订。
- 单镜 Job 创建消费明确的保存绑定和 revision。旧入口需要兼容写入时，通过显式且有审计的绑定动作形成新 revision，再入队。任务 API 的重放用稳定请求身份返回同一收据，冲突回 409。结合事务/唯一键/fence 为单镜、独立 Series 与 Run 批次统一预留，隔离合法的显式重拍和独立镜头。已存在未对账 UNKNOWN 时，旧请求不能靠变更入口、idempotency key 或计划版本开新尝试。对已确认未发送与人工明确授权的动作保留规定的状态转换与回执。
- 复用一个常驻 Worker、原 GPU 排他租约和拥有证明。外部调用前持久化提交意图、graph hash 和状态 fence，网络调用在 SQLite 写事务外，返回后立即固定 prompt ID。安全暂停、恢复、取消、撤权与生产版本变化进入原状态机。优先认领校验通过且 lineage 相符的持久 Artifact。无法证明释放条件时记录对账，已提交任务不得自动重发。图片、语音、H3 和不同 GPU 阶段共享排他合同。
- 必测双击、响应丢失、跨入口并发同镜、单镜头引用注入、宽高和 media transfer 原地改变、单镜失败与独立镜继续、Worker 在外呼前/后中止、旧 Worker 迟写、浏览器关闭、外部进程、租约丢失与连续拍摄回收。核验持久 ID、调用次数、prompt graph hash、状态 fence 和租约单次释放。

### E · 真实进度、选片、装配与交付（U10）

- 定义导演模式的当前范围选择。用显式 `package_id`、`run_id` 或待拍快照 ID 支撑 `/journey` 和每个生产/后期页面。当前范围以自己的确认、批次、有效产物和交付记录为依据。无匹配 Run 时显示等待开拍。无效深链给明确错误和可选历史列表。
- 生产完成只统计当前范围内可用的真实版本与 Artifact。历史镜头需要显式复用和校验。演示记录独立展示；`PASSED`、`DELIVERED`、`pending_review`、`accepted` 各按实际证据展示。技术 QC 失败阻断出片，ASR/VLM 等建议按既有 advisory 机制报告。每集 EDL 使用精确 Job/Artifact 及片段边界，技术装配、输出 SHA、文件播放、下载名和人的批准都有同源记录。
- 验证旧 Run 1/1、新计划 2/3、新版导演包、演示 Job 和另一 Run 同镜均不会点亮当前交付。验证指定旧包深链、范围切换、重连与异步返回顺序、跨项目错误 ID、分页最后一集、已有成片修订和新 EDL 交付版本。让历史旧集仍按原 ID 下载，后期改动复用已确认的视频并生成新交付版本。

## 分层验收和交接

### 软件门禁

1. U01–U10 每个至少一条反例先在相应基线重现，再在修复版断言正确。上游语义明确的既有用例继续通过。覆盖真实 FastAPI 路由、SQLite 并发和失败后状态，同时补 Chromium 浏览器测试。浏览器验收记录发出的实际 API 请求和阶段，使用合成输入、真实应用 UI、隔离 DB，外部服务可控注入。
2. 从仓库根跑后端定向和全量 pytest。至少包含安装器入口、安装持久化与新机/复用、素材中心与制片、四阶段回归、分镜、编译器、reference transfer、普通导演入口、Run/Series、handoff journal、advisory queue、交付及 `test_offline_e2e.py`。变动 crew 或 rulebook 时带 `test_film_crew.py`，相关 Worker/质量改动遵循 `AGENTS.md` 的全量和真实校准条件。全量需分片时记录无重叠文件清单、最终计数、退出码和合计。
3. 执行 `backend/.venv/Scripts/python.exe -m ruff check backend/shine backend/alembic backend/tests`，以及 `frontend/` 内的 `npm.cmd test -- --run`、`npm.cmd run build`。跑项目提供的浏览器脚本并修正过期定位，保留实质审批、素材与 Voice 流程断言。核对同提交的 Windows/Linux CI。
4. 在隔离环境验证空库和备份副本迁移、重复启动和 `alembic check`，记录单一 head。迁移给出前向兼容和恢复步骤。发包只用干净提交运行 `pwsh -NoProfile -File scripts/build_test_package.ps1 -OutDir <隔离新目录> -Verify`，核对 ZIP SHA-256、每文件 manifest、排除规则、入口编码、实际 catalog 统计。

### 真机门禁

1. **干净 Windows 与已有安装各一轮。** 干净宿主使用上述 ZIP，从一键入口建第一个作品，走完授权、非系统盘、依赖和模型实际下载、校验、断网续传、启动及复跑。已有安装只读核验并复用，检查没有冗余权重副本，原目录和外部进程保持用户归属。记录盘符可用空间、GPU/驱动、ComfyUI/节点/依赖和权重 pin，记录样例而非密钥或个人路径细节。
2. **真实 LLM 和素材。** 经用户当前授权的配置和合成短剧执行文档分析、分集、分镜。素材中心用授权的本机内容走导入、审核、晋升、分配、采用。已安装并获准的 Qwen Image 跑选定能力的真实样本，核验解码、尺寸、SHA 与回执。声音能力单列授权、试听、冻结和发布证据，语音可选路径也要验。缺能力则记录对应 `NOT_RUN` 或具名阻塞，上传素材路线可继续。
3. **真实 H3 全链。** 普通主线先拍最小多参考样片，逐镜核对已批准参考顺序、图/模型/映射、时长、尺寸和对白。再用一个短剧至少两集，每集多镜，含有对白、无对白及跨批次连续性。由 UI 发起一次 Run，关浏览器再恢复，Worker 自行完成后续批次。记录包、Run、Series、Job、Attempt、prompt ID、租约、每集 EDL、文件 SHA 和五门 QC。验证至少一集中文对白及无对白镜头的实际声音，VLM/ASR 结果按覆盖度分列。
4. **人验与耐久性。** 浏览器逐集播放、下载并复核参考身份、对白语言、连贯性与成片。人验由真实操作者提交，证据包含所看版本与结论。另在隔离测试覆盖至少 20 镜和多批次，记录重连、暂停、重启及恢复。合成压力结果和真实长时间 GPU 结果分别记账。对触发 `client_review_identity` 失效的文件修改，依 `AGENTS.md` 重新执行真实正负 VLM 校准、新 revision、弃用旧 revision 与重冻结计划，证据不足时维持对应历史状态。

## 最终交付

提交小步可审查的实现和回归，附复验报告。报告逐项列 U01–U10 的旧结果、新结果、入口、证据、兼容和迁移影响。单列 `SOFTWARE_VERIFIED`、`CLEAN_WINDOWS_INSTALL`、`REAL_DOWNLOAD`、`REAL_LLM`、`REAL_QWEN_IMAGE`、`REAL_VOICE`、`REAL_H3`、`VOLUME_DELIVERED` 与 `HUMAN_ACCEPTED`。每项填写实际执行的 SHA、命令、状态和证据位置。未执行的项写 `NOT_RUN` 或具名阻塞，并给出可继续的步骤和所需用户动作。

PR 只包含可公开的实现、测试和脱敏报告。用户剧本、媒体、权重、密钥、数据库、真机测试原始证据留在授权的本机目录。回滚保留旧版本与历史收据，运行中任务先安全结算或对账，迁移按验证过的备份恢复路径处理。给出测试包校验和、已知运行边界与最终验收判定。
