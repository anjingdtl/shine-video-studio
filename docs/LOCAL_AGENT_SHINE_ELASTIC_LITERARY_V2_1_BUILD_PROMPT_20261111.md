## 不得违反的红线
1. 不得建立五套五维 LLM 串行调用；合法空维度不阻断。不得把完整内部事实 schema 强迫 LLM 一次输出。
2. LLM 已完整返回的有效正文先持久化为候选草稿；非关键 JSON 错误不抹除成果。候选草稿不得自动成为权威事实、已批准剧本或正式分镜。
3. 任何硬阻断必须按具体依赖范围生效，并写 reason_code、affected_unit_ids、next_action；独立章节/场次可以继续。
4. 原文不静默截断、关键线索/伏笔不静默丢弃、对白有意重复不机械去重；所有来源跨度和哈希可追溯。
5. 保留 Provider pin、文本外传同意门禁、request_identity、lease_owner/state_version fence、SENDING/UNKNOWN 禁止盲重发、工件原子提交及 H3 生产准入。
6. SSE 收到部分字节不代表远端已停止；断流或租约过期的 external_outcome 仍可为 UNKNOWN。先对账，未经授权不再次 POST。
7. 模型 60% completion 硬上限保留：实际调用额度按任务可见输出、推理预留、协议开销动态确定；未知模型窗口不得伪装为 1M。
8. 全逻辑单元 Writer/Memory/QA/Repair 共用重试次数、Token 和成本上限；不出现无界验证—修复循环。
9. 不直接废弃 V1 未完成任务；新旧合同并存，灰度开关 off/shadow/on；shadow 不额外付费调用。
10. 普通 Web UI 继续保持四步简洁，不向小白暴露大量 JSON、原始调度状态或繁杂工程配置。

## 分阶段实施与验收
P0：真实失败分诊、四阶段 LLM 调用和阻断路径普查；建立唯一 INFO/WARNING、LOCAL_REVIEW、HARD_BLOCK 规则；添加干跑规划器；先修复不必要的硬阻断并形成基线报告。
P1：统一 Call Governor 请求预编译，所有 system/user/memory/schema 必须先完整装配、重新计数再调用；动态 completion/reasoning 预算，兼容现有 Gateway 和适配器。
P2：经探针确认的流式能力、连接/首事件/空闲/总时限、独立 Worker 心跳与物理调用台账；429 分级退避、UNKNOWN 对账与安全恢复；不自动重复付费。
P3：单一五维事实库及轻量 observation；来源证据锚点、角色别名、故事时间、人物知情时间、事实权威状态、增量版本、按场检索；缺失的非关键观察不得迫使大纲重生成。
P4：VolumeDigest 层级归并及关键事件/线索覆盖；超长 Scene 语义切拍、Beat 持久化、continuity 接续、无损拼装、DAG 影响传播；局部返工只处理必要依赖。
P5：在现有剧本与五角色分镜链中进行写前五维检索、写后 L0 确定性校验和必要时 L1 短语义复核；QA 建议不得擅自改写已批准剧情。
P6：简洁四步 UI、旧 V1 任务兼容、Windows 本地使用场景、故障注入及真实模型里程碑验收；真实付费 LLM/H3 仅在原有授权有效且用户明确允许的费用范围内执行，否则记录 NOT_RUN。
