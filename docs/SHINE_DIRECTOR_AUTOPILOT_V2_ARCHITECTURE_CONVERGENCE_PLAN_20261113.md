## 0. 一句话愿景、交付边界与工程优先级

**让不会 ComfyUI、不会写提示词、不会管理 Agent 的普通用户，导入一部小说，用少量创作决策自动制作并逐集交付真正的 AI 短剧。**

“自动”指：确认过的创作事实自动流入下游，工作台在合法、已授权、可验证的范围内自动编排；用户只处理创作选择、合法授权、不可自动决定的素材采用以及最终审片。**不代表跳过用户许可、静默创建正式主素材或把模拟出片伪装为真实 H3。**

优先级：**两集真实交付 > 消除跨阶段停摆 > 减少必须点击 > 页面美化 > 新模块/新功能。** 不为追求“一个按钮”再造一套大 Agent 流水线、第二套 GPU 调度或第三份项目状态库。

## 2. V2 目标用户旅程：七步可见、用户主要做决定

### 2.1 前台七步不变

| 可见步骤 | 普通用户看见什么 | 必要用户决策 | 后台自动做什么 |
| --- | --- | --- | --- |
| ① 创意与剧本 | 导入小说，统一可编辑的大纲正文 | 修改后确认大纲；首次发送远端模型须明确授权 | 识别/分段/大纲草拟、五维记忆、分场剧本补齐、版本投影 |
| ② 剧本统筹 | 导演风格、真人/动画、集数、每集目标秒数与分镜书预览 | 一次确认分集与风格 | 自然场次编排、剧情节拍、镜头需求预估、风格冻结 |
| ③ 镜头拆解 | 按集可编辑镜头表、时长与切点、异常定位 | 一次确认就绪集（可逐集或选中多集）；修改异常镜头 | 五工种、局部纠错、预算管控、按集落镜和版本绑定 |
| ④ 拍摄素材准备 | 镜头需求汇总，已匹配自动列为“复用” | 对缺项选上传/制作/跳过；人工选择正式采用候选 | 需求去重、素材检索、调用素材中心制作、版本化回绑 |
| ⑤ 导演包 | 本次可拍的集、工作流预设与预检结果 | 明确选择拍摄范围、批准冻结 | 构建已选集导演包、快照与就绪性检查 |
| ⑥ 视频生产 | 一个“开始真实拍摄”动作与逐集进度 | 显式授权真实 H3 运行，必要时暂停/恢复 | Run→Series→Job→ComfyUI→QC→有界返工 |
| ⑦ 后期成片 | 一集一张成片卡：可播、下载、问题与历史版本 | 艺术审片/接受/返修 | 已有 EDL、音视频/字幕装配、可用时的后处理、技术检查和交付登记 |

### 2.2 真正的“低干预自动推进”

- **默认“引导自动制作”**：一次确认后，在后端持久化的已授权边界内自动推进所有无新决策的任务；页面离开、刷新、重启不能使任务丢失。
- **“继续下一步”仅一个主动作**：状态取自服务端；进入每一步后直接显示当前应处理的实物，不让用户查找“材料化”“生成回执”“台账对账”等工程操作。
- **适当自动跳步**：已有确认版本、已匹配主素材、已通过的镜头或已成片，自动跳过重复工作；跳步仅是视图与安全调度行为，不跳过历史授权证明。
- **真正需要用户时停止在最小范围**：一个素材候选待选，只停对应需求与相关镜头；某集某场分镜异常，不停其他集的独立工作。
- **强制确认集中在“创作/法律/资金/生产/成片”关口**：大纲、分集+风格、镜头定稿、素材晋升、真实 GPU 运行、最终艺术审片。不得把这些无条件自动批准。
- **新手/专业两层，不是两个业务状态**：专业模式露出旧入口与底层诊断，但必须读写相同的权威工件、版本与权限。

## 3. 非目标、不可突破的硬边界

1. 不更换视频内核：正式视频只允许**本机已登记和真实验证**的 ComfyUI + MiniMax-H3，当前验证的 Ref2VA INT8 相关限制以本机 Profile/节点/权重能力为准。
2. 不把 Prompt 直接交给 ComfyUI：唯一 H3PromptCompiler、固定规则包来源与实际工作流映射保持有效；文学与镜头草稿允许自然语言。
3. 不新建完整第二 Worker、第二全局调度器、第二 GPU 排队/租约系统；复用现有 Run/Series/Job、ComfyOps、ResourceLease。
4. 不重写文学四阶段、五维记忆或五工种；优化入口、下游交接、上下文检索、局部失败与复用。
5. 不绕开素材主资产审批/锁定、远端文本传输同意、操作员一次性授权、真实生产许可及任一外部 UNKNOWN 对账。
6. 不隐式把虚拟/Mock/候选图当真素材，亦不把“审片建议未运行”标记为画面合格。
7. 不修改原始用户数据、模型权重、运行中的生产任务与既有项目历史；不在真实数据上强行修改状态。
8. 不顺便重做“新机安装”、多 LLM 管理、独立 Shine Assets UI 或导演风格引擎底层；这些只通过已有能力接口协作。

### 4.1 以现有代码扩展，禁止“中间编排微服务”

- 建议在 backend/shine/director/journey.py 和 director/streamline.py 扩展**只读 DirectorJourneyProjection** 与最小业务命令；复用 api_streamline.py 供导演页面调用。
- 允许轻量 facade/service 辅助文件，但它只负责查询聚合、版本验证、选择下一已存在业务动作，不能维护另一套独立阶段数据库、扫描式定时队列或自造外部任务状态。
- 真实执行仍从原有持久任务记录与 Worker 流转。对读到的状态为“不确定”，只提示有意义的下一步、恢复或对账，不凭时间推测成功。
- 通过同一份后端投影计算导演顶部进度、按集卡片、阶段主按钮与阻断原因；React 不再各自凭 shots.length、jobs.length 或本地缓存猜测“完成”。

### 4.2 单一事实源与写入归属

| 事实 | 权威对象/服务 | 下游引用规则 |
| --- | --- | --- |
| 源小说与授权 | ProjectDocument、source hash、consent ledger | 不同源文版本不可混用 |
| 大纲与人物关系 | 已确认 Outline artifact + 来源跨度；五维记忆为辅助索引 | 用户确认正文优先；不得“模型二次改写”覆盖 |
| 分集与场次 | DirectorEpisodePlan + stable section identifiers | 单集变更只失效真实依赖 |
| 导演风格 | Frozen Style Bible version/hash + profile/source | 选中的镜头和素材派生引用同一冻结版本 |
| 镜头内容 | ShotSpec + Shot revision + continuity + source lineage | 一次落镜，同输入重复调用不新增镜头 |
| 素材 | Asset identity + CandidateAsset + approval + Binding | 候选不等于正式主资产；回绑绑定具体版本 |
| 拍摄范围 | DirectorPackageVersion episode manifest/hash | 只冻结本次选中集及其真实前置依赖 |
| 视频与成片 | ProductionRun/Series/Job/Attempt/Artifact/Delivery | 不借用旧 Mock、旧 Run 或错误范围结果 |

**不允许新的“万能 ProjectJSON”复制上述内容。** 必须新增加字段时优先可由现有台账派生；只有确实不可恢复的用户决策才考虑最小持久化，并提供向后兼容迁移。

## 5. 统一按集状态投影：一页看懂“哪里卡住”

在后端实现项目与集的两个粒度：

- Project：当前计划版本、已确认集数、待制作集数、已交付集数、最新有效风格、真实生产环境状态、下一个必须动作。
- Episode：episode_id、最新计划与镜头版本、分镜状态、素材必需缺项、可打包/可开拍状态、活动 Run、镜头完成量、成片与交付版本、局部 blockers。
- Decision：按“需创作确认 / 需授权 / 需素材选择 / 可自动继续 / 失败需修复 / 结果未知待对账 / 已完成”归类，包含简洁文案、目标范围、原台账引用与实际可执行 API；不创建虚假可用按钮。

建议只读 API，例如：

- GET /projects/{project_id}/director/overview
- GET /projects/{project_id}/director/episodes/{episode_id}/overview

具体 URI 以仓库现有端点冲突情况确定；对旧 journey 接口保留完整兼容。

**跨集隔离必测**：第 2 集不完整时，第 1 集仍可显示“可备料/可打包/可拍摄/已成片”；只在两集之间有真实连续性、共同冻结事实或素材版本依赖时显示明确关联阻断，不能整片一刀切。

## 6. ①至③：取消重复文学与分镜入口，但不削弱创作质量

### 6.1 创作入口统一

- 导演首页只提供“导入小说/剧本、粘贴内容、打开已有作品”；一次源文本导入，不再从③重复选择文档或再填 locked facts。
- 已实现的 Markdown 大纲正文编辑与“确认大纲”保留为唯一正常路径。
- 文学四阶段的分卷、全局蓝图、分场剧本与五维检索继续后台工作；超长文本按已有弹性上下文与分卷交付处理。
- 各卷内部需要的专业确认，如能从用户已经确认的大纲、版本和合法授权确定，就不要求导演模式再点；存在真实文本/人物冲突时明确提示修改受影响部分。
- 如果用户修改已确认大纲，保存为新版本；只失效受影响场次/下游产物；不能让晚到任务覆盖用户编辑。支持旧项目原有工件回读。

### 6.2 四参数统筹保留，不建第二种导演风格模型

- 保留 V1 StoryboardBookPanel 的“导演风格、影片类型、集数、每集目标秒数”四项，生成真实可读的分镜书并一次确认。
- 长篇按卷处理仍用现有来源跨度与五维记忆，不要求用户手工复制或移动几百场内容。
- 导演风格模板是选择入口；冻结 Style Bible 是唯一生产事实；素材视觉方向作为派生默认，用户修改需走明确版本与影响提示。避免三处独立风格互相漂移。
- 影片类型的真人/动画信息必须贯穿图像候选生成、导演包与 H3 提示词，不允许“动画项目素材误生成实拍”。

### 6.3 分镜收成“后台五工种 + 前台按集镜头表”

- V1 EpisodeStoryboardPanel 为正常入口的唯一镜头表；传统 StoryboardPanel、FourStagePanel 的分镜 UI 保留为专业工具，正常导演页面不重复挂载或重复调用。
- 相同已确认输入复用成功的分镜工件；后台按场或必要细分执行五个工种，继续遵守 60% 输出预算、完整请求估算、流式与限流政策，禁止擅自提高输出上限。
- 显示每集镜号、动作画面、对白、成片时长、镜间切开/接拍、镜内切点、实际 H3 生成时长/片段。真实 H3 的合法时长/尺寸取已登记 Profile 实测配置，不能只信前端常量。
- 规范化模型输出可补稳定 ID、合理字段默认值、确定性排序；重要人物/对白/时序冲突必须停在具体镜头等待处理，不能编造故事事实。
- 提供“确认当前集”和“选择所有已就绪集批量确认”；批量确认仍有用户明确预览与版本校验，后端逐集返回成功/失败及 idempotency receipts；任一失败不撤销其他独立已确认集。
- UNKNOWN 保留原任务与执行证据，先核对再决定是否授权新请求；任何失败不把其他已完成镜头重生成。

## 7. ④ 素材准备归一：一个需求、一个身份、多镜复用

### 7.1 清单只从已确认镜头派生

- 从已确认镜头的 ShotSpec + 分集/场次来源 + 人物/道具/造型/音色引用推导，而非再次让另一套 Agent 全文重读小说。
- entity identity + visual/voice variant + family + approved revision 是最小去重维度。别名及角色关系使用既有身份服务；不同造型、伤痕、服装、时代等需真实区分版本。
- 展示需求名称、必要性、状态、使用集/镜号、可复用正式素材、候选来源和最近一次确认版本。
- 家族至少涵盖：人物主体/造型、真实需引用的场景与道具、必要声音参考；没有配置实际素材槽位的需求不得冒充必需项。只对源镜头可推断的内容建需求。
- 已批准同版本主素材自动预选“复用”，但跨项目调用须遵守原 Asset assignment 与授权边界。

### 7.2 必需项与可选项是不同门禁

- 必需：当前 Ref2VA Profile 的主体图、必需参考与特定音频/视频传输槽位等，经配置验证缺失时只阻对应镜头/集。
- 可选：不影响生成合法性的背景、道具或创作辅助参考，仅显示建议；用户可明确跳过。
- 移除“缺图 H3 会自行生成”的笼统文案；模型生成片段并不等于制作已经缺失的正式资产。
- 缺位提示必须携带 episode_id、shot_id、family、实际 workflow profile 与修复入口。

### 7.3 候选生产与采用的一次交接

- 选择“AI 制作”必须是用户明确意图；一次确认所选 requirements 后，复用现有 material-preparation/generate 与 Shine Assets Worker。
- 生成批次以 project + requirement snapshot + 用户选择集合 + profile/seed/variant 构造确定性请求身份；不得用 Date.now 形成重复生产键。确认成功但 HTTP 应答丢失时，优先以同一键查询/复用历史结果，绝不盲目重发。
- AI 产物仅作为 CandidateAsset；用户明确选定候选后，仍调用既有 one-use grant、promotion、锁定和项目 assignment，**不能在后台直接提升主素材**。
- 将“选定并回绑到全部对应镜头”收成单次业务动作；服务端逐项执行原有合法性验证，显示局部成功、局部失败及可恢复动作；不能谎称跨多个原接口的事务整体原子。
- 页面刷新、关页、Worker 崩溃后，候选、用户决策、已提升的 Asset 及每镜绑定从台账恢复；不让用户重新分析剧本或重复点击“生成清单”。

## 8. ⑤⑥ 统一开拍：一个前台入口，沿用原生产引擎

- 一个按集就绪面板取代导演模式里重复的 DirectorProductionRunPanel / ProductionSeriesPanel / 单镜开拍组合。
- 用户可选择单集或多集；默认优先推荐“已经具备全部实际依赖的集”；不可拍的集只展示缺项和跳转，不影响其他可拍集。
- “检查拍摄条件”调用原导演包/工作流 readiness；使用已验证的 H3 Profile、Ref2VA INT8 权重和工作流参数，不静默切换到 Mock/W6A8/未验收模型。
- 保留既有 DirectorPackageVersion 的确认事实。提供对用户清晰的“确认拍摄方案并开始真实制作”复合流程：先持久化、校验并确认所选导演包，再以有效包启动既有 Run；生产授权必须为用户显式操作，遇到部分失败分步恢复，不宣称跨 API 完全原子。
- 所有后端请求携带 scope episode_ids、有效 shot revision、profile identity、style sha、package manifest、idempotency key；相同请求重放返回已有 Run/Series，不会重开 ComfyUI、重复领取 GPU Lease 或重复付费。
- 一集运行期间，另一集可继续文学/分镜/素材任务；真实共享 GPU 受现有独占调度管控，不允许影像生成与 H3 并发抢资源。
- 专业入口继续存在专业模式；导出到正式 Run 的任务账本必须与导演模式一致，不出现两种互不相认的“正在制作”。

## 9. ⑦ 后期自动衔接：先出可审片，再由用户认可

- 当前集的必要 H3 镜头全部通过**确定性安全门禁**后，自动沿用已有 Run/EDL/字幕/声音/技术 QC/装配机制准备成片；不重建 FFmpeg 流水线。
- 只在既有合法交付权限与成片策略内自动推进；超分、二采、RelayVSR X2 等在本机验证并登记之前一律不作为默认必经路径，参数从预设显式选择。
- ⑦ 每集一张卡：已拍镜头、可播放 MP4、总时长、字幕/音频情况、技术 QC、非阻断艺术建议、导出路径和历史版本。
- “技术完成”不能代替用户“艺术认可”；允许用户选择“接受此集”或“仅返工某镜”，回流只影响真实依赖镜头、镜间衔接和当前集成片，不覆盖已交付历史版本。
- 第 2 集补修时，第 1 集已交付 Job ID、source artifact SHA 与 MP4 hash 必须保持不变，除非用户明确发起第 1 集的新修订。

## 10. 统一异常分级与下一动作：不要技术码驱动用户

| 等级 | 例子 | 系统行为 | UI 显示 |
| --- | --- | --- | --- |
| A 可确定性自动修复 | 结构默认值、可恢复映射、源工件已存在 | 复用原工件、有限本地修复，不重复请求 | 自动继续/已恢复 |
| B 可控局部返工 | 某场 schema 重要字段不全、某镜质量硬失败 | 保留其余成功部分，局部修订或有界重试 | 第 X 集第 Y 镜需修改 |
| C 必须人类决策 | 大纲确认、风格冻结、候选晋升、远端授权、真实拍摄、艺术审片 | 停在精确决策目标 | 请确认这项选择 |
| D 执行结果未知 | LLM/ComfyUI 断连后无最终回执 | 使用 intent/外部 ID/已落盘产物核对；无证据时禁止自动补发 | 结果待核对 |
| E 环境真实不可用 | 必需 Ref2VA 槽位未映射、权重/显存/节点不可用 | 准确定位设置或受影响镜头 | 修复后继续 |

所有面板只展示简洁中文原因和一个真正能执行的下一动作；错误码、trace、哈希、Token、GPU 细节在专业诊断中查看。若无法保证自动修复安全，宁可显示待修，也不能暗中补造输入。

## 11. UI 信息架构与交互约束

### 11.1 导演首页

- 主区：当前作品、全剧进度、**下一步唯一主按钮**、每集状态卡与最近一条待处理事项。
- 七步导航仍存在，但不再把每步当作必须翻页才能操作的不同产品；允许从主页直达当前集，不强迫按项目总进度顺序操作。
- 每集卡展示“分镜准备中 / 等待选素材 / 可开拍 / 拍摄中 / 可审片 / 已交付”，与后端投影严格一致。
- 导演模式不出现多套同时可点击的“生成分镜”“生成素材清单”“一键开拍”，不展示中间 UUID/原始 JSON/台账类型名。
- 素材中心与导演模式平级，导演模式通过待办直接带 project+requirement 的上下文进入素材中心，完成选材可返回原集原镜。
- 环境配置不应占用创作主界面。生产环境无法启用时显示一次可理解的“启用真实制作”引导，Mock 标签必须明显。
- 旧高级控件不得作为导演页展开后隐藏的另一套完整流程；有必要时只在专业模式保留完整入口。要保证专业用户依然可以调试。

### 11.2 动作与状态守则

- 切页/刷新后必须恢复正在进行任务、候选选择、确认草案、当前集及已创建的 Run；不可用 React 内存冒充持久状态。
- 前端负责展示和向后端发出明确意图，不自行决定哪些不可变版本“已经确认”。
- 一个操作只出现一个主 CTA，点击期间禁重入；客户端断连后用同一稳定请求键核对状态，不自行生成新键重试。
- 文案以“当前集/当前镜头/真实状态”为准；项目整体尚未完成时不能提示“全片已就绪”。

## 12. 版本、依赖、幂等与数据兼容合同

### 12.1 最小业务命令合同

每个修改类命令至少说明：project_id、target scope（episode/shot/requirement）、expected version/hash、user intent、optional idempotency key、原始权威台账回执。错误响应携带可行动的 scope/blocker，而不是一个裸 409。

建议建立可复用的 service helper 来组合现有 API，避免在前端连续发 5 次请求后只知“最后一步失败”。真正跨旧接口做不到原子事务时使用**可恢复 Saga/步骤回执**，并在后续读取时识别哪项已提交，不伪造新全局事务。

### 12.2 失效范围

- 故事结构/角色身份变更：根据实际来源跨度、五维记忆引用及分集/镜头依赖精确失效；没有安全证据时明确说明扩大范围的理由。
- 单镜画面/对白修改：只影响该镜及真实跨镜依赖、相应后期装配。
- 素材候选未采用：不改变既有主素材和已经冻结的包。
- 已确认主素材被替换：新包用新版，旧包/旧 Run/已交付成片作为可追溯历史；旧的正在运行任务不能被偷偷换引用。
- 已通过镜头：若其实际输入版本不变，一律保护其 Job/Attempt/Artifact，绝不因其他集失败重拍。

### 12.3 并发与恢复

- 采用现有 SQLite WAL/optimistic state_version、审计、submit-intent-before-send、外部 prompt ID、GPU lease 和 Worker reconciliation。
- 测试 double-click、HTTP 成功但客户端超时、Worker 在外部 submit 前后死亡、浏览器断线、重复启动、旧页提交、跨项目 ID 误用。
- 不为“自动化”降低已有原子持久化/身份与权限检查；未知结果要有明确恢复路径，不允许盲目重投。

## 15. 可执行的验收规范

### 15.1 L1 静态与单元

- Python Ruff、后端有针对性的 unit/integration、frontend TypeScript、Vitest、构建；新增对 read projection、按集就绪、需求去重、稳定幂等、版本冲突、风格投影与局部失败的测试。
- 建议重点复用：test_director_streamline.py、test_four_stage_closeout.py、test_director_run_scope.py、test_material_director_flow.py、test_asset_center.py、test_film_crew.py、test_offline_e2e.py、test_production_series.py。
- 保持原有测试断言，不得删测试、放宽身份/安全门禁来“做全绿”；对照现有基线记录测试数量与跳过维度。

### 15.2 L2 工程与浏览器穿测

- 正常导演模式必须支持：小说导入、原地编辑大纲、四参数统筹、按集镜头、素材复用/制作/批准/回绑、只选第一集打包开拍、成片预览。
- 检查：旧项目继续；专业模式入口；刷新/重启恢复；按钮防重；同键重放；跨项目/过期哈希拒绝；部分失败；文本授权与 Mock 身份明确。
- 通过普通页面完成测试，不得靠手工修改数据库、直接构造 API 数据或调整任务状态绕过 UI。

### 15.3 L3 Windows 真机双集验收（硬性，不可用 Mock 替代）

1. 本地真实 Windows 用户入口启动；项目在**隔离副本数据目录**；检查 Worker、LLM、ComfyUI、已验证 Ref2VA INT8 Profile、实际工作流与模型权重。
2. 导入原创/有授权小说，实测编辑一条剧情事实并确认；选导演风格、影片类型、2 集、单集秒数，生成并确认分镜书。
3. 完成第一集镜头，第二集至少留一场待修；第一集从正常用户界面进入素材。至少一次复用，至少一次用户授权 AI 制作候选，人工选定并回绑。
4. 只选择第 1 集构建有效导演包，显式启动真正 H3；记录 ComfyUI prompt IDs、Job/Attempt、产物 SHA、技术 QC、真实 MP4；人工播放、检查对白/字幕/音频/时长。
5. 模拟浏览器刷新及服务合法重启，从持久化进度续作第 2 集，真实生成并导出；核验第 1 集 Job ID、镜头产物 SHA、成片文件 SHA 未改变。
6. 旧项目副本升级与恢复、专业模式/素材中心跳转、失败镜头局部重做、未授权的候选不能晋升、断连的 UNKNOWN 不盲投、两集隔离与稳定重复提交均需有证据。
7. 如果真实设备/第三方 LLM/模型不可用，要列出精确的阻塞证据和最短复测步骤；L3 标记 NOT_VERIFIED，不得写 PASS。

### 15.4 用户体验与操作成本（定量记录，不伪造达标）

在相同小说、同一机型、同一工作流下，记录 V1→V2：主动点击次数、必须做出的业务确认次数、跨页面回跳次数、因技术字段手工处理次数、每集从确认分镜到“可拍”时长、已通过镜头复用率、失败返工的重复 LLM/H3 调用数。

建议目标（**设计指标，不是已达到的结果**）：

- 普通导演路径：前台只呈现一套创作/分镜/素材/开拍 CTA，**重复入口数为 0**。
- 与原始工件相同的重复提交产生**0 个重复真实模型调用/任务**；断连 UNKNOWN 不自动重新提交。
- 非跨集依赖的待修第 2 集不阻第一集：**按集隔离通过率 100%（针对设计测试集）**。
- 已成功且输入不变的镜头在续作后**0 次重拍**。
- 两集标准场景除各项素材选择/授权等依素材数量变化的合法动作外，目标把用户必需创作/生产确认控制在**约 6–10 次**；逐项列出实际次数，不能通过自动批准风险行为“刷低点击数”。
- 真实成片必须可播放、hash 可验证、技术状态真实，不能以 Fake/Mock/软测试替代。

### 15.5 验收判定：三个互不替代的结论

- ENGINEERING_PASS：代码、测试、迁移、幂等、旧项目和可控异常回归通过。
- REAL_H3_PASS：本机真实 MiniMax-H3 两集镜头、成片、音频/字幕、恢复、不重拍证据完整。
- HUMAN_ART_REVIEW：用户/授权审片人亲自确认艺术观感；无此证据标 NOT_REVIEWED。

任何维度都不能由另一个维度的 PASS 代签。

## 16. 工程风险与防止 V2 再膨胀的“停止规则”

1. 如果计划创建新的全局 orchestrator、第二套任务实体或第四种项目工件格式，必须停止并说明为什么现有服务不能扩展；默认不批准。
2. 新增用户可见页面或配置项时，必须说明它替换/删除了哪项旧操作，否则默认拒绝增加复杂度。
3. 改动 worker.py、preproduction.py 或 quality reviewer 身份敏感文件时，按 AGENTS.md 校验 client_review_identity，必要时重新进行真实 VLM 正/负校准；**不能以测试覆盖掩盖身份变化**。
4. 触及 GPU Lease/ComfyOps 不得解除独占、不能用过期时间直接证明模型已卸载；所有未知外部请求必须守住既有 intent/reconciliation。
5. 不迁移真实数据库当作测试。改数据库仅凭必要字段，保留既有 schema/hash 序列化与旧任务阅读路径，先备份和模拟升级。
6. 按集继续的任何“简化”若使跨集真实前镜/声音/素材依赖丢失，必须退回保守验证，不得为了达到按钮数量而妥协。
7. 不允许为了“一键出片”隐式发送授权原文到第三方、自动采用图片候选或未经用户明确操作启动真实 GPU。
8. 优先实际真机闭环，不能在大规模重构后才第一次运行一集真实视频。

## 18. Agent 执行总原则

- 先读 AGENTS.md、当前 main 与第一轮方案/验收；新分支只作为 V2 规格来源。
- 本地从最新基线开独立 worktree 或 feature branch，检查未提交修改与并行工程；优先保住第一轮已实施逻辑。
- 按 WP0→WP7 逐项自主建设、定向回归、真实穿测、修复和重验。任一工作包失败，保留可用成果与报告，不谎报 PASS。
- 只在本人工作分支提交；**不自动推送远端、不合并 main**，除非用户另行明确授权。
- 成功的终点不是“页面只有一个按钮”，而是**从小说到两集真实 MP4、整条正常用户旅程可连续完成、第二集失败不会导致第一集返工**。
