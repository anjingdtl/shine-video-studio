## 2. 冻结红线（必须落实）

- 正式视频生成模型仍只能是**本地 MiniMax-H3 + ComfyUI**；Qwen 图像/TTS/ASR/VLM 仅供资产准备、声音及质检，不替代正式视频生成。
- 保留现有**唯一项目/资产/任务数据库**与 H3 Prompt Compiler、RulePack、Style Bible、Job/Attempt/Artifact/QC、逐项授权人工审片；不能弱化质量门和软/硬连续性限制。
- 修改“仅人工资产”时必须区分 `CandidateAsset` 与正式 `Asset`：Agent 可自动生成/导入/质检候选，但**绝对禁止 Agent 自动批准并锁定正式主资产**；旧项目主资产及已批准状态完全保留。
- ComfyOps 是第八类受控专业 Agent；声音导演使用 VoiceOps，不能使 LLM 获得通用 Shell、任意文件系统、任意 HTTP 和数据库权限。继续使用独立 LLM Gateway，Codex 不成为产品运行时。
- 新增下载、安装、第三方节点代码、已有实例升级、真人音色克隆等高风险能力必须有服务器验证的人类授权；管理员令牌不能由 Agent 伪造。只读和 DryRun 可自动执行。
- Qwen-Image-2.1 官方模型权重采用 Qwen Research License（非商用限制），不能默认在商业项目中可用；H3 社区许可和具体节点/LoRA/声音模型许可证亦需独立审查。不得含糊写“开源即可商用”。
- 不破坏本机 8188/8189 或任意旧 ComfyUI、模型、虚拟环境/工作流；云端严格不接真实 GPU、不下载模型、不修改用户真实机器数据。
- 不把 Fake 成功写成 `REAL_TESTED` / `PRODUCTION_APPROVED`；所有输出须区分 implemented/tested_offline/mock_verified/pending_local/blocked。

## 3. 第一阶段：ComfyOps 环境感知与目录

实施环境/硬件/ComfyUI 实例/模型/节点发现的**接口、持久化和 Mock 实现**。产物包括 `EnvironmentSnapshot`、`CapabilityGapReport`、`ComfyInstance`、`ModelPackage`、`NodePackage` 和只读 API/UI。

Windows Probe 设计需要显式允许的路径/端口；支持多个实例、中文路径、不同虚拟环境、GPU/VRAM/磁盘、ComfyUI 节点清单和工作流来源。当前云端使用 `FakeWindowsHostProbe` + `FakeComfyUIInventory`，提供实例在线/离线、节点缺失、模型重复等完整用例。**不能以云端容器无 GPU 为由把本机发现功能删掉；须实现可运行的本地探针协议与受限驱动，但不能在云端假装 Windows 已扫描。**

## 4. 第二阶段：安装规划、下载管理与安全执行边界

实现来源版本锁定、模型及节点规格、许可证/商用门禁、依赖/磁盘/显存预算、已装复用、SHA-256、下载缓存、断点续传协议、安装状态机、审计/重放防护和可回滚变更清单。

关键：**云端只能执行 DryRun/FakeInstaller 测试**，不可下载真实权重或执行第三方安装脚本；实际安全执行器需实现清晰的参数化接口、操作白名单、路径和 URL 校验、计划哈希绑定与过期/并发控制，使本地 Agent 后续可接通 CLI/comfy-manager。绝不能实现 `subprocess.run(llm_output)` 或根据 LLM 自由文本执行命令。

节点安装与升级要区分新隔离实例和修改现有生产实例；后者需要更高一级人工批准、快照/回滚点以及空闲队列核查。

## 5. 第三阶段：Workflow Factory 与 Capability Registry

实现能力分类、图契约/输入输出 schema/参数映射/参考媒体传输/依赖验证、草案自动组装（仅白名单模板）、静态检查、Fake ComfyUI 执行、生产级发布审批及注册、版本和能力匹配。

已存在的 H3 Ref2VA Profile、完整图 hash、PDD8/超分历史证据必须保留；不能默认升级为新工作流已通过真实测试。允许摄影/导演/声音 Agent 通过结构化 `find_workflows` 与 `request_capability` 检索和调用，不给予直接自由 JSON 节点执行权限。

继续严格阻止：参考图/音/视频槽位漏配、节点版本不兼容、未实测的严格首帧锚定或视频参考传输、错误 H3 模式、失配的 RulePack/Style 版本。

## 6. 第四阶段：统一预制作资产工厂

新增 `AssetRequirement`、`CandidateAsset`、来源/许可/生成溯源/质量证据、统一导入 + AI 候选生成 API。至少覆盖角色定妆/三视图、服装、场景、道具、关键帧/Storyboard、动作参考、音色、对白、环境声、音乐、字幕和配置工作流的需求建模；**没有实现生成模型的类别仍要支持导入与阻滞提示**。

Cloud FakeImageProvider/FakeAudioProvider 可返回合成测试资产但必须明确 Mock；导入文件的扩展名/签名/哈希/容量/路径/跨项目校验同原库标准。候选晋升必须由服务器端真实人工操作员批准，并复用现有正式资产权限门禁；不能调用现有 approve/lock 接口伪造“user” actor。

对同一人物/服装/场景/道具创建独立版本，绑定字符 EntityID、项目和 Style version，生成结果不得覆盖已经冻结的原始母版。

## 7. 第五阶段：VoiceOps（不能忽略）

实现具有独立生命周期的 `VoiceProfile`：角色绑定、原创音色设计、授权声线克隆、音频导入、样音试听、语言/普通话/情绪/语速、VoiceProfile 版本锁定、声音权利记录和撤回限制。没有独立权利/同意凭据的可识别真人克隆必须拒绝。

通过可插拔 `TTSProvider`、`VoiceDesignProvider`、`VoiceCloneProvider`、`ASRProvider`、`ForcedAlignerProvider`；建立 Fake Voice Server/Fake ASR，在云端从“原创音色描述/用户授权音频→候选试听→人类批准→相同角色多镜头对白→语音转文字→逐字对齐→SRT/ASS”走通。

官方 Qwen3-TTS、Qwen3-ASR/ForcedAligner 等只登记**真实检查过的能力/模型 ID/版本/许可证**，不可假设每个权重都支持克隆或 VoiceDesign。真实推理标 `PENDING_LOCAL_TTS`。区分 H3 原生对白、音色参考驱动和后期配音；必须沿用 H3 参考音频硬限制与时间轴规则，不能只检测到 WAV 就宣称口型同步。

## 8. 第六阶段：预制作 DAG + GPU 资源管理

实现剧本→完整 AssetRequirement→已有资产/工作流/模型能力匹配→缺口→自动生产/人工导入建议→候选 QC/批准→完整的 `PreProductionManifest` hash/快照→`SHOOT_READY` 开机门禁。

必须覆盖角色、服装、场景、道具、音色、对白、环境声/配乐、Storyboard/首尾帧、字幕和 VLM/ASR 审片能力；关键缺项不能悄悄跳过，非关键可标记 `OPTIONAL`。上游版本变化应局部失效下游，独立任务不受影响。

GPU 资源模块实现 `ResourceLease`、独占/预算/优先级、心跳/宕机恢复和任务切换。以 Fake GPU 16GB 模拟 H3、生图、VoiceOps、ASR/VLM 争抢资源，确保 H3 生产优先、可恢复且不误杀 ComfyUI 真实进程；没有真实显存数据就标为估算。

## 9. 第七阶段：Web、API、迁移、测试与审查

前端新增：环境中心、模型/节点中心、工作流能力中心、候选资产工厂、Voice Studio、开机前预检。全部接真实 V1.3 API，不允许静态演示假按钮。应有风险确认、审批/失败详情、安装队列与模型/工作流/资产哈希、Mock/Real 标签和权限反馈。

为新增表实施增量 Alembic；测试全新库、V1.2.1 `f121a0010001` 升级副本、历史数据/审批/QC/Attempt 保留；不迁移、重写用户生产数据库。

强制负向用例：权限越权、恶意下载地址/SSRF/ZIP slip/路径穿越、安装执行计划 hash 更改、模型许可不足、缺音色克隆授权、跨项目引用、工作流缺节点/槽位、资源超预算、重试重放、候选资产自动晋升、预制作缺项仍投 H3、旧 Workflow/Style/Voice 版本混用。CI 覆盖 Ubuntu 后端、Windows 后端+API/Worker smoke、前端构建；不能因为新能力降低旧 254 个测试的覆盖。

完整 Fake E2E：新剧本→分析所需资产→发现缺模型/工作流→生成并批准 DryRun 安装计划（无实际系统变更）→Fake 图像与音色生成候选→由测试操作员走真实鉴权 API 晋升→Frozen Voice/Asset/Style/Rule→导演获取已验证可用工作流→现有 H3 Compiler + Fake ComfyUI→QC/返工及镜头复用→逐项结论 `MOCK_VERIFIED`。
