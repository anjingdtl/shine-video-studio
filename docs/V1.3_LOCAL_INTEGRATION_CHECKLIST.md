# V1.3 local integration checklist

Cloud evidence is software-only. Every item below needs a local human, authorized paths,
licensed inputs and exact model/node revisions. Do not use a cloud test operator credential,
Fake media, or `SHINE_OFFLINE_SIMULATION=1` for real production.

## 1. Prepare a disposable Windows acceptance workspace — PENDING_LOCAL_ENV

- Preserve the original 8188/8189 instances, workflows, virtual environments and production DB.
  Back up SQLite with its backup API. Migrate only the acceptance copy first.
- Record Windows/NVIDIA driver/Python/ComfyUI revisions, model/node roots, free disk and RAM.
  Explicitly allow only the intended roots/ports. Never select an entire user profile/system disk.
- Provision `SHINE_OPERATOR_ID` and `SHINE_OPERATOR_TOKEN_SHA256` using
  [the existing operator guide](operator-review.md). Keep plaintext out of env files, Git,
  URLs and browser storage. The human enters the actual credential in the UI or local CLI.
- Run `uv sync --project backend --locked`, `npm ci --prefix frontend`, Alembic `upgrade head`,
  full pytest/Ruff, frontend build and `scripts/verify_local_stack.ps1` before model work.
- Configure `SHINE_COMFY_PROBE_ROOTS` as a JSON array of explicitly allowed directories and
  `SHINE_COMFY_PROBE_PORTS` as a JSON integer array, then restart the API. POST
  `/api/v1/comfyops/inventory/refresh` with `{"mode":"local"}`. Compare the snapshot to the
  machine manually. Default `{"mode":"fake"}` remains a simulated scan.
- Check Chinese paths, offline instances, duplicate weights, extra model paths, Python/venv
  differences and junctions. Add external model roots explicitly; do not silently expand
  `extra_model_paths.yaml` into an unrestricted scan. Inventory without a hash is not integrity proof.

## 2. Install only reviewed, isolated packages — PENDING_LOCAL_ENV

1. Review each model card and exact weight/quantization/LoRA license separately from source code.
   Consult [the pinned audit](V1.3_UPSTREAM_AUDIT.md). Qwen-Image-2.1 is research/non-commercial
   absent a separate commercial license. Do not approve `UNKNOWN` or transfer a parent license
   assumption to a derivative. Recheck H3 Community License and each independent node plugin.
2. Register an exact PackageSpec: immutable revision, actual HTTPS file URLs, relative file
   paths, sizes, SHA-256, dependencies, precision/quantization and resource measurement state.
   Reference-catalog entries deliberately have no downloadable weight hashes.
3. Generate an install plan using `executor=local`, a verified disk budget and `isolated=true`.
   Inspect every byte/source/dependency, third-party-code warning and rollback scope.
4. The human obtains an `install` grant and approves the current plan digest. The resulting
   approval expires after 30 minutes. Do not use a Fake plan for this step.
5. On Windows, with the same acceptance DB and configured operator identity, explicitly run:

   ```powershell
   uv run --project backend python -m shine.comfyops.local PLAN_ID APPROVED_PLAN_SHA256 --execute
   ```

   The CLI prompts the human for the credential. This is a real download/install operation;
   it was never invoked against real packages in the cloud. It only writes the application's
   isolated package root. It does not overwrite the existing ComfyUI or execute node hooks.
6. Verify hash/size/cache reuse, resume after interruption, staging cleanup, atomic replacement
   and the `.journal`/`.rollback` recovery manifest. Keep recovery scoped to the acceptance copy.
   An interrupted attempt is not automatically replayed. For a multi-package failure, reconcile
   completed packages as well as the failed package; per-package atomicity is not a whole-machine rollback.
7. `FILES_VERIFIED_PENDING_RUNTIME` only means files matched the manifest. Bind the isolated
   packages to a separately approved instance, review any Python dependency installation and
   node setup scripts, then test loading. Existing-instance L3 upgrades/restarts are blocked
   by the HTTP planner; never work around that by modifying production paths.
8. Pin and hash the local comfy-cli executable or Manager script before using the adapters.
   `ComfyCLIAdapter.snapshot` and `ManagerAdapter.snapshot` build only fixed commands. Snapshots
   are auxiliary; they do not back up all external models/environments. Independently back those up.

## 3. Register real workflows and service bridges — PENDING_LOCAL_ENV

- Preserve these existing graph digests exactly:
  - `local-h3-ref2va-2img`: `6f7a5fb19c548ca945f8a2169e05c836d7c06f03466cf2b893b3be599505d112`
  - `local-h3-ref2va-2img-1aud`: `7d86f7b6d994b0b38cc379a4fe0268f68776c4a43e80fb0f7651a3005f57dcd6`
- Import the actual PDD8/1.5× profile separately with its actual graph/model/node hashes and
  parameter/media mappings. The historical report is not an automatically published Registry revision.
- Validate against live `/object_info` and exact node versions. Check every image/audio/video
  slot, transport, range and graph dependency. Hard anchoring and video-reference continuity
  remain blocked until independently verified; do not infer them from node names.
- The default asset/voice providers are Fake. Optional `SHINE_LOCAL_IMAGE_URL` and
  `SHINE_LOCAL_VOICE_URL` select loopback **Shine service protocols**, not official Qwen APIs.
  A local service bridge must translate the following into its exact installed model SDK/workflow.
  No cloud model weights or GPU runtime were installed to provide that service.

| Service | Request | Required result |
| --- | --- | --- |
| Image `POST /generate` | prompt, seed, immutable workflow contract, base64 reference bytes | content_base64, filename, model identity, is_mock=false for real output |
| Voice `POST /design` | description, text, character | audio_base64, duration_s, speaker, language, model, is_mock |
| Voice `POST /clone` | authorized reference_base64, reference_text, character | same voice result; no unauthorized remote transport |
| Voice `POST /conditioning` | approved audio_base64, sha256, reference_text | same sha256; preserve a reusable conditioning keyed by that digest |
| Voice `POST /tts` | text, character, conditioning digest, emotion, speed, pause | audio_base64, duration_s, speaker, language, model, is_mock |
| Voice `POST /asr` | audio_base64 | text, speaker, language, confidence, model, is_mock |
| Voice `POST /align` | audio_base64, locked text | words: text/start_s/end_s |
| Both `POST /free` | unload_models=true | released=true only after model release is confirmed |

- Qwen3-TTS VoiceDesign/Base/CustomVoice are distinct checkpoints. A stable original voice
  uses an approved designed sample plus reusable Base conditioning; CustomVoice predefined
  speakers are not an arbitrary cloning substitute. Qwen3-ASR and ForcedAligner are separate.
- For a real image workflow preview, use a `STATIC_VALIDATED` revision and an authenticated
  `workflow_preview` grant in Generate.preview_decision. This authorizes only an explicit local
  preview. Promote the resulting non-Mock candidate after QC. Bind its exact workflow/hash in
  `local-evidence`, then request a separate publication grant. Fake evidence is rejected.
- H3 publication evidence must bind a current manually verified real Job/Attempt/Artifact and
  five non-Mock gates to the exact registered graph. Candidate evidence is for local image
  previews; do not use it to claim H3 continuity or video acceptance.
- For non-video ComfyUI capabilities, `local-execution-evidence` reads a registered real
  instance's successful History, compares the graph while allowing only declared parameter
  changes, verifies the canonical output digest and live node contract, then requires a human
  grant. Fake inventory cannot supply this evidence. H3 and voice cloning cannot use this
  generic route. Declare node versions only when the inventory supplies actual version evidence;
  a missing version must not be replaced with the requested version.
- VLM/ASR/music/SFX/upscale/interpolation categories without an independently verified local
  implementation remain capability gaps or import-only. Never invent a node/template to clear a blocker.

## 4. Assets, voices and readiness — PENDING_LOCAL_GPU

- Import or produce each character/outfit/scene/prop/keyframe/storyboard/action/voice/dialogue/
  SFX/music/subtitle candidate. Record rights, source, parent/version, workflow/model and content hashes.
- Run full technical decode with FFmpeg. Missing tools report unavailable and block promotion.
  Automated real semantic acceptance is not supplied by cloud Fake QC; inspect identity,
  costume/scene/prop, licensing and semantics with the authorized human/local reviewer.
- Approve asset rights and audio-specific rights independently. Authorized cloning must bind
  the exact project, reference candidate and purpose. Test withdrawal before any re-use.
- The human listens to the actual sample and submits `listened=true` plus evidence before
  freezing the Voice Profile. Same character/conditioning hash must drive multiple dialogue lines.
- Test Mandarin text, emotion/speed/pause, speaker identity, ASR mismatch, low confidence and
  word timestamps. Export SRT/ASS; correct timestamps through the authenticated revision API.
  A transcript match is not proof of matching voice or lip sync.
- H3 reference audio must satisfy the existing 2–15s and total-duration/slot/transfer constraints.
  Choose H3_NATIVE, VOICE_REFERENCE or POST_DUB explicitly. Test actual audio uploads and playback.
- Analyze the script. The deterministic extractor recognizes speakers and explicit 场景/道具/
  服装/音效/音乐 annotations; inspect and supplement typed critical requirements for free prose,
  outfits and per-shot detail. Optional requirements must be a conscious production decision.
- Freeze Style/RulePack, approved assets and voice versions; resolve workflow/model/node/license
  gaps, then freeze the exact ready manifest. Changing any selected version/rights must stop
  the affected project production. Queued jobs keep their original manifest hash, even after a
  new manifest is approved. Use `create_revision=true` to create a new immutable plan version;
  do not overwrite a frozen plan. Unrelated registry additions do not change the selected
  workflow/model set. Confirm independent candidate tasks and other projects still work.

## 5. GPU admission and film acceptance — PENDING_LOCAL_GPU

- Measure RTX 5080 total/free VRAM, RAM and model peak/load/unload times. Replace UNKNOWN/
  ESTIMATED resource entries with observed values plus measurement evidence, never guessed claims.
- Exercise H3 exclusive priority, queued image/TTS/ASR/VLM, expired leases, OOM/provider failure,
  model release failure and Worker restart. Verify `/free` really releases models; do not kill
  existing ComfyUI processes. A lease in RECONCILE_REQUIRED blocks new conflicting work.
- Run the new H3 PDD8/upscale profile through Shine for one short shot first, then three segments,
  dependencies, repairs, cache reuse, subtitles/audio and assembly. Keep original artifacts unchanged.
- Recompute output hashes, decode all frames, inspect dimensions/FPS/duration/audio and submit
  the existing per-item authenticated human review. Do not borrow gates from an older Attempt.
- Preserve the historical distinction: old 480×864 outputs failed production visual acceptance;
  the separate 2016×1152 PDD8 sample has basic user visual acceptance, not complete-film acceptance.

## Evidence template

For every local item record: status, UTC time, named human, project/plan/attempt IDs, source
commit and license evidence, package/workflow/content hashes, exact hardware/driver versions,
commands, technical checks, measured VRAM/time, media location kept locally, per-item review,
known failures and rollback verification. Do not put private media, weights, credentials or
production databases into Git. Final acceptance requires actual human playback and audit events.
