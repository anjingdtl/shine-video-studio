# Shine 视频工作台｜导演模式与本机环境收束建设方案

> 日期 2026-11-15。本文定义实现与验收要求。开发前对照当时的工作区、分支和测试结果更新基线记录。

## 1. 建设目标与产品决定

1. **导演模式是唯一工作台。** 项目管理、素材中心、视频生产和成片库在同一套导航里。左栏保留「基础配置」，新增「高级设置」。下线专业模式切换、原四板块页面和右上角独立的「检查真实制作环境」向导。
2. **环境只在「基础配置」整备。** 新用户可以先导入文本，也可以在空项目列表时先配置机器。页面提供「一键准备」「选择检索目录」「重新检索」。固定清单内的检索、复用、下载、安装、登记、绑定、启动和验证由后台连续完成。普通用户对本次整备只操作一次。
3. **准备资源和运行生产按真实依赖推进。** 导入与编辑可立即进行。文本、图片、视频、后期分别读取自己所需的能力。缺显卡、少一份权重或某个审核模型失败，由对应的工作报告原因，其余可做的工作继续。
4. **作品确认集中在作品内。** 环境配置的一次操作覆盖环境整备。稿件定版、冻结风格、采用新主素材和艺术验收沿用作品已有的版本与授权，能在同阶段完成的集中确认。确认后自动接续制作。
5. **正式视频只走本机 ComfyUI + MiniMax-H3 多参考 Ref2VA。** 使用实际已注册的 WorkflowProfile、parameter_map 和可用参考。H3PromptCompiler 负责生成提示词。无可用参考的镜头按现有契约具名处理。Mock、真实小样、正式出片和人工验收各自出具证据。

本方案接续 [V4.1 一站式整备方案](SHINE_SETUP_ONE_STOP_V41_DESIGN_20261114.md) 与 [2026-11-15 生命周期与依赖整备验收](ACCEPTANCE_20261115_SETUP_LIFECYCLE_DEPENDENCIES.md)。本轮对旧入口的兼容限于链接迁移，旧入口统一落到导演工作台。

## 4. 本机统一检索与复用

### 4.1 检索顺序与目录覆盖

1. **快速返回已有事实。** 检查已登记实例和模型目录、用户保存的检索目录、现有 `SHINE_COMFY_PROBE_ROOTS`、部署目录、PATH、便携安装、已知缓存，以及 ComfyUI 声明的本机模型根。识别缓存中实际的模型字节。已有实例的机器也要能发现后来拷入的资源。
2. **后台深搜每块固定盘。** 由磁盘根分批检索，有独立的进度与覆盖范围。按常见 AI、下载、模型和工具目录提优先级，其他可读数据目录接着查。对超时、访问失败和跳过的区域记录可读原因。分批任务可继续扫描，早期没有结果时显示「检索中」。
3. **支持用户指定任意本地目录。** 复用 [Windows 原生目录选择器](../backend/shine/media/directory_picker.py)，支持添加多个目录、中文与空格、直接粘贴绝对路径、删除记录和定向重扫。目录可以是磁盘根、下载目录、单独的 models/custom_nodes/workflows 或工具目录。检索目录、安装目录和成片输出目录分别存储。支持用户显式选择本地外置盘。
4. **限制无关 I/O。** 系统保护区、无关缓存、网络路径和自动发现时指向范围外的链接跳过并报告。用户可选实际本地目标路径。对重解析点、目录别名和循环路径做去重。低优先级探测分批让出执行时间，打开页面或刷新状态时复用上次结果。

### 4.2 资源识别与合并

| 资源 | 发现与确认依据 |
|---|---|
| 工具和软件 | 从 repo 已声明的工具清单、必要运行依赖及支持的查找位置得到候选。只在所需阶段自动调用明确识别的工具探针，核对版本和可运行性。 |
| ComfyUI | 支持源码、便携整合包及受管安装的实际布局。识别源码版本、解释器、可用节点包、声明模型根与本地端口。对外部正在运行的实例只读发现，受管生命周期沿用进程归属证明。 |
| 模型权重与分片 | 对所选能力的固定清单做候选筛选，先用名称和字节数定位，再按大小匹配可能改名的文件。只对候选做 SHA-256，整组组件齐全后登记。跨盘复用、重复路径和同一摘要去重。 |
| 节点与运行包 | 查找独立节点包、已安装节点、wheel 缓存和清单对应的已下载压缩包。目录名是线索，实际修订、已支持的依赖闭包和加载结果是安装及使用依据。未知节点仅展示发现记录。 |
| 工作流 | 读取可识别的 ComfyUI API 图。已有标准图用图哈希确认，按真实节点、输入和传输声明校验。自定义图由高级设置提供映射，验证结果回到同一台账。 |

扫描元数据和已确认摘要存入本机 SQLite 或现有索引。文件身份由卷或规范路径、大小、修改时间等可读事实决定，变更后重新核验。跨多个根挑选有效资源，优先复用已有绑定及可用缓存，再按已核验的本地路径登记。多套安装都能用时默认采用已有且匹配的受管实例，其次按能力所需资源的完整程度选定。其他候选可在高级设置中查看。需要复制时计入磁盘预算并沿用受管的原子写入，原安装目录作为只读来源。选定范围未扫描完的文件显示「待核对」。正式确定缺项后才发起对应大文件下载。

## 5. 权威能力状态和后台整备

### 5.1 事实和接口

- 以 `setup_summary` 为现有聚合点，复用设备探针、安装实例和文件台账、LLM 检查、图像证据、H3 profile 准入。所有读接口获得同一评估下的事实。可把 `/setup/verdict`、`/system/status`、素材中心能力接口和开拍检查保留为各自调用方的投影，清理重复条件和前端绿灯推断。
- 快照至少暴露搜索范围及完成度、资源来源和缺失项、所选能力与变体、配置与验证证据、当前任务进度、原因码和可操作目标。区分「已找到」「已核验」「可运行」「已真实生成」。磁盘中存在文件的事实独立于显卡是否当前可用。
- 查询快照不触发深搜、全量哈希、安装或启动渲染器。后台更新事实，页面统一订阅或轮询。记录实例、清单、图与配置指纹；真正变化时只失效受影响的证据。相同事实版本和作品上下文应得到相同结论。
- 运行时仍在实际动作前核对所需能力、当前身份、GPU 占用与请求约束。部署、文本、图片、H3、后期和辅助审核的原因按实际依赖返回。比如图片不可用时，已有合格参考素材的 H3 项目可以开拍。

### 5.2 一次操作触发本机任务

沿用 `/setup/prepare/execute` 作为唯一用户整备入口。预览与执行共用同一个解析器。页面可在按钮旁展示选定能力、复用量、缺失量、安装位置及必要的 GPU 验证。点击后由后台按以下顺序收敛。

1. **记录意图。** 任务保存所需能力、选定目录、有效清单范围和安装位置。重新打开页面可找到同一任务。同样的意图返回已有活动任务。改变目录或档位时新任务有自己的身份，对仍在跑的任务有显式等待或可取消状态。
2. **生成差异计划。** 合并所有已找到的候选，验证可复用文件，列出精确缺项与新增字节，锁定清单修订和安装目标。H3 采用已支持且满足实际设备条件的默认档位。对当前作品已固定的方案，按版本约定处理变更。
3. **下载及安装。** 复用已有 InstallationPlan、InstallationAttempt、内容缓存和受控下载器。整备记录驱动内部逐文件授权、断点续传、校验和登记。对可恢复的网络失败做有界重试并使用清单已有镜像。后台继续负责已选择的能力，逐文件审批、手工绑定和手工激活从普通路径移除。
4. **配置及绑定。** 复用实例生命周期、recipe 生成、工作流登记和图片绑定。实例 ID、端口、catalog、variant_id、recipe 指纹和工作流图应来自同一计划。覆盖非默认端口、外部端口占用、选定变体的实例创建和旧实例复用。
5. **验证及启用。** 使用运行时控制与同一 GPU 租约排队启动、验证并释放进程。复核通过后自动启用。用现有生命周期调度协调受管实例，解决验证任务遇到活 Worker 的互斥。生产在途时验证等待，等待步骤让出调度。真实小样由实际执行者持有和释放租约，整备任务用样例 ID 等待结果。进程消失或提交结果不明时先对账，保留提交身份与现有任务证据。
6. **保存结果与恢复点。** 每步提交可复查结果。重复点击、关闭网页、Worker 重启和机器重启，均从第一个未完成步骤继续。采用带版本和租约校验的任务更新，重活和网络 I/O 在短写事务之外。运行前按当前身份核对。失败落到具体能力、文件或安装实例，其他独立能力照常推进。

用同一个 SQLite 持久化机器级能力与作品级映射。设备检索、下载、安装和验证可在空库完成，随后给新作品幂等绑定标准 profile。现有 `InstallationPlan.project_id` 非空依赖需要可迁移的机器级归属表达，避免用临时作品承载机器安装。评估现有 `AppSetting` 单任务存储能否提供任务历史、租约和恢复；需要变更时随 Alembic 迁移并测试旧库。已完成的项目版本、资产和交付件继续按原 ID 访问。

### 5.3 使用边界与自动恢复

- 一键整备的本机行为包括下载固定资源、绑定并验证。已选择的能力后来丢失可由原范围内的整备自动补齐。播放器、素材中心、开拍页等仍走统一任务，显示等待原因和原进度。
- 下载预算看需要落盘的文件、暂存空间和可用空间。对单纯准备资源复用现有策略资源整备和下载台账，实际显存、内存、驱动与生产资格在选档及运行时生效。GPU 忙显示排队。系统盘安装沿用 2026-11-15 的显式选择与 180 GiB 要求，把位置选择放在同一页。搜索和登记已有文件按实际所需空间处理。
- 对本机环回调用沿用个人工作台的身份与后台校验。模型源、节点或运行包从可追溯清单取得。仅验证本机可用性时用本地测试资源。外部上传与云端文本处理沿用已有的项目授权，凭据由现有 SecretStore 管理。需要用户提供的外部凭据或系统级操作，在对应条目给出明确下一步。
- H3 或图像提交是否已被外部接受不明确时，使用现有 attempt 与 prompt ID 查账。已证实未提交的失败按原策略恢复，已确认的输出复用，需人工决策的未知结果进入可处理状态。

| 图生图、局部修订 | 使用同一个图像运行环境。逐项核对 I2I、INPAINT 所需节点和输入，使用项目自有的测试底图及遮罩自动提交真实小样。 | 每个模式自己的真实证据。局部修订检查尺寸和遮罩合成。样例走第一张样图允许的验证路径，归入测试证据。 |
| H3 视频 | 选择已支持的多参考 Ref2VA，准备实际变体所需权重、ComfyUI 节点及 API 图。根据注册图提供图片、视频和音频槽位预算，匹配参数及 media_transfers。 | 版本、文件、实例、节点合同与运行证据相符。首次或关键指纹变化时按需在后台安排真实试镜。W6A8、NVFP4 等候选须有目标机器验收后才可纳入默认路径。 |
| 后期与交付 | 复用 FFmpeg/FFprobe、字幕和现有音视频合成与交付流水线。 | 真正的文件完整性、音视频探测与解码结果，输出采用正确的项目及版本。 |
| 可选配音、ASR、VLM | 按用户选用的功能登记或补齐运行时，走同一文件和能力台账。 | 可选任务如实记录可用、失败或待验证。辅助审核不给 H3 或交付增加依赖。 |

图像生成和 H3 可以共享已验证的 ComfyUI 基础组件，按能力决定图、权重、启动合同和实际设备条件。只有图片能力的机器按其依赖完成整备，现有 Worker 要覆盖无 H3 实例时的创建与图片真实小样。已验证的图片证据按指纹复用，相同实例和图重复打开页面不会重新出样。非默认图像增强模式的现有入口消费同一台账，真实能力按实际证据启用。

## 7. 导入、素材与成片的接续

1. **文本可立即进入作品。** 保留上传原文与版本沿革。导入、阅读、手工编辑与环境准备并行。需要 LLM 的任务按工种就绪度运行，修订生成新版本。连接或格式失败定位到哪个工种和哪一场，并提供已有恢复动作。
2. **后台自动推进可用的剧本任务。** 复用导演旅程、分集方案和分镜编排。在分镜需要引用真实槽位前自动绑定标准 workflow profile 并读取实际预算。暂缺 H3 的机器可继续处理文本和草稿，依赖实际渲染合同的动作等待对应能力。
3. **分镜之后准备素材候选。** 自动采用已确认且匹配的素材，按分镜补齐需要生成的候选，用户在作品页集中采用新主素材。镜头能用的参考由实际绑定决定。缺主素材时说明角色、镜头或槽位，独立镜头继续。
4. **一次确认接续生产。** 导演包由已定版的作品状态生成。把同阶段确认收进「确认并继续」或「确认并开拍」，向现有 ProductionRun、ProductionSeries 和 Worker 交付。后端根据确定的输入版本继续从未完成位置推进并自动合成。
5. **直接查看成片。** 生成的分集进入现有成片中心和成片库。技术交付和艺术验收分别记录。环境补齐后自动续跑的动作承接原任务标识。内容有变化时使用新版本开始明确的一次执行。

重点复现六镜穿测里的第二场 `LLM_FORMAT`。建立格式错误或已知失败的故障回归，沿用现有有界纠正，页面可从具体失败场次恢复。已有场次产物应被复用。因为环境待补而等待的项目也按原进度接续。

实现优先使用小步可提交的变更。每一步都要覆盖现有正常入口和旧数据。旧交付、项目、素材授权与固定版本依据现有标识迁移，新的登记和证据绑定只写新记录或相应的当前状态。迁移同时验证已有库升级与空库初始化。

后端按根目录 [AGENTS.md](../AGENTS.md) 的规定设置 `CODEBUDDY_SAFE_DELETE_ENABLED=0`，在仓库根按测试文件均分 **8 分片并行**，使用 `backend/.venv/Scripts/python.exe -m pytest <本分片测试文件> -q -p no:cacheprovider`。记录八个退出码及日志路径，全部退出码为 0 且各日志无 `FAILED` / `ERROR` 行才算通过。定向覆盖环境检索、整备实例、能力准入、安装恢复、图片、导演旅程、连续生产和发布入口。按变更范围执行 Ruff、Alembic 及仓库要求的 offline E2E、Worker 和质量回归。若改动涉及 `client_review_identity`，按项目规则核对需要重新发布的 VLM 校准证据。

验收报告逐项列出分支、提交、命令、日志、测试机条件和结果。自动化、模拟、真实装机、真实推理与人工验收分别写明实际证据。硬件、外部来源或凭据导致暂时无法运行的场景，记录未完成项、阻断对象和继续执行所需条件。源文本、权重、真实产物、密钥、数据库和私有验收数据留在本机。
