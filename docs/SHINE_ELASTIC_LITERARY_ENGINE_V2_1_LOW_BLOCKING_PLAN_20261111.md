## 0. 架构最高约束：不能重演 Tavo-mini 的 JSON／校验／重试停摆

**正式原则：文学内容优先，机器结构从简；允许非关键局部不完美，不允许全局无故停摆。**

Tavo-mini `storyMemoryMainlineReconciler.ts` 曾记录：HTTP 200 的有效模型回答因 chapterSummaries 与 mainlinePatch 分类不一致而陷入 `MEMORY_CHECKPOINT_SCHEMA_INVALID`、有偿 Repair/Fresh Retry，最终 fail closed。Shine V2.0 借鉴其原文证据、时间边界、结构化事实，但**不得照搬多重 JSON 合同、多级强制校验和层层修复**。

六项不可突破的工程红线：

1. **最小外部 JSON**：LLM 输出合同只包含本次任务运行所必需的信息。复杂权威记忆模型由 Python／数据库在内部构造；禁止把整套数据库事实 schema 当作单次 LLM 输出 schema。
2. **五维共用一次观测**：人物、关系、主线、线索、伏笔属于同一批剧情事实的五个检索维度。不得为每一维强制创建一个串行 LLM 任务，也不要求每个片段五维都有数据。
3. **收到有效内容先持久化**：完整收到且具有实质价值的内容可以先保存为**候选草稿**。格式错误不能自动使正文消失；但候选草稿**绝不等于通过验收、事实入权威库或用户批准**。
4. **问题分级、局部传播**：可选字段、摘要分类与措辞问题仅 warning；局部数据缺失只影响当前单元及其依赖；源文损坏、核心事实冲突、越权、UNKNOWN 等仅阻断必要范围。
5. **有限修复且不可循环套娃**：整个逻辑单元的预算统一限制修复轮数、外部请求次数、Token 和成本，含格式修复、语义复核、重试和补记忆任务。任何模块不得另开自己的无限循环。
6. **不可静默删改文学内容**：不按字符串截断正文、不因 JSON 无效丢弃已收文本、不假设没生成的事实、不任意去重有意重复对白、不擅自换模型、不越过用户确认。

### 0.1 两种“完成”必须分离

- `content_saved`：已安全保存完整可辨认的文学产物（即使存在非关键格式问题），可展示、编辑、复核、继续使用合法前置内容。
- `accepted`：满足该阶段必需的来源、结构、核心连续性、覆盖与用户批准门禁，允许作为下游**权威输入**。

技术上不要把完整收到的草稿因为非核心字段校验失败标成 FAILED，更不能把尚未批准的草稿标成 `ApprovedSceneScript`。

### 0.2 故障判级表（唯一判级规则）

| 等级 | 典型情况 | 默认行为 | 允许下游? |
| --- | --- | --- | --- |
| `INFO/WARNING` | 缺非关键字段、摘要分类不一致、五维之一合法为空、可本地规范化的标点 | 保存候选成果；本地无损规范化；记录提示 | **允许**，前提是满足该下游实际必需输入 |
| `LOCAL_REVIEW` | 某段 JSON 不可解析但正文可辨认、单个非关键事实证据缺失、单个节拍未终校、人物关系存疑 | 保留候选正文；补索引/定点校验；仅标记该单元与实际依赖 | **只允许不依赖问题的单元**；不得把疑点当已批准事实 |
| `HARD_BLOCK` | 母本/跨度缺失、必需正文不完整、未获授权外传、角色身份/关键知识冲突无法消解、来源不合法、UNKNOWN 可能重复调用 | 具名暂停受影响的节点及依赖，保留其他成果；显示明确处理动作 | **不允许受影响链路正式确认/交付** |

所有 `HARD_BLOCK` 都必须写 `reason_code, affected_unit_ids, source_evidence, next_action`，且 UI 翻译成普通中文；内部错误码不直接作为唯一用户提示。

## 1. 工程基线及明确保留的能力

Shine 现有 `backend/shine/materialprep/story.py` 已有 EXTRACT→MERGE 与来源片段；`director/pipeline.py` 已有 SourceMaster／分卷／GlobalStoryBible／SceneScript、按场次任务、镜头分块、确认、`AgentArtifact`、租约防并发、`SENDING→UNKNOWN` 不盲重发；`llm/gateway.py`、`materialprep/agent_call.py` 存在预算计算不统一且 Gateway 在创作预检后再追加 Schema 的问题；现有 `_bible_snapshot` 固定条目截断缺乏事实相关性。

参考方案补强点：WP0 故障分诊；Call Governor 统一请求预算；非流式／流式能力探测、首字节／空闲／总时长分离；分层全局蓝图；节拍级持久化；调用台账、Worker 独立心跳、`off/shadow/on` 开关。

**不直接采纳**：流式收到了部分内容便断定上游已停止；断流即自动续写；用 JSON Schema 的最坏长度乘积当作日常输出目标；默认 12K/24K/49K 推理预算普适化；按拍数平均切割关键戏；截断超长正文或随意对白去重；把删除逐段摘要当作无损压缩；V2 升级让 V1 未完成任务不可执行。

外部 LLM 使用原有授权、Provider 路由、模型 pin、真实设备资源槽；MiniMax-H3 仍是唯一视频生成核心。V1 已入队任务按 V1 契约可运行和审查；V2 不改写其请求身份。

## 2. 总体分工：一个内容调度器、一个记忆库、一个调用治理器

```text
Web 四阶段（用户仍然只看见：文本导入 → 大纲 → 剧本 → 分镜）
      │
      ├── Literary Scheduler：拆分、DAG依赖、节拍提交、成果拼装
      ├── Five-Dimension Memory：一份事实库、五种视图、时态检索和局部校正
      ├── Literary QA：L0 确定性校验 → 只在疑点出现时 L1 语义校验
      └── Call Governor（共享唯一请求治理接口）
             ├─ 完整最终消息编译 / 上下文预检 / 动态 completion 上限
             ├─ 传输能力与超时控制 / Provider adapter
             ├─ 尝试台账、Worker 心跳、UNKNOWN 对账
             └─ 统一修复/调用次数及成本上限
                        ↓
                  现有 LLM Gateway → 五工种分镜链 → H3 正式制作
```

**避免循环依赖**：记忆更新是候选草稿的**旁路归档与校验**，不是剧本生成本身必须成功的“第二套阻断流水线”。文学调度器只读取权威记忆快照；生成失败不覆盖快照，记忆观测失败可在本轮之后补偿；关键事实缺失时只阻断“需要该事实证明”的确认／交付门禁。

## 3. 四阶段详细合同与异常回退

| 阶段 | 业务产物与来源 | LLM 的最小要求 | 记忆工作 | 失败策略 |
| --- | --- | --- | --- | --- |
| ①文本导入 | SourceMaster（不可变）、段落/章节/卷候选、SourceSpan 索引 | **不必调用 LLM**；程序确定性建立来源范围 | 只建立证据锚点与可搜索索引 | 标题缺失 → 智能分片；任一来源范围缺损 → 阻断受影响范围 |
| ②故事大纲 | OutlinePart、分卷大纲、GlobalStoryBible | 沿用原简洁提取契约；可附加**有限、可选**的剧情观测 | 以同次提取事件构建五维候选事实，不再独立全书五次抽取 | 观测不合规 → 保存大纲、标记 `memory_pending`；必要时仅补关键事实，不重做大纲 |
| ③剧本编写 | 单个完整 SceneScript 草稿；长场由 Beat 候选拼装 | 正文为主，元数据最少；代码从来源与节拍计划生成 ID、范围、版本 | 写前加载相关权威事实；写后记录候选变化，局部查验 | 正文完整但可选元数据缺失 → 本地补足；节拍失败仅锁住依赖的合成和确认 |
| ④分镜编写 | 已确认剧本→现有五角色分镜链→镜头组草稿 | 不增加第二套冗长分镜 JSON | 按场检索角色/线索/伏笔的视觉约束；输出后定点核查 | 单镜或镜头组问题仅影响该场/下游确认；其他场继续 |

**范围与批准门禁不变**：全局蓝图的确认、剧本版本确认、正式分镜确认、素材和 Style Bible／H3 生产准入必须严格独立。`draft complete != approved != production-ready`。

### 3.1 S2 记忆提取不能成为新的大纲 JSON 累赘

首选沿用当前大纲提取生成的正文和原有 `OutlinePart`，在**任务成本允许**时增补很小的 `observations[]`。若 Provider 不擅长复合 JSON、Schema 严格或生成变慢，则只生成原大纲，随后从**本地已有大纲＋原文证据索引**提取高置信候选；对影响确认的重要事实再使用**单次、单范围、短输出**的补充提取。

绝不要求一个 SourceSpan／章节一次成功输出完整人物档案、人物关系网、长篇主线、所有线索和伏笔的巨大 JSON。五维合法为空，不为空时必须能验证来源。摘要文本可作为检索线索，不可倒灌成为权威事实。

### 3.2 S3 场次剧本生成合同精简

对模型的最小概念输出可用一个短信封表示：

```json
{"scene_id":"S003","content":"完整场次剧本文本","continuity_out":"本场结束后的关键状态"}
```

**这仅是设计示意，不是直接替换现有 API**。真实迁移由 `SceneScriptAdapter` 保留原有 `SceneScriptPayload`：`scene_key/section_id/source_refs` 等来自服务端可信任务定义；`characters`、`dialogue` 等能无损从脚本提取或本地可推导时才填充；不可推导则标记待补，不凭空制造。必须满足现有 `SceneScriptPayload` 必需的完整剧情/对白与批准门禁后才晋升为已确认成果。

按情节语义切拍；各拍输出限额由事件复杂度、对白量、场次重要性分配，不平均分配固定字数。每拍完整文本先保存，逐拍 `continuity_out` 接续；若上游拍失败，下游已生成拍保留原稿但标记依赖待校验，不视为直接通过。场次拼装时保留所有对白及有意的重复台词；正文超出合同上限时重新分段或调整授权的合同边界，**绝不截断**。

### 3.3 S4 分镜只消费精简记忆视图

剧本是分镜的权威叙事输入。五维记忆只提供当前镜头必需的**身份、时点、物品线索、人物认知、画面不能提前泄露的秘密**，按 Token 预算选取；主线全文/全书人物档案不能塞给每个五角色 Agent。复用 `api_film.generate_storyboard` 等既有路线及实际校验契约，优先确认真实调用形态，不凭文档猜测。

## 4. 五维故事记忆合同：内部可丰富，外部必须简单

### 4.1 内部五维事实索引

- **人物**：稳定 ID、姓名/别名、身份、外观/衣着、当前位置、当前目标、知识、持有物、生命状态；支持时点状态。
- **人物关系**：两端人物 ID、方向/类型、公开/隐藏、信任与变化、人物各自认知。
- **故事主线**：事件 ID、目标、因果、冲突、转折、叙事顺序与世界内时间顺序。
- **故事线索**：信息/物品 ID、发现者、当前持有者、已获知者、证明过程、关闭条件。
- **伏笔**：埋设点、关联线索、允许揭示的时点、兑现事件、状态（open/partially_paid/paid/unknown）。

**一个事件只记录一次**，通过 `dimensions[]` 或索引关系映射到相关维度。不得对同一个账册发现事件产生五套彼此独立的权威副本。

### 4.2 LLM → Memory 的最小观测合同

LLM 只需描述**本次出现或发生变化的事实**，例如：

```json
{
  "observations": [
    {
      "kind": "discovery",
      "subjects": ["甲", "账册"],
      "statement": "甲在酒馆发现账册的残页",
      "evidence_span_ids": ["S12#p3"]
    }
  ]
}
```

不强制模型生成稳定 UUID、全局版次、source sha256、事实生效闭区间、人物已知全集、置信分、资产关联、审批状态等字段；这些要么由服务端可信输入生成，要么另存为未决候选。原文来源由服务器解析 `evidence_span_ids` 为当前文档 sha256＋绝对 offset＋引文 hash，并检查确实出自对应片段。不能验证的观测保留候选/排除权威合并，**不必废弃同一批完整大纲正文**。

### 4.3 最少持久化实体与单一事实权威

优先复用现有 `AgentTaskRecord`、`AgentArtifact` 和现有文档、来源范围及审计。新增持久化结构按必要性精简：

- `story_memory_facts`：包含事实 ID、project、事件/实体关联、五维标签、时间、证据、权威与版本；写入追加/取代，不原地删除原著事实。
- `story_memory_revisions`：候选观测→已确认事实的原子补丁与审计；不另造五套 patch 系统。
- `story_memory_snapshots`：权威快照 ID/hash、适用的剧情时点、来源和上游版本；可按增量重建，无需在每场复制全部事实。
- `llm_call_attempts`：新增或扩展已有任务 trace/审计，以记录每次物理请求、预算、耗时、网络结果和恢复信息；先评估当前 DB 表与迁移避免重复建表。

`literary_units` 可优先建为现有任务／工件的轻量扩展，只有现有关系不能稳定表示 DAG、Beat 依赖时才新增表。`QA Findings` 可先作为有版本的 `AgentArtifact`，不必在一期为每项概念都新增一张数据库表。大文本采用文件/工件存储，不在每条 trace JSON 里复制整段原文或全文快照。

### 4.4 权威来源与时间边界

`origin`: 原著明示（source_fact）／用户已确认改编（approved_adaptation）／AI 候选（ai_proposal）。

`visibility`: 观众已知、人物已知、仅编导内部知晓；叙事顺序和故事世界时间分离。场景写作必须按目标场时点和 POV 过滤；允许显式授权的戏剧性反讽，不允许演员台词凭空提前知道秘密。草稿记忆**可以展示及供同一草稿自检**，不能成为其他已确认场次的权威。

## 5. 智能检索：一份事实，多维视图，一次查询

最小查询：`retrieve(project_id, snapshot_id, scene_id, event_position, pov_ids, source_span_ids, token_budget, purpose)`。

返回 `context_text`（简短、已裁剪到预算）、`fact_ids`、`evidence_refs`、`warnings`。避免强迫消费者拼装五份庞大嵌套 JSON；高级诊断另存详情。

硬过滤：项目隔离、文档版本、权威快照、原文有效、事实时间合法、人物知识/观众知情边界。可检索分层：

| 层级 | 内容 | 行为 |
| --- | --- | --- |
| Mandatory | 当前原文及锁定事实、当前场的关键人物／认知、已确认剧本（分镜阶段）、最小输出要求 | **不删减**；超预算则拆分任务 |
| Preferred | 活跃人物关系、直接相关线索、伏笔揭示限制、前后场状态 | 按内容 relevance 及证据分配；关系+两端角色原子捆绑 |
| Optional | 久远历史、已闭合支线、远处人物细节 | 整条事实的预算裁剪，数据库事实不删除 |

第一版使用现有 SQLite 及确定性 ID/别名/事件检索；可选 FTS，**不在一期强制引入向量数据库、5 套独立检索 Agent 或多个语义索引平台**。

## 6. Call Governor：唯一预算、可观察传输、有限重试

### 6.1 编译完整请求再计算预算

统一 `CallPlan(profile_snapshot, task_type, rendered_system, rendered_user, schema, memory_context, source_range, output_target, safety_margin)`。**最终发送的请求应与预编译结果字节同源**，避免网关追加 Schema 后改变预算。已知模型窗口不足时自动缩小合法工作单元；未知窗口**不得默认假装 1M**，引导确认能力或保守小单元探测。

共享窗口时：

```text
O_hard    = floor(0.60 × verified_effective_output_max)
O_request = min(O_hard, ceil(visible_goal + measured_or_conservative_reasoning_reserve + format_overhead))
I_final + O_request + M_safety <= verified_context_window
soft = floor((window - O_request - M_safety) × 0.80)
burst = floor((window - O_request - M_safety) × 0.95)
```

上述 60% 是**硬上限**，不是每轮默认申请值；不可用时根据 Provider 合法配置/验证能力保守降级。推理 Token 未报告则标记 unknown，不得假造。Schema 的 maxLength×maxItems 只能做潜在风险检查，**不是日常生成的目标输出 Token**。

### 6.2 流式是可观测性优化，不是无限完成保证

模型／服务商经能力探测支持时，允许 StreamingTransport；采用 connect/read-idle/first-event/total-deadline 不同超时并记录真实事件与 usage。无可观察数据的深度推理阶段不能误判为 Worker 已死；**独立 Worker 心跳与网络事件心跳分开存储**。不支持 streaming 的模型安全回退非流式，避免以串流格式错误重复 POST。

远端部分响应断流：保存**最小必要片段**供诊断/授权续作，记录可见状态 `PARTIAL_RECEIVED`，**但 external_outcome 仍为 UNKNOWN**，除非服务商有可核查的终态或明确的客户端终止证据。不得将“有字节”推论为“服务端已停止并且可以安全重发”。若确需续写，为**新请求／新尝试**并考虑重复计费，必须符合用户预授权及审计。

### 6.3 恢复和费用上限统一

- `NOT_SENT_PROVEN`：本地预算、格式预检、连接未建立，允许有限重排、拆分、受限重试。
- `HTTP_429`：仅在服务商明确表示拒绝且具备安全重试语义时，按 Retry-After/退避有限重试，记录所有物理请求。
- `RESPONSE_COMPLETE_BUT_INVALID`：先保存有价值的候选正文，再**无损**本地修格式；无法修复的必要字段才进行单元级定点重做，禁止整部长文重发。
- `TRUNCATED`：不足以生成完整文学内容时需要重划单元或显式续写；绝不“截断到句号”假装通过。
- `UNKNOWN`：先尝试唯一工件采纳／服务商状态对账；无人类或明确事先授权不得重新 POST；不阻塞无依赖任务。
- 所有重试、纠错、拆分和后置语义 LLM 复核共享 `max_calls_per_logical_unit`、`max_repair_rounds`、`max_completion_tokens_spend`、`cost_cap`，触顶后局部 `NEEDS_REVIEW`。

## 7. 智能拆分与依赖传播：避免一个节拍拖垮所有场

层级 `SourceMaster → Volume → Episode → Scene → Beat → ShotGroup`。先按原文自然章节／事件／幕／场边界切；按预算不足或预估超时动态下钻；强制硬切时必须保留源区间和断裂说明。输入必须覆盖计划范围；用户批准删改必须有 `excluded_ranges` 记录。

每个 Beat 在现有任务体系中以稳定 source hash、parent、ordinal、prompt version、memory snapshot hash 和模型 pin 建身份。每拍产生候选正文、可选增量记忆和 `continuity_out`；一次完整场次通过合并器构造完整 `SceneScriptPayload`。**前拍失败不会删除后拍已保存候选，但依赖上一个收尾的后拍不可被误判为已确认有效**。可安全并行的独立章节/场次继续；受影响的连锁节点沿 DAG 精准标记 `WAITING_DEPENDENCY` 或 `STALE`。

蓝图生成：先用确定性概要和五维事实摘要压缩，保留 `event_ids/clue_ids/foreshadow_ids/source_coverage`；按预算分层合并 `VolumeDigest`，增量重算受影响分支。不得为了省 Token 静默删除对当前剧情有作用的关键事件/伏笔；压缩溯源索引必须可回查。

## 8. 文学 QA：默认不让 LLM 的判断控制调度器

两级校验：

**L0 本地确定性**（优先）：数据所属项目/版本、原文跨度、已确认事实和历史时点、角色别名、依赖链、分镜镜头覆盖、剧本全文存在性、镜头承载对白的可验证覆盖。只要能本地证明，不另外付费调用 LLM。

**L1 定点文学语义**（出现疑点时才调用）：本场角色性格、关系走向、主线因果、线索掌握、伏笔揭露风险；最小输入是当前疑点＋相关证据＋必要正文。输出短报告；只认定为“审查建议”，不能自动改动已批准的关键叙事。

**QA 的失败不自动导致正文重生成**。无关摘要分类、弱语义意见或 L1 JSON 格式问题，降级为 `QA_PENDING/WARNING`；绝对关键事实、原文遗漏、泄密、分镜覆盖缺失才阻断对应场或正式交付。预设一个 QA 逻辑回路最大轮数，不允许 `writer→validator→repairer→validator→repairer` 无限制循环。

## 9. 真实断点恢复与版本兼容

- 完整回答收到后先本地持久化候选原文/元数据和 hash，再尝试后续 JSON 格式校验/记忆入库；持久化必须遵守项目隔离及隐私/外传授权。
- Provider 请求开始前事务落库 `SENDING` 意图；Provider 调用期间不持有 SQLite writer。完成工件与当前任务状态可原子提交；崩溃后采用相同输入身份和内容 hash 对账唯一工件，不二次发起不明结果请求。
- Worker's `lease_owner/state_version` fence 保持，租约续期由独立心跳驱动，不依赖是否收到 SSE Token。过期接管只允许尝试恢复和对账，不代表安全重发。
- 校准探针、流量统计和 ETA 缓存不能改变旧 `request_identity`；真实改变 prompt/schema/拆分范围/Provider 选择时必须写新版本 Attempt 或 Unit。
- V1 已入队和已确认数据保留执行／读取路径；新项目或新任务按 `off/shadow/on` 分阶段切换。`shadow` 仅计算与记录新策略，不改变用户请求、不额外付费生成。
- 失败节点必须有用户能理解的下一步：如“第3场已保存，但第2拍未能完成；可以重新处理第2拍或查看原因”。

### 10.1 必须纳入自动化测试的“反向断言”

1. **有效内容保护**：模拟模型返回完整但结构不规范的剧本，正文候选必须可查看；不得因为非关键字段导致全任务 FAILED。
2. **不能假通过**：仅有正文候选但丢失必要身份/来源/覆盖时，不得自动确认剧本或正式分镜。
3. **五维为空合法**：环境转场片段五维均无新增信息时，不能因此重做或 fail closed。
4. **五维更新不影响大纲本身成功**：记忆观察字段无效但大纲有效时，大纲候选保留并允许补记忆。
5. **修复费用硬限**：外部 Writer＋QA＋Memory 的所有尝试合计受一个逻辑单元的预算限制；费用耗尽必须局部停，不循环。
6. **异步依赖隔离**：第3拍失败时第1、2拍保留，第4拍若依赖第3拍则标记待核验；独立场次继续。
7. **UNKNOWN 不可自动重试**：断流、有部分 SSE 字节或 Worker 过期不自动发第二个 POST；唯一已存产物被正确采纳。
8. **原文/伏笔完整**：蓝图归并后 source coverage 与关键事件/线索/伏笔引用可追溯；漏掉关键事件不得通过正式确认。
9. **全生命周期版本**：旧 V1 已入队任务继续按 V1 行为运行；V2 的 shadow 不改变请求及权限。
10. **UI 阻断可执行**：对每个 hard blocker 给中文原因、受影响单元和明确的操作出口。

### 10.2 三层测试，避免测试本身成为停摆源

- **L1 快速测试**：纯函数、预算、Schema 适配、记忆时态、依赖与 QA 规则；常规提交执行。
- **L2 集成故障注入**：Fake Provider 返回 200/错误 JSON/部分正文/429/截断/慢事件/断流，SQLite crash/fence/迁移；每个工作包验收执行。
- **L3 真实 LLM 与 Windows Web**：只在里程碑、用户明确授权或合并前执行有费用上限的真实模型测试。真实 H3 是另一个生产准入关卡，不用其资源占用干扰文学基础测试。

## 11. 给本地/云端 Codex 的实施纪律

- 先读最新 `main` 并复核差异，以当前代码为准；本设计描述的是**目标契约**，不是“已实装”。
- 每个工作包一个可审查变更集；独立 feature flag 和契约兼容测试；**不自行删除旧测试以换取全绿**。
- 不得把五维记忆扩展为五套 LLM 强制子流程，不得在每个 Agent 之间复制全量 JSON。
- 如模型响应格式失败，首先判断是否已收到完整实质内容、是否可安全本地修复、是否影响**必要**合同；不得默认进入付费整轮重试。
- 不得把新记忆事实未经人类批准晋升为权威，不得把候选产物当正式交付。
- 不得把 SSE 断流或 lease timeout 当作上游取消成功的证据。
- 记录真实命令、实际运行结果、PR 及 commit；没有运行的测试写 NOT_RUN；不要“模拟 PASS”。

## 12. 来源与差异说明

### 12.1 对原《Shine Elastic Literary V2》方案的实质修订

- 原先为每项记忆 fact 建议了较厚的 LLM 数据合同，现在将它保留为**内部事实模型**，外部 LLM 只返回最小观察；事实版本、项目、证据 offset/hash、审批状态由本地生成。
- 原先 `ExtractObservation → Validate Schema → ...` 是过于强顺序依赖，改为大纲／剧本**先保存可用候选内容**，记忆抽取可降级为旁路、补偿或定点审查。重要事实仍在正式确认之前验证。
- 原先新增约 9 张表的建议过重，调整为**复用现有任务/工件，新增极少数具有明确价值的事实、修订、快照与物理调用记录**。
- 原先 QA 的所有 hard findings 都可能逐层阻断，现在定义了三层错误分级及“只阻断必要范围”原则。

### 12.2 对外部《SHINE_FOUR_STAGE_LLM_GOVERNOR_PLAN》的吸收及纠正

**吸收**：WP0 分诊、Call Governor、完整 CallPlan、流式能力探测、三段超时＋总时限、蓝图归并、Beat 持久化、CallLedger、独立心跳、off/shadow/on、可运行的故障注入矩阵。

**纠正**：`PARTIAL_RECEIVED` 并不能证明服务商已停止；Schema 最大字段长度不当作输出目标；不截断文学正文/不机械去重对白；Beat 字数按情节分配不等分；归并必须保留来源事件及五维线索；V1 未完任务不得只“可读而不可续”；校准不得破坏任务 identity，但真实输入变更必须有新尝试版本。
