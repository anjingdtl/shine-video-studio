# Shine Video Studio 普通用户交互收束建设方案

日期：2026-11-02。状态：**待本地 agent 实施；本文件不是实现或验收报告**。

源码基线：`main` / `6049bb8f21b5619f1e783e34a57f4540295b023b`。
适用对象：不知道 ComfyUI、节点、工作流映射和模型部署细节的 Windows 桌面用户。
配套执行提示词：[LOCAL_AGENT_UI_SIMPLIFICATION_PROMPT_20261102.md](LOCAL_AGENT_UI_SIMPLIFICATION_PROMPT_20261102.md)。

## 1. 本轮结论与范围

把工作台从“展示工程能力的控制台”收束为“引导用户完成作品的工具”：**系统检测、用户选择、AI 提建议、后台自动执行已授权步骤**。

必须完成用户提出的四件事：

1. 左侧导航按内容自然排列，缩小组间空白，同时保证文字与点击区域可读。
2. 新机页先回答“已有些什么、基础环境够不够、接下来做什么”，不要求理解部署工程术语。
3. `02 / STYLE BIBLE` 改为中文“作品风格”：整套预设下拉 + 七项可选设置，默认无需手写专业描述。
4. 其余生产内容优先使用真实数据驱动的选择器；配置并验证相应 LLM 能力后，提供可预览、可编辑、由用户采纳的 AI 推荐。

保留现有“设置 / 生产 / 交付 / 专业”四个板块及深链。主流程不再重复展示高级环境管理；专业能力在对应的高级入口保留。此轮不重建架构、不更换生成模型、不重新设计全部视觉品牌。

交互减少不能依靠删除检查、默认批准或更改历史数据实现。后端状态、授权、快照、版本、资源租约和审计继续生效。

## 3. 目标主流程与信息层级

首次使用：

```text
检测本机 → 查看已有模型与环境结论 → 必要时确认补齐 → 进入制作
```

每个作品：

```text
项目与剧本 → 素材确认 → 作品风格 → 分镜方案 → 开始制作 → 审片与导出
```

这是一条页面内的阶段导航，不再新增一个主导航体系。生产区顶部展示当前阶段、完成情况和下一步入口；交付仍属于现有交付板块，可从最后阶段跳转。允许返回修改草稿，不强制按向导锁死所有页面。

统一交互规则：

- 每个阶段一个醒目的主按钮；编辑、展开详情等用次按钮。
- 普通页每块最多一段简短说明；阻断时展示“原因 + 可执行的下一步”，技术错误码进详情。
- 默认模式不要求输入 JSON、UUID、哈希、节点名、Profile ID、资产 ID、租约或实例链参数。
- 固定枚举用下拉/单选；现有项目对象用可搜索选择器；少量布尔项用开关；创作内容保留文本框。
- 剧本、对白、镜头意图、人名和创作补充属于文本内容，不硬塞进下拉框。
- 优先预选“唯一且匹配、可用”的候选；存在多项时展示推荐标记和理由，用户可改；没有可用项时解释缺什么。
- 不用一份写死的“推荐值”冒充运行时能力检测，不自动选第一条数据充数。
- 保存失败、切换阶段、刷新列表时不清空用户未成功提交的草稿；切项目要隔离草稿和异步响应。

## 4. 左侧导航：紧凑但可读（P0）

### 4.1 布局合同

移除或重构末尾 `.nav-group{flex:1 1 auto}`，导航组使用自然高度（例如 `flex:0 0 auto`）。只让导航滚动容器占据侧栏剩余空间；正确设置 `min-height:0` 和 `overflow-y:auto`。空白允许出现在全部导航之后，不能分摊在四组之间。

桌面默认目标：

| 项目 | 目标 |
| --- | --- |
| 分组标题点击高度 | 36–40 CSS px |
| 子菜单点击高度 | 34–38 CSS px；触控布局至少 44 px |
| 导航文本 | 13–14 px，行高约 1.4；不靠缩小文字压空间 |
| 同组子项间距 | 2–4 px |
| 组间净空 | 8–12 px，随内容高度布局 |
| 高度不足 | 导航区域独立滚动，底部状态不遮住菜单 |

默认展开当前板块的子项，其他板块保留可点击标题；用明确展开按钮支持查看其他组，不因切页产生巨幅留白。保持四板块、当前高亮、键盘焦点、老锚点和 `#setup` 安装器落地行为。窄屏不能只留下没有可访问名称的图标。

禁止只在文件末尾再补一串 `!important`。整理受影响的历史覆盖规则，检查暗色、现有字号缩放和媒体查询的共同作用。

### 4.2 视觉验收

1366×768 和 1920×1080、100% 缩放下截图测量组间距；长屏不拉伸四组，短屏可到达所有入口。另测 1280×720、窄屏和 125%/150% 字号缩放，允许滚动但不重叠、不裁掉文本或焦点。

## 5. 新机设置：先说检测结论（P0）

页面名改为“制作环境”；默认保留“检测本机”“已有模型”“环境结论”“下一步”四部分。首次检测不需要先创建项目；后续配置如确实需要项目，则提供就地选择/创建，不把用户赶去页底找入口。

### 5.1 默认界面样例

```text
制作环境                              [重新检测]
基础环境满足制作要求；还需验证生成服务。

本机已有模型
视频生成 · MiniMax H3       发现文件，待校验
画面检查 · <实际模型名>     未在已检查位置发现
语音检查 · <实际模型名>     已校验

显卡与内存：满足基础要求     安装空间：充足
生成服务：待验证             AI 助手：未配置（可稍后设置）

[校验并复用已有模型]
查看检测范围与详细结果 ▾
```

以上是文案/布局示例，不是这台电脑的实测结果。模型名、数量、状态和按钮必须来自本次检测。

### 5.2 模型盘点与状态合同

按用途分“视频生成 / 画面检查 / 语音检查”等，只展示实际固定清单及其探测结果。默认显示友好名称、用途、状态；路径、大小、SHA、版本、组件 ID 放详情。保留可查看完整清单的入口，不能只显示总数。

| 真实证据 | 普通用户文案 | 不得推断 |
| --- | --- | --- |
| 尚未检测或接口失败 | 尚未检测 / 暂时无法检测 | 没有安装 |
| 有界目录未发现固定模型 | 未在已检查位置发现；可选择其他目录 | 全盘不存在、必须重新下载 |
| 大小/文件名等发现候选 | 发现文件，待校验 | 文件正确、已安装或可生成 |
| 内容哈希匹配 | 已校验；标明是在源目录或缓存中 | 已登记、已加载、已通过真实生成 |
| 已安装并通过服务契约验证 | 服务检查通过，尚未验证出片（如适用） | 真实视频和五道质量关通过 |
| 本项目实际真实生产证据 | 曾完成真实生成；显示时间及是否匹配当前配置 | 新配置也通过、所有作品质量通过 |

硬件/磁盘、模型文件、服务配置、项目开机条件、真实出片证据分别计算。首页结论只能由结构化证据聚合：未知/过期/检测失败不得变绿；已有 ACTIVE 也不能独自决定“可以生成”。项目素材/风格未准备好时，应在制作阶段提醒，不把它说成机器没装好。

AI 文本助手、画面检查模型和语音检查模型分开显示：配置 LLM 不代表拥有 VLM/ASR。按当前项目策略判断必需项；可选项缺失说明影响，不一律阻断环境基础结论。既有政策要求的审片能力仍然必须满足。

### 5.3 下一步只给一个主动作

根据最新证据依次引导：检测 → 选择已有安装（只有多个或需手动指定时）→ 校验并复用 → 确认补齐及配置 → 验证服务 → 进入制作。已完成步骤不要求重新操作，不需要补齐时不出现“下载模型”主按钮。

检测只做有界只读盘点：不能启动第三方目录代码、加载大模型、复制模型、下载或接管现有 ComfyUI。服务验证另行说明并由用户启动。自动补齐继续使用固定版本清单、审批、快照和现有顺序执行链。

复制、下载安装前给出一张清晰确认单：来源/目标、可复用和新增下载量、复制额外占用与所需空间、将启动的服务、原安装保护范围。一次确认可以覆盖展示的固定计划及有序配置步骤；不重复索要密码/工程证据。复用复制若不能纳入同一明确授权范围，保留一次独立的复制确认，不能暗中开始。

目录/清单/配置/项目变更使旧确认失效；失败中止并显示当前进度，不能盲重试或重放不确定提交。进度使用“检查文件 / 复用已有模型 / 补齐缺项 / 检查服务”等中文，并允许查看日志。

保留当前有界扫描及 `extra_model_paths`/外部链接未覆盖的说明；不在此轮引入全盘扫描、读取任意共享路径或接管个人整合包。找不到时提供“选择已有目录”和“查看范围”。

## 6. 作品风格：预设 + 七项下拉 + AI 推荐（P0/P1）

### 6.1 默认交互

标题“作品风格”，说明“选一套风格，可调整细节；确认后用于新镜头”。`STYLE BIBLE` 等英文工程标签不作为主要标题。

默认展示：

1. “整套风格”下拉：自然写实 / 都市短剧 / 温暖生活 / 冷调悬疑 / 古风剧情 / 广告展示 / 自定义。
2. 一段人话摘要，以及“调整细节”可展开的七个下拉；无需填写七段文案即可保存。
3. “AI 帮我推荐”（满足能力条件时可用）、“保存草稿”、“确认并用于新镜头”。最后一个动作继续调用明确冻结流程，显示版本和作用范围。

首次可将“自然写实”作为待确认预设，明确显示尚未确认。已有草稿/冻结内容优先恢复，不能被默认预设覆盖。选择预设或下拉只改本地草稿；用户保存或确认前不得写入冻结版本。

### 6.2 七维选择器

| 原始字段 | 用户标签 | 首批下拉选项（示例标签；实现须配完整确定性规则文本） |
| --- | --- | --- |
| `photography_language` | 画面与运镜 | 稳定叙事 / 缓慢推进 / 克制手持 / 展示环绕（仅能力允许时） |
| `shot_blocking` | 人物与机位关系 | 清晰正反打 / 双人同框 / 单人聚焦 / 环境与人物结合 |
| `color_palette` | 整体色调 | 自然中性 / 温暖柔和 / 冷色低饱和 / 明亮清透 |
| `lighting_tone` | 光线与明暗 | 自然柔光 / 明亮低反差 / 低调有层次 / 戏剧侧光 |
| `lens_texture` | 画面质感 | 干净写实 / 柔和浅景深 / 克制胶片感 / 清晰展示 |
| `editing_rhythm` | 节奏 | 舒缓 / 均衡叙事 / 紧凑；对白保留必要停顿 |
| `sound_performance` | 声音与表演 | 自然对白 / 克制悬疑 / 温暖轻松 / 广告讲述 |

每项都支持“自定义”，选中后才显示高级文本编辑。保留原字段长度、空值及编译规则校验；不可用一个“电影感”标签替代真正可编译的七维内容。模板是产品风格建议，不是 H3 能力或质量认证。

首批六套整套预设必须全部展开为七个非空原始字符串，不允许运行时随意拼凑。参考“自然写实”的完整基准内容：

| 字段 | 确定性内容示例 |
| --- | --- |
| 摄影语言 | 以中景和近景叙事，机位接近人物视线；镜头稳定，仅在叙事需要时缓慢推进，避免无动机环绕。 |
| 镜头调度 | 保持人物空间关系和视线方向；对话正反打遵守同一动作轴线，走位服务于剧情。 |
| 色彩风格 | 自然中性色彩，肤色真实；同一场景保持主辅色和冷暖关系一致，避免过度饱和。 |
| 影调与灯光 | 使用有明确来源的自然柔光，保留阴影细节，跨镜主光方向一致，避免高光溢出。 |
| 镜头质感 | 干净写实，适度景深与清晰度；保留皮肤纹理，避免塑料肤质、过锐和突变颗粒。 |
| 剪辑与节奏 | 均衡叙事，按动作和对白安排切点；保留必要停顿，默认硬切，不为追求节奏截断对白。 |
| 声音表演 | 使用项目指定语言和已确认音色；自然语速、清楚对白、适量环境声，音乐不遮盖人声。 |

“声音表演”预设不创造音色主资产；实际声音绑定仍只引用用户确认的 Voice Profile/素材。这里的语言跟随项目设定，不硬编码覆盖项目语言。

### 6.3 数据与历史兼容

- 建立一个有类型的风格目录（稳定 ID、版本、中文标签、完整七维内容及目录 hash）；预设和选项映射只有一份权威数据，前后台需要时通过现有 API 风格提供，不能各写一份。
- 保存/编译继续使用现有 `StyleBible` 七字符串结构。优先通过适配层完成，不把 preset ID 直接塞进 H3 描述，不大改数据库 schema。
- 历史自定义文本无法精确匹配选项时，显示“自定义（原内容）”并完整保留；不能按关键词猜测后替换或清空。
- 必须保留选择后的原始快照；目录升级不能重新计算旧冻结版本。预设 ID/版本/hash 通过既有元信息/审计记录其来源，不污染七维正文；确需迁移时提供独立迁移及旧库回归。
- 选择一套预设前若已有本地修改，提供差异/覆盖确认。选择后显示“已调整”，不继续假装与整套预设完全一致。
- 冻结仍遵守“保存屏幕上实际七项 → 获取动作与快照绑定的一次性 grant → 提交 expected_style → 核对冻结结果”。用户看见的内容必须等于冻结快照。
- 修改已冻结风格产生新版本；说明只影响新镜头，旧任务和历史视频继续保留原版本，既有依赖失效规则继续执行。

## 7. AI 推荐：复用现有 Runtime（P1，必做）

不另建 LLM 客户端、密钥库、项目库或任务队列。优先复用 `/film-agents` 能力/路由、FilmAgentDispatcher、`StyleProposal`、AgentArtifact、现有分镜及剪辑提案链。

### 7.1 可用条件与按钮状态

“已配置”必须细化为：相关角色路由有配置、凭据存在、结构化输出能力满足、检测状态有效、必要输入已齐、用户同意当前请求的数据外发范围。无需查看图片的风格推荐优先只使用已授权剧本文本及项目设置；LLM API 配置本身不等于允许上传素材。

| 条件 | 交互 |
| --- | --- |
| 未配置对应角色或检测未通过 | 禁用推荐，显示原因和“去配置 AI 助手” |
| 缺少必要输入 | 显示“先导入剧本”等准确下一步 |
| 准备就绪 | 用户点击后请求，显示进度；页面挂载/轮询/切阶段不调用 |
| 返回有效提案 | 展示推荐值、理由、涉及的更改与版本，用户采纳后进入草稿 |
| 超时、无效输出、过期或结果不明 | 保留原草稿，说明结果；不拿内置模板冒充 AI 成功 |

允许无 LLM 使用预设和手工选择完成非 AI 流程。未配置 LLM 时，“自动分镜”说明不可用并提供手工镜头入口，不强制用户为了选风格配置密钥。

### 7.2 推荐、采纳和生产之间的边界

AI 推荐风格流程：点击推荐 → 调用现有 `style_proposal` → 对七维内容校验 → 展示逐项差异和理由 → 用户“采纳到草稿” → 用户另行确认冻结。

推荐返回自由文本与现有预设不一致时，按“AI 自定义建议”完整展示，不强制归类到最接近选项；需要限定枚举的推荐则必须校验选项 ID 在当前目录内。

异步请求绑定 `project_id`、输入/草稿版本指纹、相关资产清单、风格版本、规则包和能力快照。请求期间编辑、切项目或输入变化，返回值不能覆盖新草稿；可保留为“基于旧内容的建议”，重新采纳前校验。现有应用提案端点若缺少这类校验，应补最小服务端合同及并发回归，不能只依赖前端按钮禁用。

重复点击合并为同一在途操作；跨刷新使用持久任务/请求身份查询结果。一次 UI 点击可以包含现有分镜链所需的多次角色调用，但每次物理请求要可审计。对已发出后断开的 LLM 请求记录未知状态并对账；不自动重放。仅按现有允许的连接前失败/明确 429 或 5xx 策略重试，不增加隐蔽轮询生成或静默换 provider。

采纳不能自动批准素材、冻结风格、覆盖锁定剧情或提交真实生成；对应动作由用户清楚确认。AI 推荐工作流时只能从能力验证通过的现有项中提出建议，不能修改 checkpoint、mode、参数映射或制造已验证状态。

## 9. 开始制作的具体收束

单镜与多镜生产共用一个项目生产设置来源，不在 App 和 SeriesPanel 各维护互相矛盾的默认值。显示“当前生成方案：名称 · 画幅 · 尺寸 · 已验证能力”，高级入口可查看 Profile 与映射。

1. 先从已注册方案中筛出项目、模式、媒体引用、模型版本、尺寸和审片能力都匹配的项。注册存在不等于可生产。
2. 仅有一个符合项时可以预选；多个项按明确规则推荐并解释，不改动实际生成模式/检查策略。无符合项时显示缺项及配置入口，不能生成虚构 Profile。
3. 宽高优先读实际生成参数/项目方案；现有“审片预期宽高”只是验证参数，不能说成改画质。生成尺寸与审片预期不一致时阻断并解释。
4. 用户选取镜头可用“选择全部可制作镜头”，同时列出被排除的镜头和原因；按项目镜头顺序展示并提交，不能按勾选顺序误改故事顺序。
5. 开始前展示镜头数量/顺序、风格版本、生成方案、质量策略、修复预算、实际会调用哪些本地/远端服务、缺项和待审内容。
6. 明确点击“开始本机制作”后创建既有 production series；依赖镜头只在源任务通过且当前有效后创建，租约贯穿序列且最终只释放一次。
7. 单镜任务同样走既有托管渲染器。不能通过浏览器/脚本逐镜手动驱动伪称无人值守。
8. 演示模式以持续可见标识和独立操作提供，不得被包装为出片；改造不静默将当前 Mock 切为真实执行，也不把真实模式切回 Mock 掩盖错误。

保留完整五道门禁；基础检查如果项目政策允许，可作为显式可选策略并说明覆盖范围。不能为了按钮可用把缺失审片能力降成通过，或将 `pending_review` 翻译为“制作完成且验收通过”。
