## 4. 本轮修复的八个缺陷

1. **服务商 429 直接判死一场分镜**：POST 的 429 被立即抛出，一次限流让整场失败。
   现在按 `Retry-After`/指数退避重试，并把冷却记在同一端点上，后续调用共享等待。
   预算：agent 通道 2 次（`AGENT_RATE_LIMIT_RETRY_ATTEMPTS`），连通性探测仍是 0 次。
   429 是「拒绝且没有答案」，重试不会买到第二份答案；5xx 与超时的未知结论仍不重放。
2. **剧组链的重试不带任何反馈**：`LLM_RATE_LIMIT` / `LLM_FORMAT` 过去不在可重试集合里；
   合同拒绝（对白非原文、格式不符）重试时模型原样再错一次。现在重试带上具名原因
   （`CONTRACT_REPAIR_NOTES`），只写规则与做法，不携带服务商文本。
3. **宿主代理环境打倒本机客户端**：`NO_PROXY` 里的 `[::1]` 让 httpx 拒绝建客户端
   （`InvalidURL: Invalid port: ':1]'`）。此前只有文字通道规整过，渲染器、本地文本模型、
   实例健康检查全部受影响。规则统一到 `shine/http_env.py`：环回端点一律 `trust_env=False`，
   远端调用先规整 `NO_PROXY`。
4. **素材缺口被当成连续性冲突**：`policy_compliant` 过去由「缺主素材」决定，于是缺素材的
   单元被连续性监督上报为冲突、被仲裁判成 conflict、最终无法落镜。现在策略违规与素材请求
   分开（`policy_compliant` / `material_request`），只报告素材缺口的条目由
   `material_request_issues` 判为素材请求，**不进仲裁也不阻塞单元**。
5. **崩溃遗留的剧组任务永久卡住一场**：持有调用的进程死掉后，任务永远 `RUNNING`，核对入口
   一直 `FILM_AGENT_TASK_STILL_RUNNING`。服务商调用活不过它自己的超时，所以超过该超时仍
   `RUNNING` 的任务属于已死进程，按已完成的尝试核对。
6. **未知结果无法被人工救回**：`external_outcome=UNKNOWN` 的任务过去核对给不出可重发结论，
   这一场既不能自动重放（会买到第二份答案）也不能重做。现在核对返回
   `UNKNOWN_REQUIRES_NEW_ATTEMPT`，面板随即以 `resend-unknown` 记录人的明确授权
   （旧任务退役为 `USER_AUTHORIZED_NEW_REQUEST`，历史里仍写着「结果未知」）。
7. **核对不幂等**：结论一旦写入就不可再被版本挡住；请求开始前的「先前未决任务」拒绝必须
   带上 `state_version`，否则面板永远判定「没有可核对的调用记录」。
8. **镜头描述含中文被拒时纠错说明不可执行**：重试说明只让模型「检查中文名」；现在要求用
   角色标签（the lead performer / the woman in the grey cloak）代替中文专名，
   并明确「名字只出现在 asset ids 与人物字段里」。实测第 1 个单元因此从「两次都拒」变成
   「导演通过」。
